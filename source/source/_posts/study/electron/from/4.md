## 一、打包与分发

### 🟢 小白：为什么需要打包

开发时你用 `npm run start` 启动应用，用户没有 Node.js 环境，也不会这样做。打包就是把你的代码 + Electron 运行时 + 所有依赖打成一个可执行文件，用户双击就能运行。

### 🟡 熟练：Electron Forge（官方推荐）

Electron Forge 是官方推荐的打包工具，整合了打包（package）、生成安装包（make）、发布（publish）三个步骤。

**快速开始**：

```bash
# 新项目
npx create-electron-app@latest my-app
cd my-app
npm run make  # 直接生成安装包

# 已有项目
npm install --save-dev @electron-forge/cli
npx electron-forge import
npm run make
```

**`package.json` 配置**：

```json
{
  "config": {
    "forge": {
      "packagerConfig": {
        "name": "MyApp",
        "icon": "./assets/icon",
        "asar": true
      },
      "makers": [
        {
          "name": "@electron-forge/maker-squirrel",
          "config": { "name": "MyApp" }
        },
        {
          "name": "@electron-forge/maker-zip",
          "platforms": ["darwin"]
        },
        {
          "name": "@electron-forge/maker-deb",
          "config": {}
        }
      ]
    }
  }
}
```

运行 `npm run make` 后，`out/make/` 目录里会有各平台的安装包：
- Windows：`.exe`（Squirrel 安装包）
- macOS：`.zip`
- Linux：`.deb`

### 🟡 熟练：手动打包（不用 Forge）

如果不用 Forge，有两种手动方式：

**方式一：预构建二进制**

```
electron/
├── Electron.app/          # macOS
│   └── Contents/
│       └── Resources/
│           └── app/       # 把你的应用放这里
│               ├── package.json
│               ├── main.js
│               └── index.html
└── resources/             # Windows/Linux
    └── app/
        ├── package.json
        ├── main.js
        └── index.html
```

**方式二：ASAR 归档**

ASAR 是 Electron 的归档格式，类似 tar，可以提升 Windows 上的文件读取性能：

```bash
npm install -g @electron/asar
asar pack app app.asar
```

```
electron/
└── resources/
    └── app.asar  # 替代 app/ 目录
```

### 🔴 专家：重命名与品牌化

打包后需要把 Electron 的名字换成你的应用名：

**macOS**：
```bash
# 重命名 .app 包
mv Electron.app MyApp.app

# 修改 Info.plist
/usr/libexec/PlistBuddy -c "Set :CFBundleDisplayName MyApp" MyApp.app/Contents/Info.plist
/usr/libexec/PlistBuddy -c "Set :CFBundleIdentifier com.mycompany.myapp" MyApp.app/Contents/Info.plist
/usr/libexec/PlistBuddy -c "Set :CFBundleName MyApp" MyApp.app/Contents/Info.plist

# Helper 也要改名
mv "MyApp.app/Contents/Frameworks/Electron Helper.app" \
   "MyApp.app/Contents/Frameworks/MyApp Helper.app"
```

**Windows**：
```bash
# 用 rcedit 修改图标和版本信息
npm install -g rcedit
rcedit electron.exe --set-icon myapp.ico --set-version-string "ProductName" "MyApp"
```

## 二、代码签名（Code Signing）

### 🟢 小白：为什么必须签名

不签名的应用在 macOS 上会被 Gatekeeper 拦截，在 Windows 上会触发 SmartScreen 警告。用户看到"无法验证开发者"的提示，大多数人会直接关掉。

### 🟡 熟练：macOS 签名与公证

macOS 需要两步：**代码签名** + **公证（Notarization）**。

**前提条件**：
- 加入 Apple Developer Program（年费 $99）
- 安装 Xcode
- 生成并下载签名证书

**用 Electron Forge 签名**：

```json
// forge.config.js
module.exports = {
  packagerConfig: {
    osxSign: {
      identity: 'Developer ID Application: Your Name (XXXXXXXXXX)',
      hardenedRuntime: true,
      entitlements: 'entitlements.plist',
      entitlementsInherit: 'entitlements.plist'
    },
    osxNotarize: {
      appleId: process.env.APPLE_ID,
      appleIdPassword: process.env.APPLE_ID_PASSWORD,
      teamId: process.env.APPLE_TEAM_ID
    }
  }
}
```

```xml
<!-- entitlements.plist -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>com.apple.security.cs.allow-jit</key>
  <true/>
  <key>com.apple.security.cs.allow-unsigned-executable-memory</key>
  <true/>
</dict>
</plist>
```

**用 `@electron/packager` 签名**：

```js
const packager = require('@electron/packager')

packager({
  dir: '/path/to/my/app',
  osxSign: {},
  osxNotarize: {
    appleId: 'your@apple.id',
    appleIdPassword: process.env.APPLE_ID_PASSWORD
  }
})
```

### 🟡 熟练：Windows 签名

**推荐：Azure Artifact Signing（最便宜，无 SmartScreen 警告）**

```bash
# 用 jsign（支持 Linux/macOS 跨平台签名 Windows 应用）
jsign \
  --storetype TRUSTEDSIGNING \
  --keystore https://eus.codesigning.azure.net/ \
  --storepass $AZURE_ACCESS_TOKEN \
  --alias trusted-sign-acct/AppName \
  --tsaurl http://timestamp.acs.microsoft.com/ \
  --tsmode RFC3161 \
  --replace MyApp.exe
```

**传统证书（EV 代码签名证书）**：

> ⚠️ 注意：2023 年 6 月起，微软要求使用 EV（扩展验证）证书，普通证书不再有效。EV 证书通常需要硬件令牌（USB Key）。

主要供应商：DigiCert、GlobalSign、Sectigo、SSL.com，价格从几百到几千美元/年不等。

**用 Electron Forge 签名 Windows**：

```json
// forge.config.js
{
  "makers": [{
    "name": "@electron-forge/maker-squirrel",
    "config": {
      "certificateFile": "./cert.pfx",
      "certificatePassword": process.env.CERTIFICATE_PASSWORD
    }
  }]
}
```

### 🔴 专家：CI/CD 中的签名

在 CI 环境中，证书通过环境变量传递：

```yaml
# GitHub Actions 示例
- name: Sign and Notarize macOS App
  env:
    APPLE_ID: ${{ secrets.APPLE_ID }}
    APPLE_ID_PASSWORD: ${{ secrets.APPLE_ID_PASSWORD }}
    APPLE_TEAM_ID: ${{ secrets.APPLE_TEAM_ID }}
    CSC_LINK: ${{ secrets.MAC_CERTS }}          # base64 编码的 .p12 文件
    CSC_KEY_PASSWORD: ${{ secrets.MAC_CERTS_PASSWORD }}
  run: npm run make
```

## 三、自动更新（Auto Updates）

### 🟢 小白：为什么需要自动更新

桌面应用不像网页，用户不会主动去下载新版本。自动更新让你能在后台静默下载更新，在合适的时机提示用户重启。

### 🟡 熟练：三种更新方案

**方案一：update.electronjs.org（最简单，开源项目推荐）**

条件：
- macOS 或 Windows
- 有公开的 GitHub 仓库
- 发布到 GitHub Releases
- macOS 构建已签名

```bash
npm install update-electron-app
```

```js
// main.js（一行代码搞定）
require('update-electron-app')()

// 或者自定义配置
const { updateElectronApp } = require('update-electron-app')
updateElectronApp({
  updateInterval: '1 hour',
  logger: require('electron-log')
})
```

**方案二：静态文件存储（S3/OSS，私有项目推荐）**

```js
// main.js
const { updateElectronApp, UpdateSourceType } = require('update-electron-app')

updateElectronApp({
  updateSource: {
    type: UpdateSourceType.StaticStorage,
    baseUrl: `https://my-bucket.s3.amazonaws.com/my-app-updates/${process.platform}/${process.arch}`
  }
})
```

更新文件目录结构：

```
my-app-updates/
├── darwin/
│   ├── x64/
│   │   ├── my-app-1.0.0-darwin-x64.zip
│   │   ├── my-app-1.1.0-darwin-x64.zip
│   │   └── RELEASES.json
│   └── arm64/
│       └── ...
└── win32/
    └── x64/
        ├── my-app-1.0.0-win32-x64.exe
        ├── my-app-1.0.0-win32-x64.nupkg
        ├── my-app-1.1.0-win32-x64.exe
        ├── my-app-1.1.0-win32-x64.nupkg
        └── RELEASES
```

macOS 的 `RELEASES.json` 格式：

```json
{
  "currentRelease": "1.1.0",
  "releases": [
    {
      "version": "1.1.0",
      "updateTo": {
        "version": "1.1.0",
        "pub_date": "2024-01-01T00:00:00+00:00",
        "notes": "修复了若干 bug",
        "name": "1.1.0",
        "url": "https://my-bucket.s3.amazonaws.com/my-app-updates/darwin/x64/my-app-1.1.0-darwin-x64.zip"
      }
    }
  ]
}
```

**方案三：自建更新服务器**

```js
// main.js：使用 autoUpdater 模块
const { autoUpdater } = require('electron')

autoUpdater.setFeedURL({
  url: `https://update.myapp.com/update/${process.platform}/${app.getVersion()}`
})

// 检查更新
autoUpdater.checkForUpdates()

// 监听更新事件
autoUpdater.on('update-available', () => {
  console.log('发现新版本，开始下载...')
})

autoUpdater.on('update-downloaded', (event, releaseNotes, releaseName) => {
  const dialogOpts = {
    type: 'info',
    buttons: ['重启', '稍后'],
    title: '应用更新',
    message: process.platform === 'win32' ? releaseNotes : releaseName,
    detail: '新版本已下载完成，重启应用以完成更新。'
  }

  dialog.showMessageBox(dialogOpts).then((returnValue) => {
    if (returnValue.response === 0) autoUpdater.quitAndInstall()
  })
})

autoUpdater.on('error', (message) => {
  console.error('自动更新出错：', message)
})
```

### 🔴 专家：更新策略与最佳实践

**增量更新（Delta Updates）**

Squirrel.Windows 支持增量更新，只下载变化的部分：

```
RELEASES 文件示例：
B0892F3C7AC91D72A6271FF36905FEF8FE993520 myapp-1.0.0-full.nupkg 103298365
A1234567890ABCDEF1234567890ABCDEF12345678 myapp-1.1.0-delta.nupkg 2048576
```

**更新时机策略**：

```js
// 不要在应用启动时立即检查（影响启动速度）
app.whenReady().then(() => {
  // 延迟 10 秒后检查
  setTimeout(() => {
    autoUpdater.checkForUpdates()
  }, 10000)

  // 之后每小时检查一次
  setInterval(() => {
    autoUpdater.checkForUpdates()
  }, 60 * 60 * 1000)
})
```

**版本回滚**：

```js
// 保留上一个版本，支持回滚
const previousVersion = app.getVersion()
// 在更新前保存当前版本信息到本地存储
// 如果新版本有严重问题，可以提供回滚选项
```

## 📝 小结

**打包流程**：
```
源代码 → Electron Forge make → 各平台安装包
                              ├── Windows: .exe (Squirrel)
                              ├── macOS: .zip / .dmg
                              └── Linux: .deb / .rpm / .AppImage
```

**签名要点**：
- macOS：需要 Apple Developer 证书 + 公证，两步缺一不可
- Windows：2023 年后必须用 EV 证书，推荐 Azure Artifact Signing
- CI/CD：证书通过环境变量传递，不要提交到代码仓库

**更新方案选择**：
| 场景 | 推荐方案 |
|------|---------|
| 开源项目，发布到 GitHub | `update-electron-app` + `update.electronjs.org` |
| 私有项目，有云存储 | `update-electron-app` + 静态文件存储 |
| 需要完全控制 | 自建更新服务器 + `autoUpdater` |
