## 一、多线程（Multithreading）

### 🟢 小白：为什么需要多线程

JavaScript 是单线程的。如果你在渲染进程里做大量计算（比如解析大文件、图像处理），整个 UI 会卡住，用户体验很差。

Web Workers 让你在独立的 OS 线程里运行 JavaScript，不阻塞 UI。

### 🟡 熟练：在 Electron 里使用 Web Workers

Electron 支持在 Web Workers 里使用 Node.js 特性，但需要开启 `nodeIntegrationInWorker`：

```js
// main.js
const win = new BrowserWindow({
  webPreferences: {
    nodeIntegrationInWorker: true  // 开启 Worker 里的 Node.js 支持
    // 注意：sandbox 不能为 true
  }
})
```

```js
// renderer.js（渲染进程）
const worker = new Worker('./worker.js')
worker.postMessage({ task: 'process', data: largeArray })
worker.onmessage = (e) => {
  console.log('Worker 完成：', e.data.result)
}
```

```js
// worker.js（Worker 线程）
const fs = require('node:fs')  // 可以用 Node.js 内置模块！

self.onmessage = async (e) => {
  const { task, data } = e.data

  if (task === 'process') {
    // CPU 密集型操作，不会阻塞 UI
    const result = data.map(item => heavyTransform(item))
    self.postMessage({ result })
  }
}
```

### 🔴 专家：原生模块在 Worker 里的限制

Worker 里可以用所有 Node.js 内置模块和 asar 归档，但**不能用 Electron 内置模块**（`BrowserWindow`、`ipcRenderer` 等）。

原生 Node.js 模块（`.node` 文件）在 Worker 里使用有严重风险：

```js
// ❌ 危险：大多数原生模块假设单线程环境
// 在 Worker 里加载可能导致崩溃或内存损坏
const nativeModule = require('some-native-module')

// ✅ 安全做法：在 Worker 启动前禁止加载原生模块
process.dlopen = () => {
  throw new Error('禁止在 Worker 启动后加载原生模块')
}
const worker = new Worker('script.js')
```

即使原生模块声称是线程安全的，`process.dlopen` 本身也不是线程安全的，所以加载操作本身就有风险。

## 二、离屏渲染（Offscreen Rendering）

### 🟢 小白：什么是离屏渲染

普通的 `BrowserWindow` 会在屏幕上显示一个窗口。离屏渲染让你把网页内容渲染到**内存里的位图**，而不是显示在屏幕上。

**典型用途**：
- 在 3D 场景里把网页内容作为纹理（游戏 UI、VR 应用）
- 截图工具
- 服务端渲染网页内容

### 🟡 熟练：两种渲染模式

**模式一：软件渲染（CPU）**

禁用 GPU 加速，用 CPU 渲染，速度更快，但不支持 WebGL 和 3D CSS：

```js
// main.js
app.disableHardwareAcceleration()  // 必须在 app ready 之前调用

function createWindow() {
  const win = new BrowserWindow({
    width: 800,
    height: 600,
    webPreferences: {
      offscreen: true  // 开启离屏渲染
    }
  })

  win.loadURL('https://github.com')

  // 监听每一帧的渲染结果
  win.webContents.on('paint', (event, dirty, image) => {
    // image 是 NativeImage 对象
    // dirty 是本次更新的脏区域（只有变化的部分）
    fs.writeFileSync('screenshot.png', image.toPNG())
  })

  win.webContents.setFrameRate(60)  // 设置帧率
}
```

**模式二：GPU 加速渲染**

支持 WebGL 和 3D CSS，有两种子模式：

```js
// 子模式 A：共享 GPU 纹理（最快，需要原生模块）
const win = new BrowserWindow({
  webPreferences: {
    offscreen: {
      useSharedTexture: true  // 直接在 GPU 内存操作，无 CPU-GPU 拷贝
    }
  }
})

// 子模式 B：CPU 共享内存位图（默认，支持 GPU 功能但有性能开销）
const win = new BrowserWindow({
  webPreferences: {
    offscreen: true  // 等同于 offscreen: { useSharedTexture: false }
  }
})
```

### 🔴 专家：性能对比与选择

| 模式 | GPU 支持 | 帧率上限 | CPU 开销 | 适用场景 |
|------|---------|---------|---------|---------|
| 软件渲染 | ❌ | 无限制 | 低 | 简单页面截图 |
| GPU 共享纹理 | ✅ | 无限制 | 极低 | 3D 引擎集成 |
| GPU 共享内存位图 | ✅ | 240fps | 中 | 需要 GPU 但不用纹理 |

> 注意：`useSharedTexture: false` 时最大帧率为 240fps，超过没有收益。

## 三、原生文件拖拽（Native File Drag & Drop）

### 🟢 小白：两种拖拽方向

- **拖入**：用户从系统拖文件到你的应用窗口（Web 标准 API，直接支持）
- **拖出**：用户从你的应用拖文件到系统（需要 Electron 特殊 API）

### 🟡 熟练：实现拖出功能

```js
// preload.js
const { contextBridge, ipcRenderer } = require('electron')

contextBridge.exposeInMainWorld('electron', {
  startDrag: (fileName) => ipcRenderer.send('ondragstart', fileName)
})
```

```html
<!-- index.html -->
<div
  style="border: 2px solid black; padding: 10px; display: inline-block"
  draggable="true"
  id="drag"
>
  拖我出去
</div>
<script src="renderer.js"></script>
```

```js
// renderer.js
document.getElementById('drag').ondragstart = (event) => {
  event.preventDefault()  // 阻止默认行为
  window.electron.startDrag('my-file.txt')
}
```

```js
// main.js
const { ipcMain, app } = require('electron')
const path = require('node:path')
const fs = require('node:fs')

ipcMain.on('ondragstart', (event, fileName) => {
  // 准备要拖出的文件
  const filePath = path.join(app.getPath('temp'), fileName)
  fs.writeFileSync(filePath, '文件内容')

  // 启动拖拽，需要提供文件路径和图标
  event.sender.startDrag({
    file: filePath,
    icon: path.join(__dirname, 'drag-icon.png')  // 拖拽时显示的图标
  })
})
```

## 四、在线/离线状态检测（Online/Offline Events）

### 🟢 小白：两种检测方式

**渲染进程**（Web 标准 API）：

```js
// renderer.js
const updateStatus = () => {
  document.getElementById('status').textContent =
    navigator.onLine ? '在线' : '离线'
}

window.addEventListener('online', updateStatus)
window.addEventListener('offline', updateStatus)
updateStatus()
```

**主进程**（Electron `net` 模块）：

```js
// main.js
const { net } = require('electron')

// 注意：只能在 app ready 之后使用
app.whenReady().then(() => {
  console.log('当前状态：', net.isOnline() ? '在线' : '离线')
  console.log('当前状态：', net.online ? '在线' : '离线')  // 同等效果
})
```

### 🔴 专家：`navigator.onLine` 的局限性

`navigator.onLine` 和 `net.isOnline()` 有一个重要限制：

- 返回 `false`：**可以确定**网络不可用
- 返回 `true`：**不能确定**能访问互联网（可能在局域网、VPN、虚拟网卡等环境）

如果需要真正检测互联网连通性，需要额外手段：

```js
// 通过实际请求检测互联网连通性
async function checkInternetConnectivity() {
  try {
    const response = await fetch('https://www.google.com/favicon.ico', {
      method: 'HEAD',
      cache: 'no-cache',
      signal: AbortSignal.timeout(5000)  // 5 秒超时
    })
    return response.ok
  } catch {
    return false
  }
}

// 定期检测
setInterval(async () => {
  const isConnected = await checkInternetConnectivity()
  updateConnectionStatus(isConnected)
}, 30000)
```

## 五、原生 Node 模块（Native Node Modules）

### 🟢 小白：什么是原生模块，为什么要重新编译

原生 Node.js 模块（`.node` 文件）是用 C/C++ 写的，编译时绑定到特定的 Node.js ABI 版本。

Electron 内置的 Node.js 版本和系统安装的 Node.js 版本不同，而且 Electron 用的是 Chromium 的 BoringSSL 而不是 OpenSSL。所以直接用 `npm install` 的原生模块在 Electron 里会报错：

```
Error: The module '/path/to/native/module.node'
was compiled against a different Node.js version
using NODE_MODULE_VERSION $XYZ.
```

### 🟡 熟练：三种安装方式

**方式一：用 `@electron/rebuild`（推荐）**

```bash
npm install --save-dev @electron/rebuild

# 每次 npm install 后运行
./node_modules/.bin/electron-rebuild

# Windows
.\node_modules\.bin\electron-rebuild.cmd
```

如果用 Electron Forge，它会自动处理重新编译。

**方式二：用 npm 环境变量**

```bash
# 设置 Electron 版本和架构
export npm_config_target=28.0.0        # Electron 版本
export npm_config_arch=x64
export npm_config_target_arch=x64
export npm_config_disturl=https://electronjs.org/headers
export npm_config_runtime=electron
export npm_config_build_from_source=true

# 安装依赖（会自动为 Electron 编译原生模块）
HOME=~/.electron-gyp npm install
```

**方式三：手动用 node-gyp**

```bash
cd /path/to/native/module
HOME=~/.electron-gyp node-gyp rebuild \
  --target=28.0.0 \          # Electron 版本
  --arch=x64 \
  --dist-url=https://electronjs.org/headers
```

### 🔴 专家：Windows 上的 win_delay_load_hook

Electron 4+ 在 Windows 上，原生模块需要的符号从 `node.dll` 变成了 `electron.exe`。`node-gyp` 会自动安装一个延迟加载钩子来处理这个问题。

如果遇到 `Module did not self-register` 或 `The specified procedure could not be found` 错误，检查模块的 `binding.gyp`：

```json
{
  "targets": [{
    "target_name": "your_module",
    "win_delay_load_hook": "true"  // 必须为 "true"，不能是 false
  }]
}
```

**排查步骤**：
1. 先运行 `@electron/rebuild`
2. 确认模块支持目标平台和架构
3. 确认 `win_delay_load_hook` 不是 `false`
4. 升级 Electron 后必须重新编译

## 六、原生代码集成（Native Code and Electron）

### 🟢 小白：什么时候需要原生代码

当 JavaScript 无法满足需求时：
- 调用系统 API（Windows COM、macOS Cocoa、Linux GTK）
- 性能关键路径（图像处理、加密、音视频编解码）
- 复用现有的 C/C++/Swift/Rust 代码库

### 🟡 熟练：三种集成方式

**方式一：Node.js 原生插件（N-API）**

最通用的方式，跨平台，ABI 稳定：

```cpp
// addon.cc
#include <node_api.h>

napi_value Add(napi_env env, napi_callback_info info) {
  // 获取参数
  size_t argc = 2;
  napi_value args[2];
  napi_get_cb_info(env, info, &argc, args, nullptr, nullptr);

  // 执行计算
  double value1, value2;
  napi_get_value_double(env, args[0], &value1);
  napi_get_value_double(env, args[1], &value2);

  // 返回结果
  napi_value result;
  napi_create_double(env, value1 + value2, &result);
  return result;
}

NAPI_MODULE_INIT() {
  napi_value fn;
  napi_create_function(env, nullptr, 0, Add, nullptr, &fn);
  napi_set_named_property(env, exports, "add", fn);
  return exports;
}
```

```js
// 在 Electron 里使用
const addon = require('./build/Release/addon.node')
console.log(addon.add(1, 2))  // 3
```

**方式二：子进程（适合独立的原生程序）**

```js
const { spawn } = require('node:child_process')

const child = spawn('./native-binary', ['--arg1', 'value'])
child.stdout.on('data', (data) => {
  console.log('原生程序输出：', data.toString())
})
```

**方式三：WebAssembly（跨平台，无需编译）**

```js
// 加载 WASM 模块
const wasmBuffer = fs.readFileSync('./module.wasm')
const wasmModule = await WebAssembly.instantiate(wasmBuffer)
const result = wasmModule.instance.exports.add(1, 2)
```

## 📝 小结

| 特性 | 适用场景 | 关键 API |
|------|---------|---------|
| Web Workers | CPU 密集型任务，不阻塞 UI | `new Worker()`, `nodeIntegrationInWorker` |
| 离屏渲染 | 截图、3D 纹理、服务端渲染 | `offscreen: true`, `webContents.on('paint')` |
| 原生拖拽（拖出） | 文件管理类应用 | `webContents.startDrag()` |
| 在线检测 | 网络状态感知 | `navigator.onLine`, `net.isOnline()` |
| 原生模块 | 调用 C/C++ 库 | `@electron/rebuild`, `node-gyp` |
| 原生代码 | 系统 API、性能关键路径 | N-API, 子进程, WASM |

**专家要注意的坑**：
- Worker 里不要加载原生模块（线程安全问题）
- `navigator.onLine` 返回 `true` 不代表能访问互联网
- Windows 上原生模块需要 `win_delay_load_hook: true`
- 升级 Electron 版本后必须重新编译原生模块
