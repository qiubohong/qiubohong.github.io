## 一、调试渲染进程

### 🟢 小白：用 DevTools 调试渲染进程

渲染进程就是普通的 Chromium 网页，直接用 DevTools 调试：

```js
// main.js：开发模式下自动打开 DevTools
if (process.env.NODE_ENV === 'development') {
  mainWindow.webContents.openDevTools()
}

// 或者通过快捷键手动打开
// Windows/Linux: Ctrl+Shift+I
// macOS: Cmd+Option+I
```

渲染进程的 Console、Sources、Network、Performance 面板和浏览器里完全一样，这里不再赘述。

## 二、调试主进程

### 🟢 小白：主进程为什么难调试

主进程跑在 Node.js 环境里，没有 UI，不能直接用 DevTools。需要用外部调试器通过 V8 Inspector 协议连接。

### 🟡 熟练：命令行启动调试

```bash
# 方式一：--inspect（不暂停，直接运行）
electron --inspect=9229 .

# 方式二：--inspect-brk（在第一行暂停，等待调试器连接）
electron --inspect-brk=9229 .
```

启动后，打开 Chrome 浏览器访问 `chrome://inspect`，点击 "inspect" 连接到你的 Electron 主进程。

### 🟡 熟练：VSCode 调试配置

VSCode 是调试 Electron 主进程最方便的方式。

**第一步**：在项目根目录创建 `.vscode/launch.json`：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug Main Process",
      "type": "node",
      "request": "launch",
      "cwd": "${workspaceFolder}",
      "runtimeExecutable": "${workspaceFolder}/node_modules/.bin/electron",
      "windows": {
        "runtimeExecutable": "${workspaceFolder}/node_modules/.bin/electron.cmd"
      },
      "args": ["."],
      "outputCapture": "std"
    }
  ]
}
```

**第二步**：在 `main.js` 里设置断点，按 F5 启动调试。

就这两步，可以在 VSCode 里直接断点调试主进程代码，查看变量、调用栈，和调试普通 Node.js 程序一样。

### 🔴 专家：调试 Electron 原生代码（C++）

如果你需要调试 Electron 的 C++ 源码（比如开发原生模块或贡献 Electron 本身）：

**Windows（C++）**：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "(Windows) Launch",
      "type": "cppvsdbg",
      "request": "launch",
      "program": "${workspaceFolder}\\out\\Testing\\electron.exe",
      "args": ["your-electron-project-path"],
      "stopAtEntry": false,
      "cwd": "${workspaceFolder}",
      "environment": [
        { "name": "ELECTRON_ENABLE_LOGGING", "value": "true" },
        { "name": "ELECTRON_ENABLE_STACK_DUMPING", "value": "true" },
        { "name": "ELECTRON_RUN_AS_NODE", "value": "" }
      ],
      "externalConsole": false,
      "sourceFileMap": {
        "o:\\": "${workspaceFolder}"
      }
    }
  ]
}
```

需要先从源码编译 Electron，参考 [Electron Build Tools](https://github.com/electron/build-tools)。

## 三、REPL 交互式调试

### 🟢 小白：什么是 REPL

REPL（Read-Eval-Print Loop）是一个交互式命令行，可以实时执行代码，非常适合快速验证 API 行为。

### 🟡 熟练：在 Electron 里使用 REPL

Electron 的主进程是 Node.js 环境，可以直接用 Node.js 的 REPL：

```bash
# 以 REPL 模式启动 Electron
ELECTRON_RUN_AS_NODE=1 electron
```

```js
// 在 REPL 里可以直接测试 Electron API
> const { app } = require('electron')
> app.getVersion()
'28.0.0'
> app.getPath('userData')
'/Users/username/Library/Application Support/Electron'
```

也可以在运行中的应用里打开 REPL：

```js
// main.js
const repl = require('node:repl')

// 在主进程里启动 REPL（通过 stdin/stdout）
const replServer = repl.start({
  prompt: 'electron> ',
  input: process.stdin,
  output: process.stdout
})

// 把常用对象注入 REPL 上下文
replServer.context.app = require('electron').app
replServer.context.BrowserWindow = require('electron').BrowserWindow
replServer.context.mainWindow = mainWindow
```

## 四、DevTools 扩展

### 🟢 小白：为什么需要 DevTools 扩展

React DevTools、Vue DevTools 这些浏览器扩展，在 Electron 里也能用，帮助调试前端框架。

### 🟡 熟练：安装 DevTools 扩展

**方式一：从 Chrome 扩展商店安装（推荐）**

```bash
npm install --save-dev electron-devtools-installer
```

```js
// main.js
const { app, BrowserWindow } = require('electron')

app.whenReady().then(async () => {
  // 只在开发模式安装
  if (process.env.NODE_ENV === 'development') {
    const { default: installExtension, REACT_DEVELOPER_TOOLS, VUEJS_DEVTOOLS } =
      await import('electron-devtools-installer')

    await installExtension([REACT_DEVELOPER_TOOLS, VUEJS_DEVTOOLS])
  }

  createWindow()
})
```

**方式二：从本地路径加载**

```js
const { session } = require('electron')
const path = require('node:path')

app.whenReady().then(() => {
  // 从 Chrome 扩展目录加载
  const extensionPath = path.join(
    process.env.HOME,
    '.config/google-chrome/Default/Extensions/fmkadmapgofadopljbjfkapdkoienihi/4.28.0_0'
  )
  session.defaultSession.loadExtension(extensionPath)
})
```

### 🔴 专家：自定义 DevTools 面板

```js
// 在 DevTools 里添加自定义面板
mainWindow.webContents.on('devtools-opened', () => {
  mainWindow.webContents.executeJavaScript(`
    // 在 DevTools Console 里执行代码
    console.log('DevTools 已打开')
  `)
})
```

## 五、自动化测试

### 🟢 小白：为什么要自动化测试

手动测试每次发版都要重复点击，费时费力还容易漏测。自动化测试让你每次提交代码都能自动验证功能是否正常。

### 🟡 熟练：WebdriverIO（推荐）

WebdriverIO 是目前最推荐的 Electron 自动化测试框架。

**安装配置**：

```bash
# 初始化 WebdriverIO（会有配置向导）
npm init wdio@latest ./

# 在向导中选择：
# "What type of testing would you like to do?" → Desktop Testing - of Electron Applications
```

配置文件 `wdio.conf.js`：

```js
export const config = {
  services: ['electron'],
  capabilities: [{
    browserName: 'electron',
    'wdio:electronServiceOptions': {
      // 如果用 Electron Forge 或 electron-builder，会自动找到应用
      // 否则手动指定：
      // appBinaryPath: './path/to/bundled/application.exe',
      appArgs: ['--no-sandbox']
    }
  }]
}
```

**编写测试**：

```js
// test/app.test.js
import { browser, $, expect } from '@wdio/globals'

describe('应用基本功能', () => {
  it('应该显示正确的标题', async () => {
    const title = await browser.getTitle()
    expect(title).toBe('My Electron App')
  })

  it('应该响应键盘输入', async () => {
    await browser.keys(['y', 'o'])
    await expect($('keypress-count')).toHaveText('YO')
  })

  it('可以通过测试调用 Electron API', async () => {
    // 在测试里直接调用 Electron API
    const appName = await browser.electron.execute(
      (electron) => electron.app.getName()
    )
    expect(appName).toBe('my-electron-app')
  })

  it('可以模拟菜单点击', async () => {
    await browser.electron.execute((electron) => {
      const menu = electron.Menu.getApplicationMenu()
      const fileMenu = menu.items.find(item => item.label === '文件')
      fileMenu.submenu.items.find(item => item.label === '新建').click()
    })
    // 验证新建操作的结果
  })
})
```

**运行测试**：

```bash
npx wdio run wdio.conf.js
```

### 🟡 熟练：Selenium（传统方案）

```bash
npm install --save-dev electron-chromedriver selenium-webdriver
```

```js
// test/selenium.test.js
const { Builder, By, until } = require('selenium-webdriver')
const chromedriver = require('electron-chromedriver')

// 启动 ChromeDriver
chromedriver.start(['--url-base=wd/hub'])

const driver = new Builder()
  .usingServer('http://localhost:9515/wd/hub')
  .withCapabilities({
    'goog:chromeOptions': {
      binary: require('electron'),
      args: [require('path').join(__dirname, '..')]
    }
  })
  .forBrowser('chrome')
  .build()

// 测试
driver.getTitle().then(title => {
  console.log('标题：', title)
})

// 清理
driver.quit()
chromedriver.stop()
```

### 🔴 专家：Mock Electron API

在测试中 Mock Electron API，避免真实的系统调用：

```js
// WebdriverIO 的 Mock 功能
describe('文件对话框', () => {
  it('应该处理文件选择', async () => {
    // Mock dialog.showOpenDialog 返回固定值
    await browser.electron.mock('dialog', 'showOpenDialog', {
      canceled: false,
      filePaths: ['/path/to/test/file.txt']
    })

    // 点击"打开文件"按钮
    await $('button#open-file').click()

    // 验证文件路径显示正确
    await expect($('#file-path')).toHaveText('/path/to/test/file.txt')

    // 清除 Mock
    await browser.electron.clearAllMocks()
  })
})
```

## 六、Headless CI 测试

### 🟢 小白：CI 上为什么需要特殊配置

Electron 基于 Chromium，需要显示驱动才能运行。CI 服务器（Travis CI、Jenkins、GitHub Actions）通常没有显示器，直接运行会报错：

```
[ERROR:browser_main_loop.cc] Unable to open X display.
```

### 🟡 熟练：用 Xvfb 虚拟显示

Xvfb（X Virtual Framebuffer）是一个虚拟显示服务器，在内存里模拟显示器。

**Linux CI 配置**：

```bash
# 安装 Xvfb
sudo apt-get install -y xvfb

# 启动虚拟显示
Xvfb :99 -screen 0 1024x768x24 &
export DISPLAY=:99

# 运行测试
npm test
```

**用 xvfb-maybe 自动处理**：

```bash
npm install --save-dev xvfb-maybe
```

```json
// package.json
{
  "scripts": {
    "test": "xvfb-maybe electron-mocha ./test/*.js"
  }
}
```

`xvfb-maybe` 会自动检测：在 Linux headless 环境里用 `xvfb-run` 包装，在 Windows/macOS 上直接运行。

### 🟡 熟练：各 CI 平台配置

**GitHub Actions**：

```yaml
# .github/workflows/test.yml
name: Test

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
      - run: npm ci

      # 安装 Xvfb 依赖
      - name: Install Linux dependencies
        run: |
          sudo apt-get update
          sudo apt-get install -y xvfb libgtk-3-0 libnotify-dev libgconf-2-4 libnss3 libxss1 libasound2

      # 用 Xvfb 运行测试
      - name: Run tests
        run: xvfb-run --auto-servernum npm test
```

**Travis CI**：

```yaml
# .travis.yml
language: node_js
node_js:
  - '18'

addons:
  apt:
    packages:
      - xvfb

before_script:
  - export DISPLAY=':99.0'
  - Xvfb :99 -screen 0 1024x768x24 > /dev/null 2>&1 &

script:
  - npm test
```

**CircleCI**：

CircleCI 已经预装了 Xvfb 和 `$DISPLAY` 环境变量，无需额外配置。

**AppVeyor（Windows CI）**：

AppVeyor 运行在 Windows 上，原生支持 Selenium 和 Chromium，无需额外配置。

### 🔴 专家：Docker 中运行 Electron 测试

```dockerfile
# Dockerfile
FROM node:18-bullseye

# 安装 Electron 依赖
RUN apt-get update && apt-get install -y \
  xvfb \
  libgtk-3-0 \
  libnotify-dev \
  libgconf-2-4 \
  libnss3 \
  libxss1 \
  libasound2 \
  libxtst6 \
  xauth \
  && rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY package*.json ./
RUN npm ci

COPY . .

# 用 Xvfb 运行测试
CMD ["xvfb-run", "--auto-servernum", "npm", "test"]
```

```bash
docker build -t electron-test .
docker run --rm electron-test
```

## 📊 调试工具对比

| 工具 | 适用场景 | 难度 |
|------|---------|------|
| Chrome DevTools | 渲染进程调试 | 🟢 简单 |
| VSCode + launch.json | 主进程断点调试 | 🟡 中等 |
| `--inspect` + chrome://inspect | 主进程调试（不用 VSCode） | 🟡 中等 |
| REPL | 快速验证 API | 🟢 简单 |
| DevTools 扩展 | React/Vue 组件调试 | 🟢 简单 |

## 📊 测试方案对比

| 方案 | 优点 | 缺点 | 推荐场景 |
|------|------|------|---------|
| WebdriverIO | 官方推荐，功能完整，支持 Mock | 配置稍复杂 | 新项目首选 |
| Selenium | 生态成熟，文档丰富 | 需要手动管理 ChromeDriver | 已有 Selenium 基础 |
| Playwright | 现代 API，速度快 | Electron 支持不如 WebdriverIO | 实验性使用 |

## 📝 小结

**调试流程**：
1. 渲染进程问题 → Chrome DevTools（F12）
2. 主进程问题 → VSCode + `.vscode/launch.json`
3. 快速验证 API → REPL
4. 前端框架调试 → DevTools 扩展（React/Vue DevTools）

**测试流程**：
1. 本地开发 → WebdriverIO 端到端测试
2. CI 环境 → Xvfb 虚拟显示 + `xvfb-maybe`
3. Mock 系统 API → `browser.electron.mock()`

**CI 配置要点**：
- Linux CI 必须安装 Xvfb 和 Chromium 依赖
- 用 `xvfb-maybe` 可以让同一个测试命令在所有平台运行
- CircleCI 和 AppVeyor 开箱即用，无需额外配置
