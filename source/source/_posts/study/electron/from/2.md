Electron 给了你比浏览器大得多的权限——JavaScript 可以访问文件系统、用户 shell、原生 API。权力越大，责任越大。这篇文章把安全和性能两个话题放在一起，因为它们的底层逻辑是一样的：**最小权限原则**。

# 第一部分：安全

## 🟢 小白入门：Electron 安全和网页安全有什么不同

### 1.1 Electron 不是浏览器

做 Web 开发时，浏览器的沙盒帮你挡了大部分风险。但 Electron 不一样：

- 网页里的 JavaScript 只能操作 DOM
- Electron 里的 JavaScript 可以读写文件、执行系统命令、访问摄像头麦克风

这意味着一个 XSS 漏洞在网页里只是"改了个页面"，在 Electron 里可能变成"在用户电脑上执行任意代码"（RCE，远程代码执行）。

### 1.2 安全是整个链条的责任

你的 Electron 应用安全性取决于：
- Chromium 的安全性
- Node.js 的安全性
- Electron 本身的安全性
- 你用的所有 npm 依赖
- **你自己写的代码**

每一环都可能是漏洞入口。

### 1.3 最重要的三条原则

1. **只加载 HTTPS 内容**：不要用 HTTP 加载任何外部资源
2. **不为远程内容开启 Node.js 集成**：`nodeIntegration: true` 是最危险的配置
3. **保持 Electron 版本最新**：安全补丁随版本发布

## 🟡 熟练进阶：20 条安全建议详解

### 2.1 只加载安全内容（HTTPS）

```js
// ❌ 危险
browserWindow.loadURL('http://example.com')

// ✅ 安全
browserWindow.loadURL('https://example.com')
```

```html
<!-- ❌ 危险 -->
<script crossorigin src="http://cdn.example.com/react.js"></script>

<!-- ✅ 安全 -->
<script crossorigin src="https://cdn.example.com/react.js"></script>
```

HTTPS 的两个核心价值：数据完整性（防篡改）+ 流量加密（防窃听）。

### 2.2 不为远程内容开启 Node.js 集成

> Electron 5.0+ 默认关闭，但要明确知道为什么。

```js
// ❌ 极度危险：加载远程内容时开启 Node.js 集成
const win = new BrowserWindow({
  webPreferences: {
    nodeIntegration: true,        // 开启 Node.js
    contextIsolation: false,      // 关闭隔离
    nodeIntegrationInWorker: true // Worker 也开启
  }
})
win.loadURL('https://example.com')

// ✅ 安全：用预加载脚本暴露受控 API
const win = new BrowserWindow({
  webPreferences: {
    preload: path.join(app.getAppPath(), 'preload.js')
    // nodeIntegration 默认 false，contextIsolation 默认 true
  }
})
win.loadURL('https://example.com')
```

**为什么危险**：如果攻击者通过 XSS 在你的页面执行了代码，开启 `nodeIntegration` 意味着他可以直接调用 `require('child_process').exec('rm -rf /')` 这样的命令。

### 2.3 开启 Context Isolation（Electron 12+ 默认）

Context Isolation 防止网页脚本污染预加载脚本的执行环境。

```js
// ✅ 默认配置（Electron 12+）
const win = new BrowserWindow({
  webPreferences: {
    contextIsolation: true  // 默认值，无需显式设置
  }
})
```

### 2.4 开启进程沙盒化（Electron 20+ 默认）

```js
// 全局强制沙盒（推荐）
app.enableSandbox()

// 或者单个窗口
const win = new BrowserWindow({
  webPreferences: {
    sandbox: true
  }
})
```

### 2.5 使用权限请求处理器

```js
const { session } = require('electron')

session.defaultSession.setPermissionRequestHandler(
  (webContents, permission, callback) => {
    const url = webContents.getURL()

    // 只允许特定来源的特定权限
    const allowedOrigins = ['https://trusted-app.com']
    const allowedPermissions = ['notifications', 'media']

    if (
      allowedOrigins.some(origin => url.startsWith(origin)) &&
      allowedPermissions.includes(permission)
    ) {
      callback(true)
    } else {
      callback(false)
    }
  }
)
```

### 2.6 定义内容安全策略（CSP）

CSP 是防御 XSS 的最后一道防线：

```js
// main.js：通过响应头设置 CSP
session.defaultSession.webRequest.onHeadersReceived((details, callback) => {
  callback({
    responseHeaders: {
      ...details.responseHeaders,
      'Content-Security-Policy': [
        "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'"
      ]
    }
  })
})
```

```html
<!-- index.html：通过 meta 标签设置 CSP -->
<meta
  http-equiv="Content-Security-Policy"
  content="default-src 'self'; script-src 'self'"
/>
```

### 2.7 限制导航

```js
app.on('web-contents-created', (event, contents) => {
  contents.on('will-navigate', (event, navigationUrl) => {
    const parsedUrl = new URL(navigationUrl)
    const allowedOrigins = new Set(['https://trusted-app.com'])

    if (!allowedOrigins.has(parsedUrl.origin)) {
      console.warn(`阻止导航到不受信任的来源：${navigationUrl}`)
      event.preventDefault()
    }
  })
})
```

### 2.8 限制新窗口创建

```js
app.on('web-contents-created', (event, contents) => {
  contents.setWindowOpenHandler(({ url }) => {
    // 只允许在外部浏览器打开 https 链接
    if (url.startsWith('https://')) {
      shell.openExternal(url)
    }
    return { action: 'deny' }  // 阻止在 Electron 内创建新窗口
  })
})
```

### 2.9 验证 IPC 消息发送者

```js
// main.js
ipcMain.handle('get-sensitive-data', async (event) => {
  // 验证发送者来源
  const senderUrl = event.senderFrame.url
  if (!senderUrl.startsWith('https://trusted-app.com')) {
    throw new Error('不受信任的发送者')
  }

  // 验证发送者是否是预期的窗口
  const win = BrowserWindow.fromWebContents(event.sender)
  if (win !== mainWindow) {
    throw new Error('非预期的发送窗口')
  }

  return sensitiveData
})
```

### 2.10 不要用 shell.openExternal 处理不受信任的内容

```js
// ❌ 危险：直接打开用户输入的 URL
shell.openExternal(userInputUrl)

// ✅ 安全：验证 URL 格式和协议
function safeOpenExternal(url) {
  try {
    const parsed = new URL(url)
    if (['https:', 'http:'].includes(parsed.protocol)) {
      shell.openExternal(url)
    }
  } catch {
    console.error('无效的 URL')
  }
}
```

## 🔴 专家深入：安全配置矩阵与 Fuses

### 3.1 安全配置矩阵

| 配置项 | 默认值（版本） | 推荐值 | 影响 |
|--------|--------------|--------|------|
| `nodeIntegration` | `false`（v5+） | `false` | 渲染进程 Node.js 访问 |
| `contextIsolation` | `true`（v12+） | `true` | 预加载脚本隔离 |
| `sandbox` | `true`（v20+） | `true` | 进程沙盒化 |
| `webSecurity` | `true` | `true` | 同源策略 |
| `allowRunningInsecureContent` | `false` | `false` | HTTPS 页面加载 HTTP |
| `experimentalFeatures` | `false` | `false` | 实验性 Chromium 特性 |

### 3.2 Electron Fuses（熔断器）

Fuses 是 Electron 提供的二进制级别的安全开关，在打包时配置，运行时无法更改：

```js
// 使用 @electron/fuses 配置
const { FuseV1Options, FuseVersion } = require('@electron/fuses')

// 在打包脚本中
await flipFuses(pathToElectronBinary, {
  version: FuseVersion.V1,
  [FuseV1Options.RunAsNode]: false,           // 禁止 ELECTRON_RUN_AS_NODE
  [FuseV1Options.EnableCookieEncryption]: true, // 开启 Cookie 加密
  [FuseV1Options.EnableNodeOptionsEnvironmentVariable]: false, // 禁止 NODE_OPTIONS
  [FuseV1Options.EnableNodeCliInspectArguments]: false, // 禁止 --inspect
  [FuseV1Options.EnableEmbeddedAsarIntegrityValidation]: true, // ASAR 完整性校验
  [FuseV1Options.OnlyLoadAppFromAsar]: true,  // 只从 ASAR 加载应用
})
```

### 3.3 安全警告系统

Electron 在开发模式下会在控制台打印安全警告：

```bash
# 强制开启安全警告（即使在生产构建中）
ELECTRON_ENABLE_SECURITY_WARNINGS=true npm start

# 关闭安全警告（不推荐）
ELECTRON_DISABLE_SECURITY_WARNINGS=true npm start
```

# 第二部分：性能

## 🟢 小白入门：性能的定义

Electron 性能不是单一指标，而是多个维度：
- **启动时间**：从点击图标到窗口出现
- **内存占用**：运行时占用的 RAM
- **CPU 使用率**：空闲时和操作时的 CPU 消耗
- **响应性**：用户操作的响应速度（不卡顿）

官方的核心建议：**先量化，再优化**。用 Chrome DevTools 找到真正的瓶颈，而不是凭感觉优化。

---

## 🟡 熟练进阶：8 条性能建议

### 4.1 不要随意引入模块

```bash
# 分析模块加载开销
node --cpu-prof --heap-prof -e "require('your-module')"
# 生成 .cpuprofile 和 .heapprofile，用 Chrome DevTools 分析
```

**真实案例**：一个提供 `isOnline()` 的网络检测模块，依赖链最终包含一个 10 万行的 JSON 文件。每次 `require()` 都要解析这个文件，在慢速机器上耗时数秒。

评估一个模块时要检查：
- 依赖树的大小（`npm ls` 或 `bundlephobia.com`）
- `require()` 时的资源消耗
- 执行实际功能的资源消耗

### 4.2 延迟加载：Just-In-Time 原则

```js
// ❌ 启动时加载所有模块
const fs = require('node:fs')
const fooParser = require('foo-parser')  // 大模块，立即加载

class Parser {
  constructor() {
    this.files = fs.readdirSync('.')  // 立即读磁盘
  }
}
const parser = new Parser()

// ✅ 按需加载
const fs = require('node:fs')

class Parser {
  async getFiles() {
    // 真正需要时才读磁盘，用异步版本
    this.files = this.files || await fs.promises.readdir('.')
    return this.files
  }

  async getParsedFiles() {
    // 真正需要时才加载大模块（有模块缓存，只慢一次）
    const fooParser = require('foo-parser')
    const files = await this.getFiles()
    return fooParser.parse(files)
  }
}
```

VS Code 的做法：打开文件时立刻显示文本（无高亮），等文本显示完再加载语法高亮。优先响应用户，后台完成剩余工作。

### 4.3 不要阻塞主进程

主进程是整个应用的"控制塔"——所有鼠标点击、窗口操作、GPU 通信都要经过它。阻塞主进程 = 整个应用冻结。

```js
// ❌ 在主进程做 CPU 密集型操作
ipcMain.handle('process-data', async (event, data) => {
  // 这会阻塞主进程！
  const result = heavyComputation(data)
  return result
})

// ✅ 用 Worker Threads 处理 CPU 密集型任务
const { Worker } = require('node:worker_threads')

ipcMain.handle('process-data', async (event, data) => {
  return new Promise((resolve, reject) => {
    const worker = new Worker('./worker.js', { workerData: data })
    worker.on('message', resolve)
    worker.on('error', reject)
  })
})
```

```js
// ❌ 主进程里用同步 I/O
const content = fs.readFileSync('/large/file')

// ✅ 用异步 I/O
const content = await fs.promises.readFile('/large/file')
```

### 4.4 不要阻塞渲染进程

```js
// ❌ 在渲染进程做大量同步计算（会卡 UI）
function processLargeArray(arr) {
  return arr.map(item => heavyTransform(item))
}

// ✅ 用 requestIdleCallback 处理小任务
requestIdleCallback(() => {
  initializeAnalytics()
  prefetchNextPage()
})

// ✅ 用 Web Workers 处理大任务
const worker = new Worker('./heavy-worker.js')
worker.postMessage({ data: largeArray })
worker.onmessage = (e) => updateUI(e.data.result)
```

### 4.5 不要引入不必要的 Polyfill

Electron 使用最新版 Chromium，很多 polyfill 是多余的：

```js
// ❌ 不必要的 polyfill（Electron 已支持这些特性）
import 'core-js/stable'
import 'regenerator-runtime/runtime'

// ✅ 直接用原生 API
const result = await fetch('https://api.example.com/data')
const arr = [1, 2, 3].flatMap(x => [x, x * 2])
```

### 4.6 避免不必要的网络请求

```js
// ❌ 启动时预加载所有数据
app.whenReady().then(async () => {
  await prefetchAllUserData()  // 可能用户根本不需要
  await downloadAllAssets()
  createWindow()
})

// ✅ 按需加载，用缓存
const cache = new Map()

async function getData(key) {
  if (cache.has(key)) return cache.get(key)
  const data = await fetchData(key)
  cache.set(key, data)
  return data
}
```

### 4.7 打包代码

```js
// webpack.config.js
module.exports = {
  target: 'electron-renderer',
  mode: 'production',
  optimization: {
    splitChunks: {
      chunks: 'all',
      // 把 node_modules 单独打包，利用缓存
      cacheGroups: {
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendors',
          chunks: 'all'
        }
      }
    }
  }
}
```

### 4.8 不需要菜单时移除默认菜单

```js
const { Menu } = require('electron')

// 如果你的应用不需要默认菜单
Menu.setApplicationMenu(null)

// 或者只在需要时设置
app.whenReady().then(() => {
  if (needsMenu) {
    Menu.setApplicationMenu(buildMenu())
  } else {
    Menu.setApplicationMenu(null)
  }
})
```

## 🔴 专家深入：性能分析工具链

### 5.1 Chrome DevTools 性能分析

```js
// 在主进程打开 DevTools
mainWindow.webContents.openDevTools()

// 或者通过快捷键：Ctrl+Shift+I（Windows/Linux）/ Cmd+Option+I（macOS）
```

**Performance 面板**：录制运行时性能，找到长任务（>50ms）和帧率下降。

**Memory 面板**：拍堆快照，找内存泄漏。

### 5.2 Chrome Tracing（多进程分析）

```js
const { contentTracing } = require('electron')

// 开始录制
await contentTracing.startRecording({
  include_categories: ['*']
})

// 5 秒后停止并保存
setTimeout(async () => {
  const tracePath = await contentTracing.stopRecording()
  console.log('Trace 保存到：', tracePath)
  // 用 chrome://tracing 打开分析
}, 5000)
```

### 5.3 启动时间分析

```js
// 在 main.js 最开始记录时间
const startTime = Date.now()

app.whenReady().then(() => {
  console.log(`应用就绪耗时：${Date.now() - startTime}ms`)
})

// 监听第一个窗口显示
mainWindow.once('show', () => {
  console.log(`首窗口显示耗时：${Date.now() - startTime}ms`)
})
```

### 5.4 内存泄漏检测

```js
// 定期检查内存使用
setInterval(() => {
  const memUsage = process.memoryUsage()
  console.log({
    rss: `${Math.round(memUsage.rss / 1024 / 1024)}MB`,
    heapUsed: `${Math.round(memUsage.heapUsed / 1024 / 1024)}MB`,
    heapTotal: `${Math.round(memUsage.heapTotal / 1024 / 1024)}MB`
  })
}, 10000)

// 常见内存泄漏原因：
// 1. 事件监听器没有移除
// 2. 闭包持有大对象引用
// 3. 全局缓存无限增长
// 4. BrowserWindow 销毁后 webContents 引用未清理
```

## 📝 小结

**安全核心原则：**
- 最小权限：只暴露必要的 API，不要暴露整个 `ipcRenderer`
- 默认安全：Electron 20+ 的默认配置已经很安全，不要随意关闭安全选项
- 验证输入：所有来自渲染进程的 IPC 消息都要验证发送者和参数

**性能核心原则：**
- 先量化：用 Chrome DevTools 找真正的瓶颈
- 延迟加载：启动时只做必要的事，其余按需加载
- 不阻塞：主进程和渲染进程都不要做同步的耗时操作

**安全和性能的共同点**：都是最小权限原则的体现——只做必要的事，不做多余的事。
