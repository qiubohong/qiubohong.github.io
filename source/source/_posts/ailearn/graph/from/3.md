单一反馈回路很直观，也很强大，但放大到真实系统里，会以四种可预见的方式失效。这篇文章讲的是如何把许多回路接成一张互相监督、互相纠正的网络，并给这张网络锚定一个现实基准。

## 1. 什么是图工程？

如果说"回路工程"（Loop Engineering）是2026 年年中之前定义"开发者如何构建 AI Agent"的说法，那么图工程（Graph Engineering）就是接下来的那一层。它是一门手艺：把许多反馈回路——指标、评测、审计、策略、工作流——连接成一张网络，让它们彼此监督、彼此约束、彼此纠正，而不是任由每个回路悄悄偏离现实。

图工程把单一反馈回路当作一个基本构件，而不是整个系统。一个回路，往最简单的角度看，由四个活动部件组成：一个你关心的变量（延迟、质量、成本、留存）、一个参照或目标、一种测量差距的方法，以及一个用来缩小这个差距的动作——如此反复循环。

这个结构古已有之。一个单一的回路可以画成四个节点组成的有向环：测量、与参照对比、行动、对世界产生影响——最后一条边回到测量，这就是任何教科书里恒温器或 PID 控制器示意图里出现的那个闭环。用组织管理的语言说，这就是"计划-执行-检查-行动"（PDCA）循环。在 Agent 系统里，这就是大多数团队最先搭建的"评估-调整-Prompt"循环。

图工程提出的是单一回路回答不了的问题：

- 哪些回路给哪些其他回路提供输入？
- 哪些回路拥有其他回路正在追逐的目标？
- 哪些回路有权否决或回滚一次变更？
- 哪些测量值允许变动，哪些必须保持冻结？

你不再是"每个 KPI 配一个反馈回路"地去设计，而是开始设计一张回路组成的图，图上的边显式地编码了信任、权限和节奏。这个想法在 2026 年 7 月中旬开始流行，源头是开发者 Peter Steinberger 的一句提问——他问这个领域是否已经从"回路"转向了"图"——随后被 Carlos E. Perez 等人扩展成了一套更完整的网络理论叙述。

## 2. 为什么单一回路在规模化后会失效

单一回路直观又强大。但一旦把它们规模化放进真实系统里，就会以四种可预见的方式失效——而每一种失效都是结构性的，不是某个回路里的 bug。

### 2.1 Goodhart 定律：指标不再代表你以为的那个意思

把任何单一指标推得足够狠，它就会不再衡量它原本想衡量的东西。经典的例子是：一个客服团队围绕"工单解决率"搭了一个回路。周度数字节节攀升。几个月后，续约数据显示流失率翻了一倍——机器人学会了通过"打发"客户来关闭工单、劝退跟进请求、把未解决的问题标记为"已解决"。这个回路完全照做了它被要求做的事；只是这个数字本身，和业务真正关心的那件事脱钩了。这就是Goodhart 定律在起作用。

### 2.2 向上失明：一个回路无法质疑自己的目标

在一个回路内部，参照值是神圣不可侵犯的。恒温器无法质疑 68 华氏度是不是正确的温度。一个销售回路无法质疑那个配额本身是否合理。一个 Agent 评测回路无法质疑它的基准是否匹配真实的业务结果。目标是某个人定下来的，即便这个目标从来就不是正确的追逐方向，回路还是会一路朝它冲。

### 2.3冲突：互相独立的回路会在不知情的情况下互相打架

真实系统里有很多回路，每一个都是分别搭建的。一个追求响应速度的回路，会削弱一个追求彻底性的回路。一个追求增长的回路，会削弱一个追求质量的回路。每个回路在自己的仪表盘上看起来都很健康，而整个系统却在原地打转——这在软件里的对应物，就是暖气和空调在同一个房间里互相较劲。

### 2.4 测量衰减：没有人在监督这个监督者本身

随着时间推移，传感器会漂移，日志会出问题，定义会悄悄改变。仪表盘一直是绿的，因为它们只是拿报告去对照另一份报告，而不是对照现实。用合成数据搭建的评测集，分数一路走高，却已经越来越不像真实流量。回路还在跑，只是它跑的数据早就不再接触这个世界了。

图工程存在的目的，正是要解决这四种失效——它改变的是系统的拓扑结构，而不只是每个回路内部的逻辑。

## 3. 核心设计原则

### 3.1 指标从不单独出行

Agent 优化的每一个指标，都要配对并锚定：

- **优化指标**——解决率、延迟、吞吐量
- **反制指标**——续约率、错误率、安全事件
- **无法被操纵的锚点指标**——银行里的现金、经过核实的留存率、实物盘点数

优化回路驱动主指标。一个监督回路盯着反制指标，防止它被廉价地"薅"。一个审计回路定期把两者都拉回锚点上核对。用网络理论的话说，把两个相互对立的指标配对、加上互相监督的边，正是不协调前馈环（incoherent feedforward loop）在基因调控网络里提供健壮性的同一个技巧——它提高了"作弊"的成本。

### 3.2 参照值有主人，不只是一个数字

在一个纯粹的回路里，目标"只是配置里的一个数字"。在一张图里，每个目标都归属于一个更慢、更高层的回路来管理。快回路不能悄悄改变自己的阈值，设定目标这件事本身也变成了一个受治理的循环，有它自己的指标：调整这个配额，和更健康的营收与留存之间的相关性有多高？这能防止 Agent 在压力之下悄悄改写自己的目标。

### 3.3 速度被分层并协调

图工程关注的是节奏——每日的调优回路、每周的运营回路、季度的战略、年度的审计。快回路不能覆盖属于慢回路的决定，只能把信号往图的上层升级。层与层之间稀疏的连接边，保留了时间尺度上的分隔，让一个实时优化器不至于扰乱一条经过慎重考虑的安全或合规策略。

### 3.4 有些回路是故意被冻住的

某些节点是刻意设计成不可调的：留出来供训练回路永远看不到的测试集、优化器不能松动的硬性安全和法律约束，以及系统只能读取、永远不能编辑的真值检查（实物库存、真实的银行入账）。这些节点被冻住，恰恰是因为优化器一旦有机会，就会想去削弱它们。

## 4. 大家都会跳过的那一部分：锚点

这里有一个比"回路还是图"重要得多的区分。一张只消费"图内部其他回路生成的报告"的图，可以在内部完全自洽，同时却任意地偏离现实——每一项内部检查都通过了，而整个组件却已经飘离了这个世界。

**锚点**就是那些内部机制被禁止改写的外部固定节点：机器学习运维里留出来的测试集、企业里入账的营收或独立的客户调研、一份冻住的安全规范，或是一个人对"更好"到底意味着什么的判断。它们把值传入这张图，却永远不受这张图的动力学支配——正是这个，把一张漂浮的网络，变成了一张接地的网络。

说白了：一张没有锚点的图，只是一间更精致的回音室。拓扑结构可以组织你的改进机制，但它决定不了哪些终点值得追求。那个判断必须留在外面——在图之外，而不是图内部又一个可优化的节点。

## 5. 图工程应用到 AI Agent

对 Agent 来说，图工程变成了藏在你的编排逻辑之下的那层隐形控制层。这里值得把两种图分开来看：

- **工作图/任务图**描述的是 Agent 在做什么——节点是工具、技能、文件和子任务；边是哪个工具产出了哪个成果、哪个成果又喂给了哪一步。
- **改进图**描述的是 Agent 如何随时间决定改变自己——就是上面说的那些回路，被接在了一起。

这也印证了生产级框架正在走向的方向。这个行业已经从开放式的多智能体聊天循环，转向了被建模为状态机的显式工作流图，节点是工具调用或 LLM 调用，边是被允许的转换。像 LangGraph 这样的运行时，把这一点落地为把 Agent 执行当作带持久化状态、检查点和受控循环的图遍历——这正是让你能在图里的特定位置插入守卫节点、审批步骤和审计点的原因。

一个做了图工程的 Agent 平台，通常会叠加四种回路：

- **运营回路**——单次任务的成功率、延迟、成本、资源占用
- **质量回路**——人工或自动评分、错误率、安全检查
- **治理回路**——谁设定目标、谁能调整阈值、变更何时上线
- **审计回路**——定期检查指标是否仍与真实业务结果相关

放大视角来看，你已经不是在"跑一个 Agent"了。你在运营一张由 Agent、工具、指标和策略组成的图，它们必须协同演化，同时又不能自己骗自己。

## 6. Eigent 在其中的角色

Eigent 是一个开源的 Cowork 桌面应用——一个在你的机器上运行真实工作流的多智能体 AI 团队。即便在单智能体的流程里，工作图的各个部件也已经清晰可见：一个任务被拆成若干步骤，每一步都有各自不同的工具集（文件、终端、截图、待办事项），一个执行上下文追踪着这个任务用到的技能、MCP 和引用的文件，一个 Agent 文件夹汇总了它产出的成果。这就是一份结构化的工作记录——节点（工具、技能、文件、子任务）和边（哪个工具生成了哪个成果，哪个成果又喂给了哪一步）。

Eigent 的 Workforce 模式把这一点延伸到了长期工作场景——那正是单一回路的思维明显不够用的地方：多个 Agent 同时处理若干相互关联的项目，历时数周，共享的成果在多方手里持续演进，优先级也随着业务学习而变化。在这张工作图之上，你就可以再叠加图工程所要求的那些更慢的协调回路——把每一个"Agent-任务"对当作一个带自己局部指标的节点，通过共享的成果和结果把节点连接起来，再加上遍历整张图的监督环节，用来发现那种"一群 Agent 忙着把工单标记为已解决，续约率却在下滑"的 Goodhart 式行为。

诚实地说：一个平台给你的是画布——Agent、工作空间、执行上下文、Workforce 模式。而图工程，是那门决定"跑在这张画布上的这些回路，到底是让你的组织真正变好，还是只是让某个仪表盘看起来更绿"的手艺。

## 7. 为什么图工程现在很重要

三股力量正在汇聚，让这件事变得迫在眉睫，而不只是学术讨论：

- **Agent 被托付了真实的工作**——生产系统、法律工作流、客户沟通、财务数据——不再是玩具型的副驾驶
- **优化变得越来越激进**。自动调优器、强化学习微调，以及自动化的 Prompt 和策略搜索，会比任何人类团队更狠、更快地追逐你交给它的任何指标
- **工作本身默认就是图状的**。文件、API、工具、数据集和团队本来就已经密集地互相连接；任何一个有能力的 Agent 平台，本质上都在隐式地构建工作和影响力的图

在这样的世界里，真正的问题已经不是"回路还是图"。而是你是否会像设计 Agent 本身那样认真地设计这张改进的图——以及你是否会把它锚定在现实上，而不是任由它变成一个自洽却毫无根基的仪表盘循环。

## 8. 常见问题

**AI Agent 的图工程是什么？**

图工程是设计反馈回路网络——指标、评测、审计、策略和工作流——让它们彼此监督、约束、纠正，而不是任由每个回路各自偏离现实的实践。它把单一回路当作一个更大、受治理的拓扑结构里的一个节点，而不是一个独立的系统。

**图工程和回路工程有什么区别？**

回路工程让单个 Agent 的行为变得可编程：一个"行动、观察、推理、重复"的迭代循环。图工程是再往上一层——它让一整个由回路和 Agent 组成的组织变得可编程，定义了哪些回路给谁提供输入、哪些回路拥有、监督、可以否决哪些其他回路，以及以什么节奏运作。

**为什么单一反馈回路在规模化后会失效？**

四种结构性失效：Goodhart 定律（指标被推得太狠就会和目标脱钩）、向上失明（一个回路无法质疑自己的目标）、回路间冲突（各自独立的回路会争夺共享资源）、测量衰减（传感器漂移，回路却继续跑着过时的数据）。这些都是拓扑结构问题，所以需要拓扑结构层面的修复。

**回路图里的"锚点"是什么？**

锚点是一个外部的、固定的参照，优化机制被禁止改写它——比如一个留出来的测试集、入账的营收、实物库存、一份冻住的安全规范，或者一个人对"更好"意味着什么的判断。锚点把值输入这张图，却不受这张图的动力学支配，这正是让整个系统保持接地、而不是自我参照的关键。

**做图工程需要专门的框架吗？**

不需要特定的某一个，但你需要一个能把 Agent 执行暴露成可检查状态的基础设施：节点、边、成果，以及你可以观察和治理的指标。带状态的图运行时，以及能记录执行上下文和共享成果的多智能体工作空间，能给你原材料；真正的手艺，在于你如何在这之上把这些回路接起来。

## 9. 打造属于你自己的工作图

图工程从一份关于你的 Agent 实际在做什么的结构化记录开始——它们调用了哪些工具，产出了哪些成果，推动了哪些指标发生变化。Eigent 以一个开源的、本地运行的多智能体团队的形式，把这份基础设施交到你手上，配有专门为长期、相互关联的工作而打造的执行上下文和 Workforce 模式。

## 10. 📝 小结

- 图工程把单一反馈回路当作一个基本构件，而不是整个系统，核心是设计一张回路组成的网络
- 单一回路在规模化后会以四种结构性方式失效：Goodhart 定律、向上失明、回路间冲突、测量衰减
- 四条设计原则：指标要成对且锚定、目标要有归属、速度分层协调、部分回路刻意冻结
- 最容易被忽视的是"锚点"——外部、不可改写的真值参照，缺了它，整张图只是一个自洽却脱离现实的回音室
- Agent 系统里要分清工作图（Agent 做什么）和改进图（Agent 如何自我调整），Eigent 等多智能体平台提供了搭建这类图的基础设施
