## 从一个问题开始

你有没有想过，ChatGPT 帮你写代码、查资料、改文档，这些事情它是怎么做到的？

不是因为模型"更聪明"了。模型本身只会预测下一个词——它不会主动去读你的文件，也不会自己跑命令。真正让它能干这些事的，是模型背后那套"脚手架"：告诉它有哪些工具可以用、怎么调用、结果怎么反馈回来、任务没完成怎么继续跑。

这套脚手架，就是 **Harness**。

DeepSeek Harness（简称 `dsh`）是 DeepSeek AI 开源的这套脚手架。官网有句话说得很直接：

> **Agent = Model + Harness**
>
> 模型是 Agent 的灵魂。Harness 给予 Agent 理解环境、使用工具，并在真实场景中持续工作的能力。

换句话说：模型是大脑，Harness 是身体。光有大脑，Agent 什么也干不了。

## 它的核心设计：一切皆插件

dsh 基于 [Cordis](https://github.com/cordiverse/cordis) 插件系统构建，整个框架只有一个核心原则——**一切皆插件**。

这话听起来像口号，但它是真的落地了的。

在 dsh 里，模型适配器是插件，工具注册表是插件，会话日志是插件，连 Agent Loop（Agent 持续运行的循环引擎）本身也是插件。Cordis 内核只做一件事：管理插件的加载、卸载和依赖关系，不承载任何 Agent 能力。

对普通用户来说，这意味着：你不需要改源码，在配置文件里换一行，就能把 DeepSeek 模型换成 OpenAI，或者把本地文件系统换成远程沙箱。

对开发者来说，这意味着：扩展 dsh 的方式是"挂载插件"，而不是"继承类"或"打补丁"。你写的插件卸载时，它注册的所有东西——工具、事件监听、定时器——都会自动清理，不会留下垃圾。

对架构师来说，这背后是一套严格的依赖注入和副作用管理机制。每个插件通过 `ctx`（上下文对象）声明依赖、注册能力，框架保证依赖就绪后才加载插件，卸载时自动回滚所有副作用。这是 Cordis 论文里描述的"时空可组合性"编程范式的工程实现。

## 每次运行，都有迹可循

用过其他 Agent 框架的人大概都踩过这个坑：Agent 跑了一半出了问题，你完全不知道它当时看到了什么、做了什么决定、哪一步出了岔子。只能翻日志，靠猜。

dsh 对这个问题的回答是：**模型可见即已记录**。

这是一条运行时不变量。抵达模型请求的一切——系统提示词、思维链、工具调用与结果、子 Agent 调度、每一次上下文注入——都会写入一个仅追加设计的会话日志。

打开 **Trajectory 视图**，你可以按来源逐条查看模型当时看到的内容。不只是"它做了什么"，而是"它为什么这么做"。

这个日志不只是用来调试的。恢复中断的会话、分叉出一个新的执行路径、回放历史运行、生成遥测数据——全都基于同一份事件流。

## 四种运行模式

dsh 内置了四种模式，不是为了凑数，是真的对应了不同的使用场景：

**标准模式** 是日常用的主力。文件编辑、Shell 执行、网页检索、子代理调度，该有的都有。你说"帮我重构这个模块"，它会自己读文件、改代码、跑测试、验证结果，一套流程跑下来。

**PTC 模式**（Program-Then-Call）有点意思。普通模式下模型是一步一步调工具，PTC 模式下模型会先写一段 TypeScript 程序，把多步操作组合进去，再一次性执行。对需要精确控制执行顺序的场景，这个模式更可靠。

**极简模式** 只有两个工具：持久 bash 和文件编辑器。专门用来跑基准测试——排除所有干扰变量，看模型本身的能力上限。

**创造模式** 是最特别的一个。它让 Agent 检查自己的运行时、在内存里试验插件，然后帮你设计新的 Agent preset。相当于用 Agent 来创造 Agent。

## 安全：Agent 能干活，但得管住它

这是很多人上手 Agent 框架时容易忽略的问题。Agent 能读文件、跑命令、访问网络——这些能力如果没有边界，在生产环境里是很危险的。

dsh 内置了三层安全机制，从外到内依次收紧：

**沙箱（Sandbox）** 是第一道门。所有进程启动都经过 `ctx.sandbox` 后端包装，由沙箱决定是否允许执行、如何限制权限。你可以把沙箱指向一个远程隔离环境，这样 Bash、PTY、文件系统访问就全部在隔离容器里跑，不会碰到宿主机。而且因为文件系统和进程提供方共享同一个执行世界，换一个沙箱后端，Bash、PTY、LSP 等所有工具会一并迁移过去，不需要逐个适配。

**审批策略（Approval Policy）** 是第二道门。某些操作执行前，Web UI 会弹出确认框，等你点了才继续。哪些操作需要审批、哪些可以直接放行，都可以在 `dsh-base` 组合包里配置。Agent 要删文件或者跑危险命令时，你有机会叫停。

**工具执行把关** 是第三道门，也是最细粒度的一层。工具调用走的是一条流水线：

```
tool/call → tools/pre-execute → tools/execute → tools/post-execute → tool/result
```

`pre-execute` 和 `post-execute` 是两个可拦截的扩展点。你可以在这里注入安全检查逻辑——过滤危险命令、记录审计日志、限制文件操作范围。不同的 Agent preset 还可以配置不同的权限集合，实现最小权限原则。

## 跑起来只需要一行

安装 Node.js 之后：

```bash
npx @deepseek-ai/dsh web
```

打开 `http://127.0.0.1:3080`，一个完整的 Agent Web UI 就在那了。配置 API Key、选工作区、发第一条指令，整个过程不超过 10 分钟。

想从源码跑：

```bash
git clone https://github.com/deepseek-ai/deepseek-harness
cd deepseek-harness
pnpm install && pnpm run build
pnpm dsh web
```

## 📝 小结

- dsh 是 DeepSeek AI 开源的 Agent 框架，核心理念是"一切皆插件"——所有能力均由插件提供，可在配置层自由替换，不需要改源码
- 基于 Cordis 框架，插件的依赖注入和副作用管理是框架级保证，不是靠约定
- "模型可见即已记录"是核心不变量，Trajectory 视图让调试从"靠猜"变成"有据可查"
- 四种运行模式（标准/PTC/极简/创造）对应不同场景，不是摆设
- 三层安全机制（沙箱/审批策略/工具执行把关）覆盖 Agent 乱来的主要风险
- 目前处于开发者预览阶段，核心 API 持续迭代中
