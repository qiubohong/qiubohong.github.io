> **🎁 读完你会得到**：文档解析插件 + 向量检索工具 + 权限隔离方案 + 一个能问"我们公司的报销流程是什么"的 Agent。

公司文档的命运通常是这样的：写的时候认真写，放到共享盘之后就再也没人看了。

新员工入职，找不到操作手册，只能问老员工。老员工也记不清，翻了半天找到一个 2021 年的版本，不知道还算不算数。

这个问题，用 RAG（检索增强生成）+ dsh 可以很干净地解决。

## 这套方案能解决什么

先说清楚边界，避免期望过高。

**能做到的**：员工用自然语言提问，Agent 从公司文档里找到相关内容，给出准确回答，并标注来源文档。支持追问，比如"那报销上限是多少"——它知道你还在问报销流程。

**做不到的**：实时同步文档更新（需要手动触发重新索引）、理解图表和复杂表格（纯文本提取）、跨文档做复杂推理（比如"把这两份合同的差异列出来"，这个需要专门设计）。

想清楚这两点，就知道这套方案适不适合你的场景了。

---

## 技术选型

中小企业落地 RAG，有几个选择：

| 方案 | 优点 | 缺点 | 适合场景 |
|---|---|---|---|
| 本地向量库（Chroma/Faiss） | 免费、数据不出公司 | 需要自己维护 | 数据敏感、预算有限 |
| 云向量数据库（Pinecone/Weaviate） | 托管、省心 | 有费用、数据上云 | 预算充足、快速上线 |
| 纯关键词检索（Elasticsearch） | 简单、可控 | 语义理解弱 | 文档结构化、关键词明确 |

这篇用 **Chroma**（本地向量库）+ **OpenAI Embeddings**（或 DeepSeek Embeddings）。数据不出公司，部署简单，中小企业首选。

## 第一步：文档解析与索引

这个脚本离线运行，把公司文档解析成向量存到 Chroma。

```typescript
// src/scripts/index-docs.ts
import { ChromaClient } from 'chromadb'
import { OpenAI } from 'openai'
import { readFileSync, readdirSync, statSync } from 'fs'
import { join, extname, basename } from 'path'

const chroma = new ChromaClient({ path: 'http://localhost:8000' })
const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY })

// 简单的文本分块：按段落切，每块不超过 500 字
function splitIntoChunks(text: string, maxChunkSize = 500): string[] {
  const paragraphs = text.split(/\n\n+/)
  const chunks: string[] = []
  let current = ''

  for (const para of paragraphs) {
    if ((current + para).length > maxChunkSize && current) {
      chunks.push(current.trim())
      current = para
    } else {
      current += (current ? '\n\n' : '') + para
    }
  }
  if (current.trim()) chunks.push(current.trim())
  return chunks
}

// 读取文档（目前支持 .txt 和 .md，Word/PDF 需要额外解析库）
function readDocument(filePath: string): string {
  const ext = extname(filePath).toLowerCase()
  if (['.txt', '.md'].includes(ext)) {
    return readFileSync(filePath, 'utf-8')
  }
  throw new Error(`暂不支持 ${ext} 格式，请先转换为 txt 或 md`)
}

async function indexDocuments(docsDir: string) {
  const collection = await chroma.getOrCreateCollection({
    name: 'company-knowledge',
    metadata: { 'hnsw:space': 'cosine' }
  })

  const files = readdirSync(docsDir).filter(f =>
    ['.txt', '.md'].includes(extname(f).toLowerCase())
  )

  console.log(`找到 ${files.length} 个文档，开始索引...`)

  for (const file of files) {
    const filePath = join(docsDir, file)
    const content = readDocument(filePath)
    const chunks = splitIntoChunks(content)
    const docName = basename(file, extname(file))

    console.log(`  处理 ${file}：${chunks.length} 个分块`)

    // 批量生成 embedding
    const embeddings = await openai.embeddings.create({
      model: 'text-embedding-3-small',
      input: chunks
    })

    await collection.add({
      ids: chunks.map((_, i) => `${docName}_chunk_${i}`),
      embeddings: embeddings.data.map(e => e.embedding),
      documents: chunks,
      metadatas: chunks.map((_, i) => ({
        source: file,
        docName,
        chunkIndex: i,
        totalChunks: chunks.length
      }))
    })
  }

  console.log('索引完成！')
}

indexDocuments('./docs').catch(console.error)
```

运行索引：

```bash
# 先启动 Chroma
docker run -p 8000:8000 chromadb/chroma

# 把公司文档放到 docs/ 目录，然后运行
npx ts-node src/scripts/index-docs.ts
```

## 第二步：向量检索工具插件

```typescript
// src/plugins/rag-search.ts
import type { Context } from '@deepseek-ai/cordis'
import { ChromaClient } from 'chromadb'
import { OpenAI } from 'openai'

export const name = 'rag-search'
export const inject = ['tools']

export function apply(ctx: Context) {
  const chroma = new ChromaClient({ path: 'http://localhost:8000' })
  const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY })

  ctx.tools.register({
    name: 'search_company_docs',
    description: '在公司内部文档中搜索相关信息。当员工询问公司政策、流程、规范、产品信息等内部知识时使用。',
    parameters: {
      type: 'object',
      properties: {
        query: {
          type: 'string',
          description: '搜索问题，用自然语言描述'
        },
        topK: {
          type: 'number',
          description: '返回最相关的文档片段数量，默认3',
          default: 3
        }
      },
      required: ['query']
    },
    async execute({ query, topK = 3 }) {
      try {
        const collection = await chroma.getCollection({ name: 'company-knowledge' })

        // 生成查询向量
        const queryEmbedding = await openai.embeddings.create({
          model: 'text-embedding-3-small',
          input: query
        })

        // 向量检索
        const results = await collection.query({
          queryEmbeddings: [queryEmbedding.data[0].embedding],
          nResults: topK,
          include: ['documents', 'metadatas', 'distances']
        })

        if (!results.documents[0]?.length) {
          return { found: false, message: '未在公司文档中找到相关信息' }
        }

        // 过滤相似度太低的结果（距离 > 0.5 说明不太相关）
        const relevantResults = results.documents[0]
          .map((doc, i) => ({
            content: doc,
            source: results.metadatas![0][i]?.source as string,
            docName: results.metadatas![0][i]?.docName as string,
            similarity: 1 - (results.distances![0][i] || 0)
          }))
          .filter(r => r.similarity > 0.5)

        if (relevantResults.length === 0) {
          return { found: false, message: '未找到足够相关的文档内容' }
        }

        return {
          found: true,
          results: relevantResults,
          tip: '以上内容来自公司内部文档，请以最新版本为准'
        }
      } catch (error) {
        ctx.logger.error('[rag-search] 检索失败：%s', error)
        return { found: false, message: '文档检索服务暂时不可用' }
      }
    }
  })
}
```

## 第三步：系统提示词——让 Agent 知道自己是"内部助手"

```typescript
// src/plugins/kb-prompt.ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'kb-system-prompt'
export const inject = ['systemPrompt']

export function apply(ctx: Context) {
  ctx.systemPrompt.register({
    id: 'kb-persona',
    priority: 100,
    content: `你是公司内部知识助手，帮助员工快速找到公司文档中的信息。

## 工作方式
1. 收到问题后，先用 search_company_docs 工具搜索相关文档
2. 基于搜索结果回答，并注明信息来源（哪个文档）
3. 如果搜索结果不够充分，告知员工并建议联系相关部门

## 回答规范
- 回答要准确，不要在文档内容之外添加推测
- 每次回答末尾注明：「来源：[文档名称]」
- 如果文档内容有歧义或可能已过期，提醒员工核实

## 不能做的事
- 不能回答文档中没有的内容
- 不能透露其他员工的个人信息
- 不能对公司政策做出超出文档范围的解释`
  })
}
```

## 第四步：权限隔离（进阶）

如果公司有不同部门的文档，不是所有人都能看所有内容，可以在检索时加部门过滤：

```typescript
// 在 rag-search.ts 的 execute 函数中加入权限过滤
async execute({ query, topK = 3, department }) {
  const whereFilter = department
    ? { department: { $eq: department } }
    : undefined

  const results = await collection.query({
    queryEmbeddings: [queryEmbedding.data[0].embedding],
    nResults: topK,
    where: whereFilter,  // 只搜索该部门的文档
    include: ['documents', 'metadatas', 'distances']
  })
  // ...
}
```

索引时给文档打上部门标签：

```typescript
metadatas: chunks.map(() => ({
  source: file,
  docName,
  department: 'hr'  // 或 'finance', 'tech', 'sales'
}))
```

## 文档更新怎么办

这是 RAG 系统最常见的运维问题。文档更新了，索引里的内容还是旧的。

最简单的方案：**定期全量重建索引**。每天凌晨跑一次索引脚本，把 `docs/` 目录里的所有文档重新索引。对于中小企业来说，文档量不大，全量重建一般 5 分钟以内。

如果文档更新频繁，可以做增量更新：记录每个文件的最后修改时间，只重新索引有变化的文件。

```typescript
// 增量更新：只处理有变化的文件
const lastIndexed = loadLastIndexedTimes()  // 从本地 JSON 读取
for (const file of files) {
  const mtime = statSync(join(docsDir, file)).mtime.getTime()
  if (mtime > (lastIndexed[file] || 0)) {
    // 删除旧的 chunks，重新索引
    await reindexFile(file)
    lastIndexed[file] = mtime
  }
}
saveLastIndexedTimes(lastIndexed)
```

## 实际效果和局限

这套方案在实际使用中，对于结构清晰的文档（比如 FAQ、操作手册、政策文件）效果很好，准确率能到 85% 以上。

但有几个场景效果不好：

**表格和图表**：纯文本提取会丢失表格结构。如果文档里有大量表格，考虑用 `pdf-parse` 或 `mammoth`（Word 解析）做更精细的处理。

**跨文档推理**：比如"把 A 合同和 B 合同的付款条款对比一下"，这需要同时检索两份文档并做比较，当前方案做不好，需要专门设计多文档对比工具。

**口语化问题**：员工有时候问的很口语，比如"那个啥，报销的事怎么弄"，关键词不明确，检索效果会差。可以在工具里加一步"问题改写"，让模型先把问题规范化再检索。

---

## 📝 小结

- RAG 的核心是"检索 + 生成"，检索质量决定回答质量，文档分块和 embedding 模型的选择很关键
- 中小企业用 Chroma 本地向量库起步，数据不出公司，部署简单
- 系统提示词里明确"基于文档回答、标注来源"，是保证准确性的关键
- 文档更新用定期全量重建索引，简单可靠，比增量更新好维护
- 表格、跨文档推理是 RAG 的弱项，遇到这类需求要单独设计
