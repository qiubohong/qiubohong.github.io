## 工具是什么，Agent 怎么用它

先说清楚工具在整个系统里的位置。

Agent 每次收到用户指令，会把指令和"当前可用的工具列表"一起发给模型。模型看完之后，决定要不要调工具、调哪个、传什么参数。

这个"工具列表"就是你注册的工具的 schema——名字、描述、参数定义。模型靠这些信息决定用哪个工具。

所以工具开发有两个关键点：

**描述要写好**：模型靠描述决定用哪个工具。描述含糊，模型就会选错，或者不知道该用哪个。

**参数要定义清楚**：模型靠参数 schema 决定传什么值。schema 不准确，模型传的参数就会出问题。

这两点比代码逻辑本身更重要。一个功能完美但描述烂的工具，Agent 根本不会用。

## Tool DSL：一个工具的完整结构

dsh 的工具注册用 `ctx.tools.register()` 方法，接受一个工具定义对象。来看完整结构：

```typescript
import type { Context } from '@deepseek-ai/cordis'

export const name = 'my-tools'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register({
    // ① 工具名：Agent 调用时用的标识符，用下划线命名
    name: 'search_users',

    // ② 描述：这是最重要的字段，模型靠它决定用不用这个工具
    // 写清楚：什么时候用、能做什么、不能做什么
    description: '在用户数据库中搜索用户信息。当需要查找特定用户的详细信息时使用。' +
      '支持按姓名、邮箱、用户ID搜索。不支持模糊搜索，关键词需要精确匹配。',

    // ③ 参数定义：JSON Schema 格式
    parameters: {
      type: 'object',
      properties: {
        query: {
          type: 'string',
          description: '搜索关键词，支持：用户姓名（精确）、邮箱地址、用户ID（数字）'
        },
        field: {
          type: 'string',
          description: '搜索字段',
          enum: ['name', 'email', 'id'],  // 枚举值限制模型的选择范围
          default: 'name'
        },
        limit: {
          type: 'number',
          description: '返回结果数量上限，默认10，最大50',
          default: 10
        }
      },
      required: ['query']  // 必填参数
    },

    // ④ 执行函数：工具的实际逻辑
    async execute({ query, field = 'name', limit = 10 }) {
      // 实际的数据库查询逻辑
      const results = await db.users.findMany({
        where: { [field]: query },
        take: Math.min(limit, 50)
      })

      if (results.length === 0) {
        return { found: false, message: `未找到匹配"${query}"的用户` }
      }

      return {
        found: true,
        count: results.length,
        users: results.map(u => ({
          id: u.id,
          name: u.name,
          email: u.email,
          createdAt: u.createdAt
        }))
      }
    }
  })
}
```

逐个字段说一下：

**`name`**：工具的唯一标识符。用下划线命名（`search_users` 而不是 `searchUsers`），因为模型对下划线命名的工具理解更稳定。

**`description`**：最重要的字段，没有之一。写清楚三件事：什么时候用这个工具、它能做什么、它不能做什么。"不能做什么"很多人忘了写，但它能防止模型在不合适的场景下乱用工具。

**`parameters`**：JSON Schema 格式。`properties` 里每个参数都要有 `description`，告诉模型这个参数填什么。有枚举值的用 `enum` 限制，有默认值的用 `default` 声明。

**`execute`**：工具的实际执行逻辑。接收参数，返回结果。返回值会被序列化成字符串发给模型，所以返回对象就行，不需要手动 `JSON.stringify`。

## 参数类型：怎么让模型传对值

参数定义写得好不好，直接影响模型传参的准确率。几个实用技巧：

**用 `enum` 限制选项**：如果参数只有几个合法值，一定要用 `enum`。模型看到枚举列表，会从里面选，不会乱填。

```typescript
// ❌ 不好：模型可能传 "ascending"、"asc"、"ASC"、"增序" 各种写法
sortOrder: {
  type: 'string',
  description: '排序方向'
}

// ✅ 好：明确限制，模型只能选这两个
sortOrder: {
  type: 'string',
  description: '排序方向',
  enum: ['asc', 'desc']
}
```

**描述里给例子**：抽象的描述不如一个具体的例子。

```typescript
// ❌ 不好：模型不知道日期格式
startDate: {
  type: 'string',
  description: '开始日期'
}

// ✅ 好：给了格式示例
startDate: {
  type: 'string',
  description: '开始日期，格式：YYYY-MM-DD，例如：2026-01-15'
}
```

**复杂参数用 `object` 嵌套**：如果参数本身是个结构体，用嵌套的 `object` 类型。

```typescript
filter: {
  type: 'object',
  description: '筛选条件',
  properties: {
    status: {
      type: 'string',
      enum: ['active', 'inactive', 'pending']
    },
    minAge: {
      type: 'number',
      description: '最小年龄'
    }
  }
}
```

**`required` 只放真正必须的参数**：可选参数不要放进 `required`，让模型在不需要时可以不传。

## 错误处理：别抛异常，返回错误信息

这是工具开发里最容易踩的坑。

很多人写工具时，遇到错误就 `throw new Error(...)`。但在 dsh 里，工具抛异常会打断整个执行流程，Agent 会收到一个不友好的错误，然后不知道怎么继续。

正确的做法是：**把错误信息当成工具结果返回给 Agent**。

```typescript
async execute({ userId }) {
  // ❌ 错误：抛异常会打断 Agent 的执行流程
  const user = await db.users.findById(userId)
  if (!user) {
    throw new Error(`用户 ${userId} 不存在`)
  }

  // ✅ 正确：返回错误信息，让 Agent 自己决定怎么处理
  const user = await db.users.findById(userId)
  if (!user) {
    return {
      success: false,
      error: `用户 ${userId} 不存在`,
      suggestion: '请检查用户ID是否正确，或使用 search_users 工具查找用户'
    }
  }

  return { success: true, user }
}
```

注意 `suggestion` 字段——这不是必须的，但加上之后，Agent 看到错误时会有更明确的下一步方向，不容易卡住。

还有一类错误是系统级的——数据库连接失败、网络超时之类的。这类错误也要捕获，不能让它冒泡出去：

```typescript
async execute({ query }) {
  try {
    const results = await db.search(query)
    return { success: true, results }
  } catch (error) {
    // 系统级错误：记录日志，返回友好提示
    ctx.logger.error('[search-tool] 查询失败：%s', error.message)
    return {
      success: false,
      error: '数据库查询失败，请稍后重试',
      // 不要把原始错误信息暴露给模型，可能包含敏感信息
    }
  }
}
```

## 工具执行流水线：在工具前后插入逻辑

第 01 篇提到过，dsh 的工具执行走一条流水线：

```
tool/call → tools/pre-execute → tools/execute → tools/post-execute → tool/result
```

`pre-execute` 和 `post-execute` 是两个可拦截的扩展点。你可以在这里加安全检查、审计日志、限流等逻辑，而不需要修改每个工具的代码。

来看一个实际例子——给所有工具加执行时间统计：

```typescript
// scratch-plugin/src/tool-monitor.ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'tool-monitor'

export function apply(ctx: Context) {
  const timings = new Map<string, number>()

  // 工具执行前：记录开始时间
  ctx.on('tools/pre-execute', async (event, next) => {
    timings.set(event.callId, Date.now())
    ctx.logger.info('[monitor] 工具开始执行：%s', event.name)
    await next()  // 必须调用 next()，否则工具不会执行
  })

  // 工具执行后：计算耗时
  ctx.on('tools/post-execute', async (event, next) => {
    const startTime = timings.get(event.callId)
    if (startTime) {
      const duration = Date.now() - startTime
      ctx.logger.info('[monitor] 工具执行完成：%s，耗时 %dms', event.name, duration)
      timings.delete(event.callId)

      // 如果耗时超过 5 秒，打一个警告
      if (duration > 5000) {
        ctx.logger.warn('[monitor] 工具执行超时警告：%s 耗时 %dms', event.name, duration)
      }
    }
    await next()
  })
}
```

注意 `pre-execute` 和 `post-execute` 是 **waterfall 事件**——监听器必须调用 `next()` 才能让执行继续往下走。如果你不调 `next()`，工具就不会执行，Agent 会收到一个空结果。

这个特性可以用来做**工具拦截**——在 `pre-execute` 里检查参数，如果不合法就不调 `next()`，直接返回拒绝信息：

```typescript
ctx.on('tools/pre-execute', async (event, next) => {
  // 拦截危险的 bash 命令
  if (event.name === 'bash' || event.name === 'shell') {
    const cmd = event.arguments?.command || ''
    const dangerousPatterns = ['rm -rf', 'DROP TABLE', 'format c:']

    for (const pattern of dangerousPatterns) {
      if (cmd.toLowerCase().includes(pattern.toLowerCase())) {
        ctx.logger.warn('[security] 拦截危险命令：%s', cmd)
        // 不调用 next()，工具不执行
        // 通过修改 event.result 返回拒绝信息
        event.result = {
          error: `命令被安全策略拦截：检测到危险操作 "${pattern}"`,
          blocked: true
        }
        return
      }
    }
  }

  await next()
})
```

## 实战：一个完整的「查数据库」工具

说了这么多，来写一个真正能用的工具。

场景：公司有一个 SQLite 数据库，存着产品信息。我们要让 Agent 能查这个数据库，回答"XX 产品的库存是多少"这类问题。

```typescript
// scratch-plugin/src/product-query.ts
import type { Context } from '@deepseek-ai/cordis'
import Database from 'better-sqlite3'
import { join } from 'path'

export const name = 'product-query'
export const inject = ['tools']

export function apply(ctx: Context) {
  // 初始化数据库连接
  let db: Database.Database | null = null

  ctx.effect(() => {
    const dbPath = join(process.cwd(), 'data', 'products.db')
    db = new Database(dbPath, { readonly: true })  // 只读，防止 Agent 误改数据
    ctx.logger.info('[product-query] 数据库连接成功：%s', dbPath)

    return () => {
      db?.close()
      ctx.logger.info('[product-query] 数据库连接已关闭')
    }
  })

  // 工具1：查询产品信息
  ctx.tools.register({
    name: 'query_product',
    description: '查询产品的详细信息，包括库存、价格、规格等。' +
      '当用户询问某个产品的具体信息时使用。支持按产品名称或SKU查询。',
    parameters: {
      type: 'object',
      properties: {
        keyword: {
          type: 'string',
          description: '产品名称关键词或SKU编号，例如："iPhone 15" 或 "SKU-001"'
        },
        fields: {
          type: 'array',
          description: '需要返回的字段，不填则返回所有字段',
          items: {
            type: 'string',
            enum: ['name', 'sku', 'price', 'stock', 'category', 'description']
          }
        }
      },
      required: ['keyword']
    },
    async execute({ keyword, fields }) {
      if (!db) {
        return { success: false, error: '数据库未初始化' }
      }

      try {
        // 构建查询
        const selectFields = fields?.length
          ? fields.join(', ')
          : 'id, name, sku, price, stock, category'

        const stmt = db.prepare(
          `SELECT ${selectFields} FROM products
           WHERE name LIKE ? OR sku = ?
           LIMIT 10`
        )

        const results = stmt.all(`%${keyword}%`, keyword)

        if (results.length === 0) {
          return {
            success: false,
            message: `未找到包含"${keyword}"的产品`,
            suggestion: '请尝试使用更简短的关键词，或使用 list_product_categories 查看所有分类'
          }
        }

        return {
          success: true,
          count: results.length,
          products: results
        }
      } catch (error) {
        ctx.logger.error('[product-query] 查询失败：%s', error)
        return { success: false, error: '查询执行失败，请稍后重试' }
      }
    }
  })

  // 工具2：查询库存预警
  ctx.tools.register({
    name: 'check_low_stock',
    description: '查询库存不足的产品列表。当用户询问"哪些产品快没货了"或需要补货提醒时使用。',
    parameters: {
      type: 'object',
      properties: {
        threshold: {
          type: 'number',
          description: '库存预警阈值，低于此数量视为库存不足，默认10',
          default: 10
        },
        category: {
          type: 'string',
          description: '按分类筛选，不填则查询所有分类'
        }
      }
    },
    async execute({ threshold = 10, category }) {
      if (!db) {
        return { success: false, error: '数据库未初始化' }
      }

      try {
        let query = 'SELECT name, sku, stock, category FROM products WHERE stock < ?'
        const params: any[] = [threshold]

        if (category) {
          query += ' AND category = ?'
          params.push(category)
        }

        query += ' ORDER BY stock ASC LIMIT 20'

        const results = db.prepare(query).all(...params)

        if (results.length === 0) {
          return {
            success: true,
            message: `所有产品库存均高于 ${threshold}，无需补货`,
            lowStockProducts: []
          }
        }

        return {
          success: true,
          threshold,
          count: results.length,
          lowStockProducts: results,
          summary: `共有 ${results.length} 个产品库存低于 ${threshold}`
        }
      } catch (error) {
        ctx.logger.error('[product-query] 库存查询失败：%s', error)
        return { success: false, error: '查询执行失败' }
      }
    }
  })

  ctx.logger.info('[product-query] 产品查询工具已注册')
}
```

加载这个插件：

```yaml

```

## 工具描述的写法：影响 Agent 行为的关键

工具描述写得好不好，直接决定 Agent 会不会用你的工具、用得对不对。

来看一个对比：

```typescript
// ❌ 描述太简单，模型不知道什么时候用
{
  name: 'get_data',
  description: '获取数据',
  // ...
}

// ✅ 描述清晰，模型知道什么时候用、怎么用
{
  name: 'query_product',
  description: '查询产品的详细信息，包括库存、价格、规格等。' +
    '当用户询问某个产品的具体信息时使用。' +
    '支持按产品名称或SKU查询。' +
    '不支持模糊搜索，关键词需要精确匹配产品名称的一部分。',
  // ...
}
```

几个写描述的原则：

**说清楚触发条件**："当用户询问...时使用"。这告诉模型什么情况下应该调这个工具。

**说清楚能力边界**："支持...，不支持..."。防止模型在不合适的场景下调用。

**说清楚参数含义**：每个参数的 `description` 都要写，不能留空。

**避免歧义**：如果有多个功能相似的工具，要在描述里区分清楚它们的适用场景。

## 一个真实的踩坑：工具返回值太大

工具返回的内容会被塞进 Agent 的上下文窗口。如果返回值太大，会快速消耗 Token，导致上下文溢出。

我遇到过一个案例：一个工具查询数据库，返回了几百条记录，每条记录还有很多字段。结果 Agent 跑了几轮就上下文溢出了。

解决方法：**在工具里控制返回量**。

```typescript
async execute({ keyword, limit = 10 }) {
  const results = await db.search(keyword)

  // 限制返回数量
  const limited = results.slice(0, Math.min(limit, 20))

  // 只返回必要字段，不要把整个对象都返回
  return {
    total: results.length,
    returned: limited.length,
    items: limited.map(item => ({
      id: item.id,
      name: item.name,
      // 只返回 Agent 需要的字段，不要返回所有字段
    }))
  }
}
```

还有一个技巧：如果数据量大，可以分页返回，让 Agent 按需请求：

```typescript
parameters: {
  type: 'object',
  properties: {
    page: {
      type: 'number',
      description: '页码，从1开始，默认1',
      default: 1
    },
    pageSize: {
      type: 'number',
      description: '每页数量，默认10，最大20',
      default: 10
    }
  }
}
```

## 📝 小结

- 工具是 Agent 和外部世界交互的唯一接口，描述写得好不好比代码逻辑更重要
- Tool DSL 的四个关键字段：`name`（标识符）、`description`（触发条件和能力边界）、`parameters`（JSON Schema）、`execute`（执行逻辑）
- 参数定义技巧：用 `enum` 限制选项、描述里给例子、复杂参数用嵌套 `object`
- 错误处理原则：别抛异常，把错误信息当结果返回，加上 `suggestion` 帮 Agent 找到下一步
- 工具执行流水线（`pre-execute` / `post-execute`）是加安全控制和审计日志的正确位置
- 控制工具返回量，避免大量数据撑爆上下文窗口
