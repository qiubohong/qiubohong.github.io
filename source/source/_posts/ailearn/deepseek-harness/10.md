一家做电商的朋友跟我说，他们客服团队每天要回答几百条重复问题——"这个能退货吗"、"发货要几天"、"有没有优惠券"。三个客服，每天 80% 的时间在复制粘贴。

这种场景，是 AI 客服最容易落地的地方。不需要多复杂的技术，但要做对几个关键点。

## 先想清楚要做什么

很多人上来就开始写代码，结果做出来的东西要么太简单（就是个问答机器人），要么太复杂（搞了一堆用不上的功能）。

一个能实际用起来的中小企业客服系统，核心需求其实就三条：

**回答产品问题**：能查到公司的产品信息、政策、FAQ，给出准确的回答，不能瞎编。

**多轮对话**：用户问"这个能退货吗"，客服说"可以，7天无理由"，用户再问"那运费谁出"——这个上下文得记住。

**知道自己的边界**：遇到投诉、复杂纠纷、需要查订单的情况，要能识别出来，转给人工，不能硬撑。

这三条想清楚了，代码就好写了。

## 第一步：搭知识库插件

知识库是整个系统的基础。中小企业一般没有向量数据库，用 JSON 文件存 FAQ 就够了，后面有需要再升级。

```typescript
// src/plugins/knowledge-base.ts
import type { Context } from '@deepseek-ai/cordis'
import { readFileSync } from 'fs'
import { join } from 'path'

export const name = 'knowledge-base'
export const inject = ['tools']

interface FAQItem {
  question: string
  answer: string
  keywords: string[]
  category: string
}

export function apply(ctx: Context) {
  // 加载 FAQ 数据
  const faqData: FAQItem[] = JSON.parse(
    readFileSync(join(__dirname, '../data/faq.json'), 'utf-8')
  )

  // 注册知识库查询工具
  ctx.tools.register({
    name: 'search_knowledge_base',
    description: '在产品知识库中搜索相关问题和答案。当用户询问产品信息、退换货政策、配送时效等问题时使用。',
    parameters: {
      type: 'object',
      properties: {
        query: {
          type: 'string',
          description: '用户的问题或关键词'
        },
        category: {
          type: 'string',
          description: '问题分类：product（产品）/ policy（政策）/ delivery（配送）/ payment（支付）',
          enum: ['product', 'policy', 'delivery', 'payment', 'other']
        }
      },
      required: ['query']
    },
    async execute({ query, category }) {
      // 简单的关键词匹配，实际项目可以换成向量检索
      const results = faqData.filter(item => {
        const matchCategory = !category || item.category === category
        const matchKeyword = item.keywords.some(kw =>
          query.toLowerCase().includes(kw.toLowerCase())
        ) || item.question.toLowerCase().includes(query.toLowerCase())
        return matchCategory && matchKeyword
      })

      if (results.length === 0) {
        return { found: false, message: '知识库中未找到相关信息' }
      }

      return {
        found: true,
        results: results.slice(0, 3).map(r => ({
          question: r.question,
          answer: r.answer,
          category: r.category
        }))
      }
    }
  })

  ctx.logger.info('[knowledge-base] 知识库加载完成，共 %d 条记录', faqData.length)
}
```

## 第二步：人工转接插件

这是很多 AI 客服做不好的地方——不知道什么时候该"认输"。

```typescript
// src/plugins/handoff.ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'handoff'
export const inject = ['tools']

// 需要转人工的触发词
const HANDOFF_TRIGGERS = [
  '投诉', '举报', '骗子', '假货', '维权',
  '订单号', '查订单', '物流异常', '丢件',
  '人工', '转人工', '客服', '真人'
]

export function apply(ctx: Context) {
  ctx.tools.register({
    name: 'request_human_agent',
    description: '当用户需要人工客服时调用此工具。适用场景：用户明确要求转人工、涉及投诉纠纷、需要查询具体订单信息、问题超出知识库范围且无法解答。',
    parameters: {
      type: 'object',
      properties: {
        reason: {
          type: 'string',
          description: '转接原因，用于告知人工客服背景'
        },
        urgency: {
          type: 'string',
          enum: ['normal', 'urgent'],
          description: '紧急程度'
        }
      },
      required: ['reason']
    },
    async execute({ reason, urgency }) {
      // 实际项目里这里对接你的客服系统 API
      // 比如：发送 webhook、写入数据库、推送到客服工作台
      ctx.logger.info('[handoff] 转人工请求：%s（%s）', reason, urgency)

      return {
        success: true,
        message: '已为您转接人工客服，预计等待时间 2-5 分钟。转接期间您可以继续描述问题，人工客服接入后会看到完整对话记录。',
        ticketId: `CS${Date.now()}`
      }
    }
  })

  // 监听用户消息，自动检测是否需要转人工
  ctx.on('user/message', (event) => {
    const content = event.content?.toLowerCase() || ''
    const needsHandoff = HANDOFF_TRIGGERS.some(trigger =>
      content.includes(trigger)
    )
    if (needsHandoff) {
      ctx.logger.info('[handoff] 检测到转人工触发词')
      // 可以在这里注入提示，让模型优先考虑转人工
    }
  })
}
```

## 第三步：系统提示词配置

系统提示词决定了 Agent 的"性格"和边界。这里有几个关键点：

```typescript
// src/plugins/cs-tools.ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'cs-system-prompt'
export const inject = ['systemPrompt']

export function apply(ctx: Context) {
  ctx.systemPrompt.register({
    id: 'cs-persona',
    priority: 100,
    content: `你是「XX品牌」的智能客服助手小X。

## 你的职责
- 回答用户关于产品、政策、配送、支付的问题
- 使用知识库工具查询准确信息，不要凭空编造
- 遇到无法回答的问题，诚实告知并转接人工

## 回答风格
- 简洁友好，不要过于正式
- 每次回答控制在100字以内，除非用户需要详细说明
- 用"您"称呼用户

## 必须转人工的情况
- 用户明确要求转人工
- 涉及投诉、纠纷、维权
- 需要查询具体订单信息
- 连续2次无法从知识库找到答案

## 禁止事项
- 不得承诺知识库中没有的优惠或政策
- 不得对竞品做出负面评价
- 不得透露内部系统信息`
  })
}
```

## 上线前的检查清单

做完功能，上线前还有几件事要确认：

**知识库质量**：FAQ 覆盖了 80% 的常见问题吗？关键词设置准确吗？跑几十条真实用户问题测一下。

**转人工逻辑**：触发词列表够不够？有没有漏掉的场景？建议找几个真实客服聊聊，他们最清楚哪些问题不该让 AI 回答。

**回答准确性**：重点测退货政策、价格、活动这类"说错了有损失"的问题。宁可说"我不确定，帮您转人工确认"，也不要给出错误信息。

**并发压力**：dsh 默认是单进程，如果日均咨询量超过 500 条，考虑用 headless 模式 + 消息队列做异步处理。

**会话超时**：用户半小时没回复，会话应该自动关闭，避免资源占用。

## 一个真实的踩坑经验

我在帮一家公司落地这套方案时，遇到过一个问题：模型有时候会"发挥"——知识库里说"7天无理由退货"，它回答成了"15天无理由退货"。

原因是模型的训练数据里有其他电商平台的政策，它在"帮忙补充"。

解决方法很简单：在系统提示词里加一句"**所有政策信息必须来自知识库查询结果，不得使用训练数据中的信息**"，问题就消失了。

这也是为什么系统提示词里要明确写"使用知识库工具查询，不要凭空编造"——不是废话，是真的有用。

## 📝 小结

- 中小企业客服系统的核心是三件事：准确回答、记住上下文、知道边界
- 知识库用 JSON + 关键词匹配起步，够用了，后面有需要再换向量检索
- 人工转接逻辑要提前想好触发条件，宁可多转也不要硬撑
- 系统提示词里明确禁止"凭空编造"，是防止模型发挥的关键
- 上线前重点测"说错了有损失"的问题，比如退货政策、价格
