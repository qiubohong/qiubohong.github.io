> **📖 原文来源**：[How the agent loop works - Claude Code Docs](https://code.claude.com/docs/en/agent-sdk/agent-loop)

了解消息生命周期、工具执行、上下文窗口以及驱动 SDK Agent 运行的架构。

Agent SDK 让你可以在自己的应用中嵌入 Claude Code 的自主 Agent 循环。SDK 是一个独立的包，让你能以编程方式控制工具、权限、费用限制和输出。使用它不需要安装 Claude Code CLI。

当你启动一个 Agent 时，SDK 会运行与 Claude Code 相同的[执行循环](https://code.claude.com/docs/en/how-claude-code-works#the-agentic-loop)：Claude 评估你的提示词，调用工具执行操作，接收结果，然后重复这个过程，直到任务完成。本文将解释这个循环内部发生了什么，帮助你更有效地构建、调试和优化 Agent。

## 循环概览

每个 Agent 会话都遵循相同的周期：

![Agent 循环示意图：你的提示词进入 Agent 循环，Claude 评估后要么请求工具调用（结果反馈回下一次评估），要么返回最终答案](https://mintcdn.com/claude-code/ikqp3_70mqIahteV/images/agent-loop-diagram.svg?w=2500&fit=max&auto=format&n=ikqp3_70mqIahteV&q=85&s=5af064f8e493e45105e1e9ef73d3400b)

**1. 接收提示词。** Claude 接收你的提示词，以及系统提示词、工具定义和对话历史。SDK 会产出一条 `SystemMessage`，其 subtype 为 `"init"`，包含会话元数据。

**2. 评估并响应。** Claude 评估当前状态并决定如何继续。它可能以文本回应、请求一个或多个工具调用，或者两者兼有。SDK 会产出一条 `AssistantMessage`，包含文本内容和工具调用请求。

**3. 执行工具。** SDK 运行每个被请求的工具并收集结果。每组工具结果都会反馈给 Claude 用于下一次决策。你可以使用 [hooks](https://code.claude.com/docs/en/agent-sdk/hooks) 在工具运行前拦截、修改或阻止工具调用。

**4. 重复。** 步骤 2 和 3 循环执行。每个完整的循环称为一个 **Turn（轮次）**。Claude 持续调用工具并处理结果，直到产出一个不包含工具调用的响应。

**5. 返回结果。** SDK 产出最终的 `AssistantMessage`（纯文本响应，无工具调用），随后产出一条 `ResultMessage`，包含最终文本、token 用量、费用和会话 ID。

一个简单的问题（"这里有哪些文件？"）可能只需要一两个轮次来调用 `Glob` 并返回结果。复杂的任务（"重构 auth 模块并更新测试"）则可能跨越多个轮次，链式调用数十个工具——读取文件、编辑代码、运行测试——Claude 会根据每次结果调整自己的方案。

## 轮次与消息

**轮次**是循环内的一次往返：Claude 产出包含工具调用的输出，SDK 执行这些工具，结果自动反馈给 Claude。这个过程不会将控制权交还给你的代码。轮次持续进行，直到 Claude 产出不包含工具调用的输出，此时循环结束并交付最终结果。

以提示词"修复 auth.ts 中的测试失败"为例，看看一个完整的会话是什么样的。

首先，SDK 将你的提示词发送给 Claude，并产出一条包含会话元数据的 `SystemMessage`。然后循环开始：

- **轮次 1**：Claude 调用 `Bash` 运行 `npm test`。SDK 产出一条包含工具调用的 `AssistantMessage`，执行命令，然后产出一条包含输出结果（三个失败）的 `UserMessage`。
- **轮次 2**：Claude 调用 `Read` 读取 `auth.ts` 和 `auth.test.ts`。SDK 返回文件内容并产出一条 `AssistantMessage`。
- **轮次 3**：Claude 调用 `Edit` 修复 `auth.ts`，然后调用 `Bash` 重新运行 `npm test`。三个测试全部通过。SDK 产出一条 `AssistantMessage`。
- **最终轮次**：Claude 产出纯文本响应，不含工具调用："已修复 auth bug，三个测试现在全部通过。"SDK 产出包含此文本的最终 `AssistantMessage`，然后产出一条包含相同文本以及费用和用量的 `ResultMessage`。

这共有四个轮次：三个包含工具调用，一个最终的纯文本响应。

你可以用 `max_turns` / `maxTurns` 来限制循环次数，它只计算工具使用轮次。例如，上面的循环中设置 `max_turns=2` 会在编辑步骤之前停止。你也可以用 `max_budget_usd` / `maxBudgetUsd` 根据花费阈值来限制轮次。

不设限制时，循环会一直运行到 Claude 自行完成，这对范围明确的任务没问题，但对开放性提示词（"改进这个代码库"）可能会运行很久。为生产环境的 Agent 设置预算是个好的默认做法。

## 消息类型

循环运行时，SDK 会产出一系列消息流。每条消息都有一个 `type` 字段，告诉你它来自循环的哪个阶段。五种核心类型如下：

**`SystemMessage`**：会话生命周期事件。`subtype` 字段用于区分：`"init"` 是第一条消息（会话元数据），`"compact_boundary"` 在[压缩](#自动压缩)后触发。在 TypeScript 中，compact boundary 是独立的 `SDKCompactBoundaryMessage` 类型，而不是 `SDKSystemMessage` 的 subtype。

**`AssistantMessage`**：在每次 Claude 响应后产出，包括最终的纯文本响应。包含该轮次的文本内容块和工具调用块。

**`UserMessage`**：在每次工具执行后产出，包含发回给 Claude 的工具结果内容。也会在你向循环中流式传入用户输入时产出。

**`StreamEvent`**：仅在启用部分消息时产出。包含原始 API 流式事件（文本增量、工具输入块）。详见[流式响应](https://code.claude.com/docs/en/agent-sdk/streaming-output)。

**`ResultMessage`**：标志 Agent 循环结束。包含最终文本结果、token 用量、费用和会话 ID。检查 `subtype` 字段来判断任务是否成功或触发了限制。`ResultMessage` 之后可能还会有少量尾随系统事件（如 `prompt_suggestion`），所以要迭代流直到完成，而不是在收到结果后就中断。详见[处理结果](#处理结果)。

这五种类型覆盖了两个 SDK 中 Agent 循环的完整生命周期。TypeScript SDK 还会产出额外的可观测性事件（hook 事件、工具进度、速率限制、任务通知），提供额外细节，但不是驱动循环所必需的。

## 处理消息

你需要处理哪些消息取决于你在构建什么：

- **只需最终结果**：处理 `ResultMessage` 来获取输出、费用，以及任务是否成功或触发了限制。
- **进度更新**：处理 `AssistantMessage` 来查看 Claude 每个轮次在做什么，包括它调用了哪些工具。
- **实时流式传输**：启用部分消息（Python 中的 `include_partial_messages`，TypeScript 中的 `includePartialMessages`）来实时获取 `StreamEvent` 消息。详见[实时流式响应](https://code.claude.com/docs/en/agent-sdk/streaming-output)。

检查消息类型的方式取决于使用的 SDK：

- **Python**：用 `isinstance()` 检查消息类型，类从 `claude_agent_sdk` 导入（例如 `isinstance(message, ResultMessage)`）。
- **TypeScript**：检查 `type` 字符串字段（例如 `message.type === "result"`）。`AssistantMessage` 和 `UserMessage` 将原始 API 消息包装在 `.message` 字段中，所以内容块在 `message.message.content`，而不是 `message.content`。

## 工具执行

工具赋予 Agent 采取行动的能力。没有工具，Claude 只能用文本回应。有了工具，Claude 可以读取文件、运行命令、搜索代码，以及与外部服务交互。

### 内置工具

SDK 包含与 Claude Code 相同的工具：

| 类别 | 工具 | 功能 |
|------|------|------|
| 文件操作 | `Read`、`Edit`、`Write` | 读取、修改和创建文件 |
| 搜索 | `Glob`、`Grep` | 按模式查找文件，用正则表达式搜索内容 |
| 执行 | `Bash` | 运行 shell 命令、脚本、git 操作 |
| 网络 | `WebSearch`、`WebFetch` | 搜索网页，抓取并解析页面 |
| 发现 | `ToolSearch` | 按需动态查找和加载工具，而不是预加载所有工具 |
| 编排 | `Agent`、`Skill`、`AskUserQuestion`、`TaskCreate`、`TaskUpdate` | 启动子 Agent、调用技能、询问用户、追踪任务 |

除内置工具外，你还可以：
- 通过 [MCP 服务器](https://code.claude.com/docs/en/agent-sdk/mcp)连接外部服务（数据库、浏览器、API）
- 用[自定义工具处理器](https://code.claude.com/docs/en/agent-sdk/custom-tools)定义自定义工具
- 通过[设置源](https://code.claude.com/docs/en/agent-sdk/claude-code-features)加载项目技能，用于可复用的工作流

### 工具权限

Claude 根据任务决定调用哪些工具，但你控制这些调用是否被允许执行。你可以自动批准特定工具、完全阻止其他工具，或要求对所有工具进行审批。三个选项共同决定什么可以运行：

- **`allowed_tools` / `allowedTools`**：自动批准列表中的工具。一个只读 Agent 将 `["Read", "Glob", "Grep"]` 加入允许工具列表后，这些工具无需提示即可运行。未列出的工具仍然可用，但需要权限。
- **`disallowed_tools` / `disallowedTools`**：阻止列表中的工具，无论其他设置如何。
- **`permission_mode` / `permissionMode`**：控制不在允许或拒绝规则中的工具的处理方式。

你还可以用 `"Bash(npm *)"` 这样的规则来限定单个工具，只允许特定命令。

当工具被拒绝时，Claude 会收到一条拒绝消息作为工具结果，通常会尝试不同的方法或报告无法继续。

### 并行工具执行

当 Claude 在单个轮次中请求多个工具调用时，两个 SDK 都可以根据工具类型并发或顺序运行它们。只读工具（如 `Read`、`Glob`、`Grep` 以及标记为只读的 MCP 工具）可以并发运行。修改状态的工具（如 `Edit`、`Write` 和 `Bash`）则顺序运行以避免冲突。

自定义工具默认顺序执行。要为自定义工具启用并行执行，在其注解中设置 `readOnlyHint`。

## 控制循环运行方式

你可以限制循环的轮次数、费用、Claude 的推理深度，以及工具在运行前是否需要审批。这些都是 `ClaudeAgentOptions`（Python）/ `Options`（TypeScript）上的字段。

### 轮次与预算

| 选项 | 控制内容 | 默认值 |
|------|----------|--------|
| `max_turns` / `maxTurns` | 最大工具使用往返次数 | 无限制 |
| `max_budget_usd` / `maxBudgetUsd` | 停止前的最大费用 | 无限制 |

当任一限制触发时，SDK 返回一条带有对应错误 subtype 的 `ResultMessage`（`error_max_turns` 或 `error_max_budget_usd`）。

### 推理深度（Effort Level）

`effort` 选项控制 Claude 应用多少推理。较低的推理深度每轮使用更少的 token，降低费用。并非所有模型都支持 effort 参数。

| 级别 | 行为 | 适用场景 |
|------|------|----------|
| `"low"` | 最少推理，快速响应 | 文件查找、列出目录 |
| `"medium"` | 均衡推理 | 常规编辑、标准任务 |
| `"high"` | 深入分析 | 重构、调试 |
| `"xhigh"` | 扩展推理深度 | 编码和 Agent 任务；推荐用于 Fable 5 和 Opus 4.7+ |
| `"max"` | 最大推理深度 | 需要深度分析的多步骤问题 |

> **注意**：`effort` 用延迟和 token 费用换取每次响应内的推理深度。[扩展思考](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)是一个独立功能，会在输出中产生可见的思维链块。两者相互独立：你可以在启用扩展思考的同时设置 `effort: "low"`，也可以在不启用扩展思考的情况下设置 `effort: "max"`。

### 权限模式

`permission_mode`（Python）/ `permissionMode`（TypeScript）控制 Agent 在使用工具前是否请求审批：

| 模式 | 行为 |
|------|------|
| `"default"` | 不在允许规则中的工具会触发你的审批回调；没有回调则拒绝 |
| `"acceptEdits"` | 自动批准文件编辑和常见文件系统命令（`mkdir`、`touch`、`mv`、`cp` 等）；其他 Bash 命令遵循默认规则 |
| `"plan"` | Claude 可以探索和规划，但不编辑源文件；文件编辑永远不会自动批准，会通过你的 `canUseTool` 回调提示 |
| `"dontAsk"` | 永不提示。通过权限规则预批准的工具可以运行，其他一切都被拒绝 |
| `"auto"`（仅 TypeScript）| 使用模型分类器来批准或拒绝每个工具调用 |
| `"bypassPermissions"` | 运行所有允许的工具而不询问，除非有明确的 ask 规则匹配；不能在 Unix 上以 root 运行。仅在 Agent 的操作不会影响你关心的系统的隔离环境中使用 |

## 上下文窗口

上下文窗口是 Claude 在会话期间可用的信息总量。它不会在会话内的轮次之间重置。所有内容都会累积：系统提示词、工具定义、对话历史、工具输入和工具输出。在轮次间保持不变的内容（系统提示词、工具定义、CLAUDE.md）会自动进行[提示词缓存](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)，降低重复前缀的费用和延迟。

### 什么会消耗上下文

| 来源 | 加载时机 | 影响 |
|------|----------|------|
| 系统提示词 | 每次请求 | 小的固定费用，始终存在 |
| CLAUDE.md 文件 | 会话开始，通过 `settingSources` | 每次请求都包含完整内容（但经过提示词缓存，只有第一次请求支付全额费用） |
| 工具定义 | 每次请求；MCP 模式默认延迟加载 | 内置工具模式每次请求都加载。工具搜索默认延迟加载 MCP 工具模式 |
| 对话历史 | 随轮次累积 | 随每个轮次增长：提示词、响应、工具输入、工具输出 |
| 技能描述 | 会话开始，通过设置源 | 简短摘要；完整内容仅在调用时加载 |

大型工具输出会消耗大量上下文。读取一个大文件或运行输出冗长的命令，单个轮次就可能使用数千个 token。上下文在轮次间累积，所以包含大量工具调用的长会话比短会话积累的上下文要多得多。

### 自动压缩

当上下文窗口接近限制时，SDK 会自动压缩对话：它将较旧的历史总结以释放空间，同时保留最近的交流和关键决策。发生这种情况时，SDK 会在流中产出一条 `type: "system"`、`subtype: "compact_boundary"` 的消息（Python 中是 `SystemMessage`；TypeScript 中是独立的 `SDKCompactBoundaryMessage` 类型）。

压缩会用摘要替换较旧的消息，所以对话早期的具体指令可能不会被保留。持久性规则应放在 CLAUDE.md 中（通过 `settingSources` 加载），而不是放在初始提示词中，因为 CLAUDE.md 内容会在每次请求时重新注入。

你可以通过以下几种方式自定义压缩行为：

- **CLAUDE.md 中的摘要指令**：压缩器会像读取其他上下文一样读取你的 CLAUDE.md，所以你可以在其中加入一个章节，告诉它在摘要时要保留什么。章节标题是自由格式的（不是魔法字符串）；压缩器根据意图进行匹配。
- **`PreCompact` hook**：在压缩发生前运行自定义逻辑，例如归档完整的对话记录。hook 接收一个 `trigger` 字段（`manual` 或 `auto`）。
- **手动压缩**：将 `/compact` 作为提示词字符串发送，按需触发压缩。以这种方式发送的命令是 SDK 输入，不是仅限 CLI 的快捷方式。

### 保持上下文高效

针对长时间运行的 Agent 的几个策略：

**使用子 Agent 处理子任务。** 每个子 Agent 以全新的对话开始（没有之前的消息历史，但会加载自己的系统提示词和项目级上下文，如 CLAUDE.md）。它看不到父 Agent 的轮次，只有其最终响应作为工具结果返回给父 Agent。主 Agent 的上下文增长的是那个摘要，而不是完整的子任务记录。

**有选择地使用工具。** 每个工具定义都占用上下文空间。使用 `AgentDefinition` 上的 `tools` 字段将子 Agent 限定在它们所需的最小工具集。

**注意 MCP 服务器的费用。** MCP 工具搜索默认延迟加载 MCP 工具模式。当工具搜索关闭时，每个 MCP 服务器会将其所有工具模式添加到每次请求中，所以几个拥有大量工具的服务器在 Agent 开始工作之前就可能消耗大量上下文。

**对常规任务使用较低的推理深度。** 对只需要读取文件或列出目录的 Agent，将 `effort` 设置为 `"low"`，以减少 token 用量和费用。

## 会话与连续性

每次与 SDK 的交互都会创建或继续一个会话。从 `ResultMessage.session_id`（两个 SDK 均可用）捕获会话 ID，以便稍后恢复。TypeScript SDK 还将其作为 init `SystemMessage` 上的直接字段暴露；在 Python 中它嵌套在 `SystemMessage.data` 中。

恢复时，之前轮次的完整上下文会被还原：读取过的文件、执行过的分析，以及采取过的操作。你还可以 fork 一个会话，在不修改原始会话的情况下探索不同的方案。

> **注意**：在 Python 中，`ClaudeSDKClient` 会自动跨多次调用处理会话 ID。

## 处理结果

循环结束时，`ResultMessage` 会告诉你发生了什么并给出输出。`subtype` 字段（两个 SDK 均可用）是检查终止状态的主要方式。

| 结果 subtype | 发生了什么 | `result` 字段是否可用？ |
|-------------|-----------|----------------------|
| `success` | Claude 正常完成了任务 | 是 |
| `error_max_turns` | 在完成前触发了 `maxTurns` 限制 | 否 |
| `error_max_budget_usd` | 在完成前触发了 `maxBudgetUsd` 限制 | 否 |
| `error_during_execution` | 错误中断了循环（例如 API 失败或请求被取消） | 否 |
| `error_max_structured_output_retries` | 在配置的重试限制内未产出有效的结构化输出 | 否 |

`result` 字段（最终文本输出）只在 `success` 变体中存在，所以在读取它之前务必检查 subtype。所有结果 subtype 都携带 `total_cost_usd`、`usage`、`num_turns` 和 `session_id`，这样即使在出错后你也可以追踪费用并恢复。

结果还包含一个 `stop_reason` 字段，指示模型在最终轮次停止生成的原因。常见值有 `end_turn`（模型正常完成）、`max_tokens`（触发输出 token 限制）和 `refusal`（模型拒绝了请求）。

## Hooks

[Hooks](https://code.claude.com/docs/en/agent-sdk/hooks) 是在循环特定节点触发的回调：工具运行前、工具返回后、Agent 完成时等等。一些常用的 hook：

| Hook | 触发时机 | 常见用途 |
|------|----------|----------|
| `PreToolUse` | 工具执行前 | 验证输入，阻止危险命令 |
| `PostToolUse` | 工具返回后 | 审计输出，触发副作用 |
| `UserPromptSubmit` | 发送提示词时 | 向提示词注入额外上下文 |
| `Stop` | Agent 完成时 | 验证结果，保存会话状态 |
| `SubagentStart` / `SubagentStop` | 子 Agent 启动或完成时 | 追踪和聚合并行任务结果 |
| `PreCompact` | 上下文压缩前 | 在摘要前归档完整记录 |

Hook 在你的应用进程中运行，不在 Agent 的上下文窗口内，所以它们不消耗上下文。Hook 还可以短路循环：拒绝工具调用的 `PreToolUse` hook 会阻止其执行，Claude 会收到拒绝消息。

## 综合示例

以下示例将本文的关键概念整合到一个修复测试失败的 Agent 中。它配置了允许的工具（自动批准，让 Agent 自主运行）、项目设置，以及轮次和推理深度的安全限制。循环运行时，它捕获会话 ID 以便潜在的恢复，处理最终结果，并打印总费用。

```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage


async def run_agent():
    session_id = None

    async for message in query(
        prompt="找到并修复 auth 模块中导致测试失败的 bug",
        options=ClaudeAgentOptions(
            allowed_tools=[
                "Read",
                "Edit",
                "Bash",
                "Glob",
                "Grep",
            ],  # 在此列出工具会自动批准它们（无需提示）
            setting_sources=[
                "project"
            ],  # 从当前目录加载 CLAUDE.md、技能、hooks
            max_turns=30,  # 防止会话失控
            effort="high",  # 复杂调试需要深入推理
        ),
    ):
        # 处理最终结果
        if isinstance(message, ResultMessage):
            session_id = message.session_id  # 保存以便潜在的恢复

            if message.subtype == "success":
                print(f"完成：{message.result}")
            elif message.subtype == "error_max_turns":
                # Agent 用完了轮次。用更高的限制恢复。
                print(f"触发轮次限制。恢复会话 {session_id} 以继续。")
            elif message.subtype == "error_max_budget_usd":
                print("触发预算限制。")
            else:
                print(f"已停止：{message.subtype}")

            if message.total_cost_usd is not None:
                print(f"费用：${message.total_cost_usd:.4f}")


asyncio.run(run_agent())
```

## 下一步

了解了循环之后，根据你在构建的内容，可以继续：

- **还没运行过 Agent？** 从[快速入门](https://code.claude.com/docs/en/agent-sdk/quickstart)开始，安装 SDK 并看到完整示例端到端运行。
- **准备好接入你的项目？** [加载 CLAUDE.md、技能和文件系统 hooks](https://code.claude.com/docs/en/agent-sdk/claude-code-features)，让 Agent 自动遵循你的项目约定。
- **构建交互式 UI？** 启用[流式传输](https://code.claude.com/docs/en/agent-sdk/streaming-output)，在循环运行时实时显示文本和工具调用。

- **运行长时间或昂贵的任务？** 将隔离的工作卸载给[子 Agent](https://code.claude.com/docs/en/agent-sdk/subagents)，保持主上下文精简。
