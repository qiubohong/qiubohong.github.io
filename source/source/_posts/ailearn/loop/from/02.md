# Agent Loop 🚀 —— AI 驱动的软件开发

Agent Loop 是一个 AI 驱动的软件开发框架。它使用一组由编排者（Orchestrator）管理的专家 AI Agent 团队，处理从规划、架构到编码、测试和部署的各类任务。你通过简单的命令来引导整个流程。

<!-- more -->

---

## 核心概念

该框架建立在三个关键组件之上：

**Orchestrator（编排者）**：项目经理 AI。你给它一个高层目标，它将其拆解，并将任务委派给合适的专家。

**Specialist Agents（专家 Agent）**：具有特定角色的 AI（如 *Architect*、*Builder*、*Tester*）。它们执行编排者分配的任务，遵循严格的规范。

**Commands（命令）**：你与系统交互的接口。你使用 `/plan`、`/build`、`/test` 等命令来启动工作流。

### 工作流程

典型的工作流是一条清晰的委派链：

1. **你**：发出命令（例如 `/build "一个登录 API 端点"`）
2. **Orchestrator**：接收命令，制定详细计划，并选择合适的 Agent（例如 *Builder* Agent）
3. **Specialist Agent**：执行任务，遵循 TDD 等最佳实践，并遵守项目约定
4. **Result**：Agent 交付完成的工作（如新代码和通过的测试），供你审查

---

## 可用的专家 Agent

每个 Agent 都是软件工程特定领域的专家。

| Agent | 角色 |
|-------|------|
| **Architect（架构师）** | 设计系统架构，做出高层技术决策 |
| **Builder（开发者）** | 以测试驱动开发（TDD）和整洁代码为重点实现功能 |
| **Code（编码专家）** | 处理高度复杂的编码任务、算法和性能优化 |
| **Debugger（调试员）** | 调查并解决 bug 和技术问题 |
| **Orchestrator（编排者）** | 管理整体工作流，将任务委派给其他 Agent |
| **Planner（规划者）** | 将想法转化为详细规格、用户故事和验收标准 |
| **Researcher（研究员）** | 收集信息，比较技术方案，提供带引用的报告 |
| **Reviewer（审查员）** | 进行代码审查，确保质量、安全性和规范遵从 |
| **Scope Analyst（范围分析师）** | 分析问题，确定工作范围和受影响的代码库区域 |
| **Security Analyst（安全分析师）** | 识别并缓解安全漏洞 |
| **Tester（测试员）** | 创建并运行测试，确保软件质量 |

## 常用命令速查

以下是驱动项目的常用命令速查表。

### 规划与设计

**`/plan "<功能>"`**：创建一个详细的、感知文件的实现计划。
示例：`/plan "实现魔法链接认证"`

**`/spec "<功能>"`**：生成包含用户故事和验收标准的正式功能规格。
示例：`/spec "带头像上传的用户个人资料页"`

**`/propose-solutions "<问题>"`**：比较多个技术方案的优缺点。
示例：`/propose-solutions "选择数据库：SQL vs. NoSQL"`

### 开发与实现

**`/build "<功能>"`**：遵循 TDD，构建包含代码和测试的功能。
示例：`/build "一个获取用户资料的 API 端点"`

**`/tdd "<功能>"`**：严格遵循红-绿-重构 TDD 循环实现功能。
示例：`/tdd "带双因素认证的用户登录函数"`

**`/fix "<bug>"`**：针对特定 bug 实施专项修复。
示例：`/fix "登录按钮在移动端无响应"`

**`/refactor <文件或代码>`**：在不改变行为的前提下改善现有代码结构。
示例：`/refactor src/utils/helpers.js`

### 质量与验证

**`/test "<组件>"`**：为组件生成完整的测试套件（单元测试、集成测试）。
示例：`/test "用户认证服务"`

**`/analyze [路径]`**：分析代码的质量、安全性和架构问题。
示例：`/analyze src/core/auth.js`

**`/review <PR URL 或路径>`**：进行全面的代码审查。
示例：`/review https://github.com/org/repo/pull/123`

### 项目管理

**`/commit`**：为你的暂存更改生成符合 Conventional Commit 规范的提交信息。

**`/update-project-docs`**：扫描代码库并将所有文档更新到最新状态。

**`/research "<主题>"`**：进行研究并提供结构化报告。
示例：`/research "2024 年 API 安全最佳实践"`

## 核心原则（Agent 的思维方式）

Agent 的行为由 `CLAUDE.md` 中定义的一套核心原则所约束。

**委派，而非亲力亲为（Delegate, Don't Do）**：*Orchestrator* 始终将任务委派给专家，它自己从不写代码。

**先思考，再行动（Think, Then Act）**：Agent 在执行前使用结构化的思考过程（`think` → `think harder` → `ultrathink`）来规划工作。

**上下文为王（Context is King）**：Agent 在编写或修改代码之前，**必须**在项目中搜索已有的模式、约定和文档。这确保所有变更都符合项目风格。

**测试优先（Tests First）**：开发由测试驱动（TDD）。在实现代码之前，始终先写一个失败的测试。

**引用来源（Cite Your Sources）**：*Researcher* Agent 为其发现提供引用，确保信息可验证。

## 端到端工作流示例

以下是如何使用 Agent Loop 从零开始构建一个新功能：

```bash
# 1. 将想法转化为具体计划
/plan "
每周向用户发送碳排放报告邮件
"

# 2. 生成正式规格，包含用户故事和验收标准
/spec "
按照计划实现邮件报告生成器
"

# 3. 使用测试驱动开发构建功能
/build "
实现邮件报告批处理任务
"

# 4. 确保新模块的完整测试覆盖
/test "
src/jobs/report_batch.py
"

# 5. 分析新代码的质量或安全问题
/analyze src/jobs/report_batch.py

# 6. 更新项目 README 以包含新功能
/update-project-docs
```
