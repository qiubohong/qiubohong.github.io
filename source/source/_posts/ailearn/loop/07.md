Agent 跑起来了。

你盯着终端，看到一堆输出滚过去，然后它停了。

成功了？失败了？跑了多少钱？它到底干了什么？

如果你只能靠 `print` 调试，那这个 Agent 离生产还差得远。

这篇补上前六篇没讲清楚的东西——**可观测性**。不是那种"加个日志"的可观测性，而是真正理解 Agent 内部发生了什么的能力。

## 先搞清楚：Agent 会产出什么

前几篇讲 Agent Loop 的时候，我们一直把它当黑盒——输入一个任务，等它输出结果。

但 Agent 跑的时候，SDK 其实在持续产出一条消息流。每条消息都有类型，告诉你它来自循环的哪个阶段。

> 💡 **来源**：[How the agent loop works - Claude Code Agent SDK](https://code.claude.com/docs/en/agent-sdk/agent-loop) — SDK 在循环运行时产出五种核心消息类型，覆盖 Agent 循环的完整生命周期

五种核心消息类型：

```
SystemMessage     → 会话生命周期事件（初始化、压缩边界）
AssistantMessage  → Claude 每次响应（含工具调用请求）
UserMessage       → 工具执行结果（反馈给 Claude 的内容）
StreamEvent       → 实时流式事件（启用流式传输时才有）
ResultMessage     → 循环结束标志（最终结果 + 费用 + 状态）
```

大部分人只处理最后一条——`ResultMessage`。这没问题，但你因此错过了很多信息。

来看一个完整的消息流长什么样：

```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions
from claude_agent_sdk import SystemMessage, AssistantMessage, UserMessage, ResultMessage

async def run_with_observability(task: str):
    print(f"\n{'='*50}")
    print(f"任务：{task}")
    print(f"{'='*50}\n")

    turn_count = 0

    async for message in query(
        prompt=task,
        options=ClaudeAgentOptions(
            allowed_tools=["Read", "Glob", "Grep", "Bash"],
            max_turns=20,
        ),
    ):
        # 会话初始化
        if isinstance(message, SystemMessage):
            if message.subtype == "init":
                print(f"[会话开始] session_id: {message.data.get('session_id', 'N/A')}")
            elif message.subtype == "compact_boundary":
                print(f"[上下文压缩] 对话历史已压缩，释放 Token 空间")

        # Claude 的每次响应
        elif isinstance(message, AssistantMessage):
            turn_count += 1
            # 提取文本内容
            text_parts = [
                block.text for block in message.message.content
                if hasattr(block, 'text')
            ]
            # 提取工具调用
            tool_calls = [
                block for block in message.message.content
                if block.type == "tool_use"
            ]

            if text_parts:
                print(f"[轮次 {turn_count}] Claude 说：{' '.join(text_parts)[:100]}...")
            if tool_calls:
                for call in tool_calls:
                    print(f"[轮次 {turn_count}] 调用工具：{call.name}")

        # 工具执行结果
        elif isinstance(message, UserMessage):
            tool_results = [
                block for block in message.message.content
                if hasattr(block, 'type') and block.type == "tool_result"
            ]
            for result in tool_results:
                # 只打印结果的前 100 个字符，避免刷屏
                content_preview = str(result.content)[:100]
                print(f"[工具结果] {content_preview}...")

        # 最终结果
        elif isinstance(message, ResultMessage):
            print(f"\n{'='*50}")
            print(f"[循环结束]")
            print(f"  状态：{message.subtype}")
            print(f"  轮次：{message.num_turns}")
            print(f"  费用：${message.total_cost_usd:.4f}")
            if message.subtype == "success":
                print(f"  结果：{message.result[:200]}...")
            print(f"{'='*50}\n")

asyncio.run(run_with_observability("列出当前目录下所有 Python 文件"))
```

这段代码跑起来，你就能看到 Agent 每一步在干什么——调了哪些工具、工具返回了什么、最后花了多少钱。

## ResultMessage：读懂它，你才知道 Agent 为什么停了

`ResultMessage` 是最重要的消息，但大部分人只看 `result` 字段，忽略了 `subtype`。

这是个坑。

`result` 字段只在任务**成功完成**时才有值。如果 Agent 是因为触发了限制或者出错而停的，`result` 是空的——你拿到一个空字符串，还以为任务完成了。

> 💡 **来源**：[How the agent loop works - Claude Code Agent SDK](https://code.claude.com/docs/en/agent-sdk/agent-loop) — `result` 字段只在 `success` 变体中存在，所以在读取它之前务必检查 subtype

`subtype` 有五种值：

| subtype | 发生了什么 | `result` 是否有值 |
|---------|-----------|-----------------|
| `success` | Claude 正常完成了任务 | ✅ 有 |
| `error_max_turns` | 触发了最大轮次限制 | ❌ 没有 |
| `error_max_budget_usd` | 触发了预算上限 | ❌ 没有 |
| `error_during_execution` | 执行中出错（API 失败、请求被取消） | ❌ 没有 |
| `error_max_structured_output_retries` | 结构化输出重试次数超限 | ❌ 没有 |

正确的处理方式：

```python
elif isinstance(message, ResultMessage):
    if message.subtype == "success":
        # 任务正常完成，可以安全读取 result
        process_result(message.result)

    elif message.subtype == "error_max_turns":
        # Agent 用完了轮次，任务没完成
        # 可以用 session_id 恢复，继续跑
        print(f"轮次用完，任务未完成。session_id: {message.session_id}")
        resume_session(message.session_id)

    elif message.subtype == "error_max_budget_usd":
        # 超预算了
        print(f"预算超限，已花费 ${message.total_cost_usd:.4f}")

    elif message.subtype == "error_during_execution":
        # 执行中出错，需要排查
        print(f"执行出错，session_id: {message.session_id}")
        # 记录日志，通知运维

    # 无论什么情况，这些字段都有值
    print(f"总费用：${message.total_cost_usd:.4f}")
    print(f"总轮次：{message.num_turns}")
```

还有一个容易忽视的字段——`stop_reason`。

`stop_reason` 告诉你模型在**最终轮次**停止生成的原因：

- `end_turn`：模型正常完成，主动停止
- `max_tokens`：触发了输出 Token 上限，被强制截断
- `refusal`：模型拒绝了请求（内容安全策略触发）

`stop_reason` 和 `subtype` 是两个不同维度的信息。`subtype` 说的是"循环为什么结束"，`stop_reason` 说的是"最后一次生成为什么停"。

遇到 `stop_reason == "max_tokens"` 的时候要特别注意——模型的最后一次输出被截断了，它可能没说完。这时候 `subtype` 可能还是 `success`（因为循环正常结束了），但实际上输出是不完整的。

```python
elif isinstance(message, ResultMessage):
    if message.subtype == "success":
        if message.stop_reason == "max_tokens":
            # 输出被截断，结果可能不完整
            print("⚠️ 警告：输出被截断，结果可能不完整")
            print(f"  建议：增大 max_tokens 或拆分任务")
        process_result(message.result)
```

## effort 参数：用推理深度换成本

这是原始文档里有、但前六篇完全没提到的一个参数。

`effort` 控制 Claude 在每次响应时投入多少推理。推理越深，质量越高，但 Token 消耗也越多、延迟越大。

> 💡 **来源**：[How the agent loop works - Claude Code Agent SDK](https://code.claude.com/docs/en/agent-sdk/agent-loop) — `effort` 用延迟和 token 费用换取每次响应内的推理深度，并非所有模型都支持

五个级别：

| 级别 | 行为 | 适用场景 |
|------|------|----------|
| `"low"` | 最少推理，快速响应 | 文件查找、列出目录、简单查询 |
| `"medium"` | 均衡推理 | 常规编辑、标准任务 |
| `"high"` | 深入分析 | 重构、调试、复杂逻辑 |
| `"xhigh"` | 扩展推理深度 | 复杂编码和 Agent 任务 |
| `"max"` | 最大推理深度 | 需要深度分析的多步骤问题 |

实际工程里，这个参数能省不少钱。

举个例子：一个代码审查系统，它需要做两件事——先用 `Glob` 找到所有 Python 文件，再逐个分析代码质量。

找文件这一步，根本不需要深度推理。`effort: "low"` 就够了，速度快、成本低。分析代码质量这一步，才需要 `effort: "high"` 或 `"xhigh"`。

```python
# 第一步：找文件，不需要深度推理
async for message in query(
    prompt="列出所有 Python 文件",
    options=ClaudeAgentOptions(
        allowed_tools=["Glob"],
        effort="low",   # 简单任务，低推理深度
        max_turns=3,
    ),
):
    if isinstance(message, ResultMessage) and message.subtype == "success":
        file_list = message.result

# 第二步：分析代码，需要深度推理
async for message in query(
    prompt=f"分析以下文件的代码质量，找出潜在问题：\n{file_list}",
    options=ClaudeAgentOptions(
        allowed_tools=["Read"],
        effort="high",  # 复杂分析，高推理深度
        max_turns=20,
    ),
):
    if isinstance(message, ResultMessage) and message.subtype == "success":
        analysis = message.result
```

这个拆分方式，第一步的成本可以降到原来的 1/3 到 1/5。任务量大的时候，这个差距很明显。

有一点要注意：`effort` 和扩展思考（Extended Thinking）是两个独立的功能。`effort` 控制的是推理深度，扩展思考控制的是是否在输出中显示思维链。两者可以独立设置，互不影响。

## CLAUDE.md：比系统提示词更可靠的持久性规则

这是前六篇里最大的一个遗漏，也是实际工程中最容易踩的坑。

**问题**：你在系统提示词里写了"这个项目用 Python 3.11，不要用 3.10 的语法"。跑了 30 轮之后，Agent 开始用 3.10 的语法写代码。

第04篇讲过，这是上下文压缩导致的——早期的系统提示词被压缩掉了。

但原始文档里有一个解法，前六篇没有提到：

> 💡 **来源**：[How the agent loop works - Claude Code Agent SDK](https://code.claude.com/docs/en/agent-sdk/agent-loop) — 持久性规则应放在 CLAUDE.md 中（通过 `settingSources` 加载），而不是放在初始提示词中，因为 CLAUDE.md 内容会在每次请求时重新注入

**CLAUDE.md 的特殊之处**：它不是一次性注入的，而是**每次请求都重新注入**。

这意味着即使上下文被压缩了，CLAUDE.md 里的内容也不会丢失——下一次请求时，它会重新出现在上下文里。

```
项目结构：
my-project/
├── CLAUDE.md          ← 持久性规则放这里
├── src/
│   └── ...
└── tests/
    └── ...
```

CLAUDE.md 的内容示例：

```markdown
# 项目规范

## 技术栈
- Python 3.11（不要使用 3.10 及以下的语法）
- 使用 pytest 做测试，不要用 unittest
- 类型注解必须完整，不允许 `Any` 类型

## 代码风格
- 函数命名用 snake_case
- 类命名用 PascalCase
- 每个函数必须有 docstring

## 禁止事项
- 不要修改 `config/production.yaml`
- 不要删除任何测试文件
- 不要使用 `os.system()`，改用 `subprocess`

## 压缩摘要指令
在生成摘要时，必须保留：
1. 已完成的文件修改列表
2. 当前任务的进展状态
3. 重要的架构决策
```

注意最后那个"压缩摘要指令"章节——这是一个很有用的技巧。压缩器在生成摘要时会读取 CLAUDE.md，所以你可以在里面告诉它"压缩时必须保留哪些信息"。

加载 CLAUDE.md 的方式：

```python
options=ClaudeAgentOptions(
    setting_sources=["project"],  # 从当前目录加载 CLAUDE.md
    # 或者指定具体路径
    # setting_sources=["/path/to/project"],
)
```

一个判断标准：**什么东西该放 CLAUDE.md，什么该放系统提示词？**

- 跨任务都需要遵守的规则 → CLAUDE.md（项目规范、禁止事项、技术栈约束）
- 只针对当次任务的指令 → 系统提示词（"这次任务的目标是..."、"重点关注..."）

## PreCompact Hook：压缩前把重要信息存下来

第03篇提到了 Hook 的列表，但没有讲 `PreCompact` 的实际用法。

`PreCompact` 在上下文压缩**发生之前**触发。这给了你一个机会——在历史被压缩之前，把重要信息存到外部。

> 💡 **来源**：[How the agent loop works - Claude Code Agent SDK](https://code.claude.com/docs/en/agent-sdk/agent-loop) — `PreCompact` hook 在压缩发生前运行自定义逻辑，例如归档完整的对话记录

```python
import json
import os
from datetime import datetime

def pre_compact_hook(hook_data):
    """
    压缩前触发：把完整的对话历史存到文件
    hook_data 包含：
    - trigger: "manual"（手动触发）或 "auto"（自动触发）
    - messages: 当前完整的消息列表
    - session_id: 当前会话 ID
    """
    trigger = hook_data.get("trigger", "unknown")
    session_id = hook_data.get("session_id", "unknown")
    messages = hook_data.get("messages", [])

    # 创建归档目录
    archive_dir = f".agent_archives/{session_id}"
    os.makedirs(archive_dir, exist_ok=True)

    # 生成归档文件名（带时间戳）
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    archive_file = f"{archive_dir}/compact_{timestamp}_{trigger}.json"

    # 提取关键信息
    key_info = extract_key_info(messages)

    # 保存完整记录
    with open(archive_file, "w", encoding="utf-8") as f:
        json.dump({
            "session_id": session_id,
            "trigger": trigger,
            "timestamp": timestamp,
            "message_count": len(messages),
            "key_info": key_info,
            "full_messages": messages,  # 完整历史
        }, f, ensure_ascii=False, indent=2)

    print(f"[PreCompact] 已归档 {len(messages)} 条消息到 {archive_file}")


def extract_key_info(messages):
    """从消息历史中提取关键信息"""
    modified_files = []
    completed_steps = []
    tool_calls_summary = []

    for msg in messages:
        if hasattr(msg, 'message') and hasattr(msg.message, 'content'):
            for block in msg.message.content:
                # 记录文件修改操作
                if hasattr(block, 'name') and block.name in ["Edit", "Write"]:
                    if hasattr(block, 'input') and 'file_path' in block.input:
                        modified_files.append(block.input['file_path'])
                # 记录工具调用摘要
                if hasattr(block, 'name'):
                    tool_calls_summary.append(block.name)

    return {
        "modified_files": list(set(modified_files)),
        "tool_calls_count": len(tool_calls_summary),
        "tool_calls_summary": tool_calls_summary[-20:],  # 最近 20 次工具调用
    }


# 注册 hook
options = ClaudeAgentOptions(
    hooks={
        "PreCompact": pre_compact_hook,
    }
)
```

`PreCompact` 最实用的场景是**长任务的断点恢复**。

想象一个跑了 40 轮的代码迁移任务，中途触发了自动压缩。压缩之后，"已迁移了哪些文件"这个信息可能被摘要掉了。但如果你在 `PreCompact` 里把这个信息存到文件，压缩之后可以重新注入到系统提示词里。

## 会话 Fork：探索不同方案而不破坏原有进度

这个功能很少有人知道，但在某些场景下非常有用。

> 💡 **来源**：[How the agent loop works - Claude Code Agent SDK](https://code.claude.com/docs/en/agent-sdk/agent-loop) — 你可以 fork 一个会话，在不修改原始会话的情况下探索不同的方案

场景：Agent 跑到第 15 步，你不确定接下来该用方案 A 还是方案 B。你想两个都试试，但不想从头跑。

```python
# 保存当前会话 ID
current_session_id = "sess_abc123"

# Fork 出两个分支，分别探索不同方案
async def explore_option_a():
    async for message in query(
        prompt="用方案 A 继续：重构为微服务架构",
        options=ClaudeAgentOptions(
            resume_session_id=current_session_id,  # 从当前状态继续
            fork=True,  # fork 模式，不修改原始会话
        ),
    ):
        ...

async def explore_option_b():
    async for message in query(
        prompt="用方案 B 继续：保持单体架构，优化性能",
        options=ClaudeAgentOptions(
            resume_session_id=current_session_id,
            fork=True,
        ),
    ):
        ...

# 两个方案并行探索
await asyncio.gather(explore_option_a(), explore_option_b())
```

Fork 之后，两个分支各自独立运行，互不影响。原始会话也不受影响，你随时可以回到第 15 步的状态重新来过。

## 把这些拼在一起：一个生产级的 Agent 框架

前面讲了这么多零散的知识点，来看看怎么把它们组合成一个真正可用于生产的 Agent 框架。

```python
import asyncio
import json
import os
from datetime import datetime
from claude_agent_sdk import query, ClaudeAgentOptions
from claude_agent_sdk import SystemMessage, AssistantMessage, UserMessage, ResultMessage


class ProductionAgent:
    """
    生产级 Agent 框架
    集成：可观测性、成本控制、持久化、错误处理
    """

    def __init__(self, task_id: str, project_dir: str = "."):
        self.task_id = task_id
        self.project_dir = project_dir
        self.session_id = None
        self.turn_count = 0
        self.total_cost = 0.0
        self.log_file = f".agent_logs/{task_id}.jsonl"

        os.makedirs(".agent_logs", exist_ok=True)
        os.makedirs(".agent_archives", exist_ok=True)

    def _log(self, event_type: str, data: dict):
        """结构化日志，每行一个 JSON"""
        entry = {
            "timestamp": datetime.now().isoformat(),
            "task_id": self.task_id,
            "session_id": self.session_id,
            "event": event_type,
            **data,
        }
        with open(self.log_file, "a", encoding="utf-8") as f:
            f.write(json.dumps(entry, ensure_ascii=False) + "\n")

    def _pre_compact_hook(self, hook_data):
        """压缩前归档"""
        archive_path = f".agent_archives/{self.task_id}_{datetime.now().strftime('%H%M%S')}.json"
        with open(archive_path, "w", encoding="utf-8") as f:
            json.dump(hook_data, f, ensure_ascii=False, indent=2)
        self._log("pre_compact", {"archive": archive_path, "trigger": hook_data.get("trigger")})

    async def run(
        self,
        task: str,
        effort: str = "medium",
        max_turns: int = 30,
        max_budget_usd: float = 1.0,
        resume_session_id: str = None,
    ) -> dict:
        """
        运行 Agent，返回结构化结果
        """
        self._log("task_start", {"task": task, "effort": effort, "max_turns": max_turns})

        result = {
            "success": False,
            "output": None,
            "session_id": None,
            "turns": 0,
            "cost_usd": 0.0,
            "stop_reason": None,
            "error": None,
        }

        try:
            async for message in query(
                prompt=task,
                options=ClaudeAgentOptions(
                    allowed_tools=["Read", "Edit", "Write", "Bash", "Glob", "Grep"],
                    setting_sources=["project"],   # 加载 CLAUDE.md
                    effort=effort,
                    max_turns=max_turns,
                    max_budget_usd=max_budget_usd,
                    resume_session_id=resume_session_id,
                    hooks={"PreCompact": self._pre_compact_hook},
                ),
            ):
                if isinstance(message, SystemMessage):
                    if message.subtype == "init":
                        self.session_id = message.data.get("session_id")
                        result["session_id"] = self.session_id
                        self._log("session_init", {"session_id": self.session_id})
                    elif message.subtype == "compact_boundary":
                        self._log("context_compacted", {})

                elif isinstance(message, AssistantMessage):
                    self.turn_count += 1
                    tool_calls = [
                        {"name": b.name, "input_preview": str(b.input)[:100]}
                        for b in message.message.content
                        if hasattr(b, 'type') and b.type == "tool_use"
                    ]
                    if tool_calls:
                        self._log("tool_calls", {"turn": self.turn_count, "tools": tool_calls})

                elif isinstance(message, ResultMessage):
                    result["turns"] = message.num_turns
                    result["cost_usd"] = message.total_cost_usd or 0.0
                    result["stop_reason"] = message.stop_reason
                    self.total_cost += result["cost_usd"]

                    if message.subtype == "success":
                        # 检查输出是否被截断
                        if message.stop_reason == "max_tokens":
                            result["error"] = "输出被截断，结果可能不完整"
                            self._log("warning", {"reason": "output_truncated"})
                        result["success"] = True
                        result["output"] = message.result

                    elif message.subtype == "error_max_turns":
                        result["error"] = f"轮次用完（{max_turns} 轮），任务未完成"
                        self._log("error", {"type": "max_turns", "session_id": self.session_id})

                    elif message.subtype == "error_max_budget_usd":
                        result["error"] = f"预算超限（${max_budget_usd}），已花费 ${result['cost_usd']:.4f}"
                        self._log("error", {"type": "budget_exceeded", "cost": result["cost_usd"]})

                    elif message.subtype == "error_during_execution":
                        result["error"] = "执行中出错"
                        self._log("error", {"type": "execution_error"})

                    self._log("task_end", {
                        "success": result["success"],
                        "turns": result["turns"],
                        "cost_usd": result["cost_usd"],
                        "stop_reason": result["stop_reason"],
                    })

        except Exception as e:
            result["error"] = str(e)
            self._log("exception", {"error": str(e)})

        return result


# 使用示例
async def main():
    agent = ProductionAgent(task_id="refactor_auth_20260805")

    result = await agent.run(
        task="重构 auth 模块，提取公共逻辑，增加单元测试",
        effort="high",       # 重构任务需要深度推理
        max_turns=40,
        max_budget_usd=2.0,
    )

    if result["success"]:
        print(f"✅ 完成，花费 ${result['cost_usd']:.4f}，共 {result['turns']} 轮")
        print(f"结果：{result['output'][:300]}...")
    else:
        print(f"❌ 失败：{result['error']}")
        if result["session_id"]:
            print(f"可以用 session_id={result['session_id']} 恢复任务")


asyncio.run(main())
```

这个框架做了几件事：

1. **结构化日志**：每个事件都记录到 `.jsonl` 文件，方便后续分析
2. **成本追踪**：每次任务结束都记录花了多少钱
3. **PreCompact 归档**：压缩前自动保存完整历史
4. **错误分类**：区分"轮次用完"、"预算超限"、"执行出错"，每种情况有不同的处理策略
5. **截断检测**：发现 `stop_reason == "max_tokens"` 时发出警告

## 一个真实的调试场景

说个具体的例子，把上面的知识点串起来。

让 Agent 做一个代码迁移任务，跑了一段时间之后，发现它在重复做已经做过的事。

**第一步：看日志**

```bash
# 查看最近的工具调用记录
grep '"event": "tool_calls"' .agent_logs/task_001.jsonl | tail -20
```

发现它在第 18 轮和第 32 轮都调用了 `Read` 读取同一个文件。说明上下文压缩之后，它忘了自己读过这个文件。

**第二步：看压缩记录**

```bash
ls .agent_archives/task_001_*.json
# task_001_143022.json  ← 第一次压缩
# task_001_162815.json  ← 第二次压缩
```

打开第一次压缩的归档，看看压缩前的消息历史里有没有"已读取文件列表"。

发现有，但压缩后的摘要里没有保留这个信息。

**第三步：修复**

在 CLAUDE.md 里加一条压缩指令：

```markdown
## 压缩摘要指令
在生成摘要时，必须保留以下信息：
1. 已读取的文件列表（格式：`- 已读取：{文件路径}`）
2. 已修改的文件列表（格式：`- 已修改：{文件路径}`）
3. 当前任务进展（已完成哪些步骤，还剩哪些步骤）
```

重新跑，问题消失了。

这就是可观测性的价值——不是"加个日志"，而是**能看到 Agent 内部发生了什么，然后针对性地修复**。

## 📝 小结

- **消息流**：Agent 跑的时候产出五种消息，`AssistantMessage` 告诉你它在干什么，`ResultMessage` 告诉你为什么停了
- **ResultMessage subtype**：`success` 才有 `result` 字段，其他四种都是错误状态，要分别处理
- **stop_reason**：`max_tokens` 说明输出被截断，结果可能不完整，要特别处理
- **effort 参数**：简单任务用 `"low"`，复杂任务用 `"high"`，按任务类型分级，能省不少钱
- **CLAUDE.md**：持久性规则放这里，不要放系统提示词——因为它每次请求都会重新注入，不会被压缩掉
- **PreCompact Hook**：压缩前归档完整历史，配合 CLAUDE.md 的压缩指令，解决"压缩后失忆"的问题
- **会话 Fork**：探索不同方案时用，不破坏原有进度
