## 一、逐页讲稿

### P1 封面

- **本页是什么**：本讲封面——"Prompt 提示语工程｜让 AI 一次就懂"。

- **开场/衔接话术**（开场白）：
  "前面两讲，我们认识了模型、搭好了本地环境。今天讲整个系列里门槛最低、回报最高的一讲——Prompt 提示语工程。一句话概括它的价值：**同样一个模型，会写 Prompt 的人，产出可能是你的十倍**。"

- **核心讲解**：
  "先纠正一个常见的误解：很多人以为 AI 变强了，就不用管 Prompt 了。恰恰相反，模型越强，Prompt 越重要——因为强大的模型就像一位『上知天文、下知地理的超级专家』，但这位专家有个毛病：**不会读心术**。你不说清楚，它就靠猜。你问得稀里糊涂，它就答得莫名其妙；你问得精准具体，它就能精准调用最合适的能力。所以今天这一讲，就是把『怎么好好说话』拆成一套可复用的骨架，让你从此告别『随机抽奖式』的 AI 输出。讲完你就能明白那句老话的另一半：垃圾进、垃圾出——反过来，好问题进，好答案出。"

- **页面关键元素指引**：指向封面"好/坏 Prompt 对比"的视觉，预告本讲会反复用正反例对比。

- **现场动作/Demo**：无。

- **时长**：约 1 分钟。

### P2 Prompt 是什么（五要素总览）

- **本页是什么**：Prompt 的定义 + 五大组成部分总览（角色/上下文/指令/范例/输出格式）。

- **开场/衔接话术**：
  "先给 Prompt 下个准确定义，再把这个骨架整体亮出来。"

- **核心讲解**：
  "OpenAI 官方是这么定义的：Prompt 是一段用于**指导模型输出**的短文本，它可以提供上下文、指定输出格式、甚至控制模型行为。翻译成人话就是——**Prompt 是给模型的一份工作说明书**。你给员工布置任务，光说一句『把这个做一下』，他肯定懵；但如果你说『你是负责数据的，把这批订单按地区统计一下，输出成表格发我』，他就门儿清。这份『工作说明书』，由五个部分组成，页面这五张卡就是今天的全部内容：**角色**——你让 AI 扮演谁；**上下文**——任务的背景信息；**指令**——具体要做什么；**范例**——给个样板参考；**输出格式**——结果长什么样。记住这个骨架，后面每一页拆一个要素，拆完我们拿它拼一个完整的 SQL 生成器。"

- **页面关键元素指引**：五要素卡从左到右点过，给每个要素一个"一句话定位"，建立整体骨架印象。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："五个要素是不是每次都要写全？"
  - A："不必死板。简单任务（比如查个天气）只用『指令』就够；复杂任务（比如生成 SQL、写报告）才需要五要素齐全。它们是『工具箱』，不是『公式』——按需取用。"

- **时长**：约 3 分钟。

### P3 要素①：角色

- **本页是什么**：角色要素——专业型/创意型/中介型三种角色 + 多重角色协作、反向角色，配正反例。

- **开场/衔接话术**：
  "第一个要素：角色。想象你拍一部电影，不指定角色，演员自由发挥；指定了『演医生』，他的表演立刻贴合剧情。给 AI 角色，就是给它戴上不同的『职业帽子』。"

- **核心讲解**：
  "角色有三种典型用法。**专业型**：要权威内容就指定专家身份。反例『告诉我如何减肥』，太宽泛；正例『假如你是营养学教授，为一名 BMI 超标的上班族制定安全减重方案，需包含饮食、运动和心理调节建议』。**创意型**：激发故事力。反例『写一首诗』；正例『模仿李白的浪漫主义风格，以"人工智能与月亮"为主题，写一首七言绝句』。**中介型**：让 AI 模拟特定对象的口吻。反例『教孩子刷牙』；正例『你是一只爱干净的卡通兔子，用儿歌和拟声词教 3 岁小朋友正确的刷牙步骤』。角色还有两个进阶玩法：**多重角色协作**——『你既是编剧又是影评人，先写大纲再从观众角度分析』；**反向角色**——『你现在是小学生，我来教你勾股定理，我讲不清你随时提幼稚问题』。一句话：给 AI 发一张工作证，它的输出立刻专业起来。"

- **页面关键元素指引**：左栏三角色（专业/创意/中介），右栏正反例对比；每个角色先念反例再念正例，让学员感受"加角色前后"的落差。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："角色是不是写得越具体越好？"
  - A："方向对，但别跑偏。年龄、行业、性格这些描述越具体，输出越生动。但注意『角色与目标一致』——别让诗人写代码、让程序员写情诗（除非刻意制造反差）。角色是为任务服务的。"

- **时长**：约 5 分钟。

### P4 要素②：上下文

- **本页是什么**：上下文要素——单次提问背景 + 多轮对话延续 + 两大误区（信息过载/断层跳跃）。

- **开场/衔接话术**：
  "第二个要素：上下文。想象你跟朋友聊天，他突然来一句『好的，明天见』，你肯定懵——明天见谁？在哪见？AI 也一样，缺上下文，它只能瞎猜。"

- **核心讲解**：
  "上下文分两种。**单次提问内**提供背景：反例『这段话翻译成英文』——AI 不知道用途、语气、术语要不要保留；正例『这是一份医疗器械说明书的技术参数部分，请用专业学术英语翻译以下中文段落，保留术语缩写：[附原文]』。**多轮对话中**延续上下文：第一轮说『帮我写封辞职信，改得温和点』，第二轮接『谢谢！请在结尾加一句"感谢团队过去三年的支持"』——AI 会根据前文调整，而不是重新生成。但上下文有两个误区要警惕：一是**信息过载**——堆一堆无关细节，AI 反而迷失重点，只留强相关的背景；二是**断层跳跃**——多轮对话中突然换话题不重置，AI 还沉浸在旧语境里，新任务开始前最好说一句『现在我们讨论另一个问题……』。把上下文想成给导航设起点终点，设对了 AI 才不迷路。"

- **页面关键元素指引**：左栏"背景"对话气泡 + 右栏两大误区卡；先讲两种正确用法，再讲两个误区（红色警示）。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："上下文给多少算合适？"
  - A："一个判断标准：『强相关才给』。跟任务直接相关的背景、约束、前置条件，给足；跟任务无关的，砍掉。信息不是越多越好，是越『相关』越好。"

- **时长**：约 4 分钟。

### P5 要素③：指令

- **本页是什么**：指令要素——动词先行 + 结果导向 + 任务层级 + 约束条件，配三大正反例 + 典型错误修正表。

- **开场/衔接话术**：
  "第三个要素，也是五要素里的核心——指令。如果把 AI 当员工，指令就是你布置的任务书。这一页最容易踩坑，我们多花点时间。"

- **核心讲解**：
  "写指令记住四个字：**动词先行**。直接用动词开头，声明任务类型。反例『关于气候变化的数据』——没有动作；正例『对比近十年全球碳排放量变化趋势，用柱状图数据表格展示，标注主要国家增减幅度』。第二点，**区分任务层级**：基础操作类是单一动作，比如『将以下英文论文摘要翻译成简体中文』；综合分析类是多步骤处理，比如『阅读这三篇调查报告，总结研究方法共性，批判性分析样本选择偏差风险』。第三点，**约束条件绑定**：给指令加上限制，比如『用小学生能理解的比喻解释区块链原理（不超过 100 字）』、『生成 5 条七夕珠宝促销文案，要求押韵，每条附表情符号』。再送你一张『典型错误修正表』：缺主指令的，补全动作；多指令混杂的，分步拆解；指令过泛的，精准聚焦。记住那句金句：**不要问 AI 能做什么，而是告诉它该怎么做**。"

- **页面关键元素指引**：上半讲"动词先行+结果导向"，下半重点指"正反例三卡"和"错误修正表"；每个错误类型念一遍反例→正例。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："指令写太细会不会限制 AI 发挥？"
  - A："取决于任务。创意类任务（写诗、起名）可以留白让 AI 发挥；执行类任务（整理、生成、翻译）越细越准。一个技巧：把『做什么』写死，把『怎么润色』放开，让 AI 在约束内自由发挥。"

- **时长**：约 6 分钟。

### P6 要素④：范例

- **本页是什么**：范例要素——风格迁移/复杂格式/语义校准三大场景 + 正反例对比、渐进迭代技巧。

- **开场/衔接话术**：
  "第四个要素：范例。这是我个人觉得最被低估、效果最猛的一个。它的类比是——**给 AI 一本临摹字帖**。"

- **核心讲解**：
  "试想两种教法：一种纯文字描述『画一只猫，要有科技感』；另一种图文对照『参考这张赛博朋克机械猫设计图，保持齿轮关节和荧光线条，但把瞳孔改成三角形』。显然第二种能锁定预期。范例适用于三个场景。**风格迁移**：抽象审美难描述，反例『我想要复古的海报字体』，正例『参照这张 1950 年代电影海报的字体风格，为咖啡馆店名"旧时光"设计 LOGO』。**复杂格式规范**：要结构化输出时，直接给模板示例，比『按学术期刊格式调整参考文献』靠谱得多。**语义校准**：防止专业用词跑偏，仿照范例的技术文档结构来写。范例还有个隐藏心法：**给一个世界级的样例，往往比写一百个要求更管用**。进阶技巧有正反例对比（明确质量红线）、渐进迭代（先给基础范例，收到初稿再追加）。记住：遇到抽象需求时，先问自己一句——我能不能找到一个具体参照物？"

- **页面关键元素指引**：三场景卡并列，每个场景都点"反例→正例"；强调"临摹字帖"这个类比和"世界级样例"心法。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："用别人的作品当范例，会不会有版权问题？"
  - A："会，注意别直接复制受保护内容。用范例是为了传『风格/结构』，不是传『内容』。关键片段优于完整长文；商业场景尤其要留意版权。"

- **时长**：约 5 分钟。

### P7 要素⑤：输出格式

- **本页是什么**：输出格式要素——段落/列表/表格/代码块/对话体 + 格式设计四要素（层次/留白/标记/交互）。

- **开场/衔接话术**：
  "最后一个要素：输出格式。同样一份内容，格式对了直接能用，格式乱了还要二次加工——格式就是『信息的整形术』。"

- **核心讲解**：
  "常见格式五类：**自然段落**（故事、观点）、**结构化列表**（要点、步骤）、**表格/图表**（数据对比）、**代码块**（编程、公式）、**对话体**（情景模拟、访谈）。怎么选？看用途——要复制发朋友圈就用段落，要快速扫描就用列表，要比参数就上表格。格式设计有四要素：**层次分明**（标题分级、序号标识）、**留白控制**（限制每点字数、空行分隔）、**标记强化**（关键术语加粗、盈利标绿亏损标红）、**交互适配**（兼容微信排版、适配手机竖屏）。举个正例：反例『说说新能源汽车的优点』，正例是给出一个带标题、分节、用符号标注的完整框架。最后一句避坑指南：**别过度格式化**——简单天气查询不需要五级目录，好的格式是专业表达，不是形式主义。"

- **页面关键元素指引**：四格式卡先点过，重点落在下方"格式设计四要素"；强调"格式验证"（加一句"请确保 JSON 格式有效"）。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："模型不听我的格式要求怎么办？"
  - A："加一句自检指令，比如『请确保输出是合法的 JSON』或『请严格按上述 Markdown 结构输出，不要添加额外说明』。多数模型对这类显式约束的遵守度会明显提高。"

- **时长**：约 4 分钟。

### P8 💡 加分项：下指令四要素

- **本页是什么**：下指令四要素——做什么 + 用什么材料 + 输出什么格式 + 发到哪里，成功率 30%→90%+。

- **开场/衔接话术**：
  "五要素拆完了。这里再送你一个更精炼的『口袋版』，来自一套给 Agent（智能体）下指令的方法——四要素。它跟五要素是相通的，但更容易记住、更适合『让 AI 做事』的场景。"

- **核心讲解**：
  "记住这个公式：**好指令 = 做什么 + 用什么材料 + 输出什么格式 + 发到哪里**。四个要素各司其职：『做什么』是具体任务；『用什么材料』是 AI 要处理的内容或来源（哪个文件、哪封邮件、哪个网址）；『输出什么格式』是结果长什么样（列表、表格、Word 文档）；『发到哪里』是结果送哪去（发给我、存到桌面、写入飞书文档）。看对比——模糊指令：『帮我整理一下邮件』；清晰指令：『帮我读取今天收到的所有邮件，按"重要"和"一般"两类整理，用列表格式总结每封邮件的发件人和主题，发给我看』。用对四要素，同样一个 AI 的成功率能从 30% 拉到 90% 以上。为什么？因为 AI 没有常识和默认理解，你不说清楚，它就像新入职的员工一样懵。四要素就是给它的『入职说明书』。"

- **页面关键元素指引**：这是深色巨数页，重点指"30% → 90%"这个数据；四要素公式逐项点过，最后落到模糊/清晰指令的对比。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："四要素和五要素到底用哪个？"
  - A："本质是同一套思想的两张皮。五要素（角色/上下文/指令/范例/格式）更细，适合写复杂的系统 Prompt；四要素（做什么/材料/格式/发到哪）更贴近『下达任务』，适合日常让 AI 干活、尤其给 Agent 下指令。两者不冲突，用哪个顺手用哪个。"

- **时长**：约 5 分钟。

### P9 实战：SQL 生成器

- **本页是什么**：用五要素构建一个完整可用的 SQL 生成器 Prompt，现场演示。

- **开场/衔接话术**：
  "理论讲完了，现在把它们组装成一件『真家伙』——一个 SQL 生成器。目标：你输入一句业务关键词，它输出一条正确的 SQL。"

- **核心讲解**：
  "这个 SQL 生成器的 Prompt，五要素一个不少。**角色**：定位为『具备多表关联设计能力的专业数据库工程师』。**上下文**：说明用户可能不熟表结构、不熟函数、多条件易混、要兼顾性能。**指令**：三步处理流程——语义解析（识别操作类型/表字段/过滤条件/排序/分页）→ 结构映射（自动 JOIN、字符串加引号、数值不加、日期转换）→ 逻辑校验（危险操作加警示、超 3 表建议索引、模糊查询提示性能）。**范例**：给一组『输入关键词 → 生成 SQL』的示例，让模型照葫芦画瓢。**输出格式**：『仅返回 SQL 语句，无需任何额外说明』。完整版我贴在讲义第二部分，大家课后直接抄去用。现场我演示一遍：输入『最近三个月上海地区单价超过 5000 元的电子产品订单，按金额降序排』，看它输出一条带三表 JOIN、时间函数、LIMIT 的完整 SQL。"

- **页面关键元素指引**：左栏是 Prompt 结构（五要素标注），右栏是 SQL 输出代码块；重点指"范例"和"输出格式"两个要素，它们决定了输出质量。

- **现场动作/Demo**：Live Demo——把第二部分完整 Prompt 粘进 DeepSeek（或本地 deepseek-v4-flash），输入示例关键词，展示生成的 SQL。

- **可能的学员提问 & 回答**：
  - Q："这个 SQL 生成器能直接拿来生产用吗？"
  - A："作为模板可以，但生产要补几样东西：真实的表结构（替换范例里的 orders/users/products）、安全校验（防注入、防无条件 DELETE）、以及对生成 SQL 的执行确认。它展示的是『五要素如何落地』，真实系统要在这个骨架上加固。"

- **时长**：约 7 分钟。

### P10 降低 AI 幻觉

- **本页是什么**：幻觉是什么 + 三种降幻觉手段（PromptTemplate + FewShot + 示例选择器，预告第 4 讲）。

- **开场/衔接话术**：
  "Prompt 写得好，能大幅减少一个最让人头疼的问题——AI 幻觉。这一页聊聊它。"

- **核心讲解**：
  "**AI 幻觉**，指模型生成看似合理、实则错误或虚构的内容，本质是模型基于统计模式产生的『自信错误』——它一本正经地胡说八道，还说得特肯定。怎么降？三板斧。第一，**约束 Prompt**：直接告诉它『不知道就说不知道』『只依据给定资料回答，不要编造』，这是零成本但最有效的一招。第二，**FewShot 少样本示例**：给它几个正确的问答范例，等于做一次『微型训练』，让它照着正确模式走。第三，**示例选择器**：示例多了就像个小知识库，用语义相似度挑出跟当前问题最相关的几个示例（这在 LangChain 里有现成的 `SemanticSimilarityExampleSelector`）。这三板斧，本质是把模型的『自我发挥空间』框住——你给的约束和范例越清晰，它越难胡说。后面第 4 讲我们会正式学 LangChain 的 PromptTemplate，今天先埋个概念。"

- **页面关键元素指引**：上半讲"幻觉=自信错误"的定义，下方三技巧卡逐个点；强调"不知道就说不知道"这一句最实用。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："FewShot 和 RAG 有什么区别？"
  - A："有点像。FewShot 是静态地在 Prompt 里塞几个固定示例；RAG 是动态地从知识库里检索相关资料再喂给模型。规模小、示例少用 FewShot；资料多、要实时更新用 RAG。第 5 讲会专门展开 RAG。"

- **时长**：约 5 分钟。

### P11 冷知识 & 总结

- **本页是什么**：总结收官——五要素回顾 + 金句"不要问 AI 能做什么，而是告诉它该怎么做" + 自测 3 题。

- **开场/衔接话术**：
  "最后一页，收个尾。今天内容不少，但真正要带走的，就一句话 + 一个骨架。"

- **核心讲解**：
  "先给今天那颗『冷知识』：很多人拿到 AI 的第一反应是问『你能做什么？』——这是错的。正确姿势是**『不要问 AI 能做什么，而是告诉它该怎么做』**。因为 AI 的能力边界由你的指令决定，你问得越泛，它答得越泛；你指令越具体，它产出越精准。再回顾今天的骨架：五要素——**角色**（扮演谁）、**上下文**（什么背景）、**指令**（做什么）、**范例**（参照什么）、**输出格式**（长什么样），外加一个口袋版四要素（做什么/材料/格式/发到哪）。最后强调一句：这个骨架是『骨架』不是『终点』，真正内化靠的是练习——课后设计一个你自己的生成类 Prompt，跑一跑、改一改，直到满意。练完这个，你就正式跨过了本系列第一个里程碑 M1 的门槛。"

- **页面关键元素指引**：居中金句 + 五要素回顾；最后落到"练习才内化"和自测 3 题上。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："学完这讲，我能做什么了？"
  - A："你能把一个模糊需求，拆成一份结构化 Prompt，让 AI 的输出质量明显上一个台阶——写周报、整理纪要、生成 SQL、翻译、写文案，全都通用。而且这套能力是 M1 里程碑的核心，也是后面所有 Agent 开发的地基。"

- **时长**：约 5 分钟。

### 1. SQL 生成器完整 Prompt（五要素完整版，可直接复制）

> 本 Prompt 为纯文本，粘进 DeepSeek 或本地 deepseek-v4-flash 即可使用。五个要素已用注释标注。

```text
# 角色
您是具有以下能力的专业数据库工程师：
- 准确解析用户业务场景关键词
- 掌握ANSI SQL标准及主流数据库方言
- 熟悉数据库设计范式与性能优化原则
- 具备多表关联查询设计能力

# 上下文
用户需要快速生成准确SQL语句但可能面临：
1. 不熟悉复杂表关联结构
2. 对特定函数用法不明确(如时间处理函数)
3. 多条件组合逻辑易混淆
4. 需要兼顾查询性能优化

# 指令
按以下步骤处理用户输入的关键词：
1. 语义解析：识别关键词中的核心要素
   - 操作类型(SELECT/INSERT/UPDATE/DELETE)
   - 目标表/字段
   - 过滤条件(时间范围、状态值等)
   - 排序/分组需求
   - 分页参数

2. 结构映射：
   a. 自动关联相关表的JOIN条件
   b. 识别VARCHAR字段自动添加引号
   c. 数值型字段保持原生格式
   d. 日期字段转换处理(如STR_TO_DATE)

3. 逻辑校验：
   - 当检测到危险操作时(如无条件的DELETE)添加警示
   - 对超过3表关联的查询建议索引优化
   - 为模糊查询(%value%)提示性能影响

# 范例
[输入关键词]
"需要最近三个月上海地区单价超过5000元的电子产品订单，按金额降序排"

[输出]
SELECT
    o.order_id,
    u.user_name,
    p.product_name,
    o.order_amount,
    o.create_time
FROM
    orders o
    JOIN users u ON o.user_id = u.user_id
    JOIN products p ON o.product_id = p.product_id
WHERE
    o.region = '上海'
    AND p.category = '电子产品'
    AND o.order_amount > 5000
    AND o.create_time >= DATE_SUB(CURDATE(), INTERVAL 3 MONTH)
ORDER BY
    o.order_amount DESC
LIMIT 100;

[说明]
1. 自动关联三表JOIN
2. 数值条件未加引号
3. 添加LIMIT防止结果集过大
4. 时间条件使用函数动态计算

# 输出格式
[仅返回SQL语句，无需任何额外说明]

如果你已理解上述要求，请回答是的。
```

### 3. 示例选择器（SemanticSimilarityExampleSelector，示例多时按语义挑）

```python
from langchain.prompts.example_selector import SemanticSimilarityExampleSelector
from langchain_chroma import Chroma
from langchain_ollama.embeddings import OllamaEmbeddings
from langchain.prompts import FewShotPromptTemplate, PromptTemplate

# 用本地 Ollama 的中文嵌入模型（对中文更友好）
ollama_emb = OllamaEmbeddings(
    base_url="http://127.0.0.1:11434",
    model="shaw/dmeta-embedding-zh",
)

examples = [
    {"question": "谁的寿命更长，穆罕默德二世还是爱因斯坦？",
     "answer": "爱因斯坦活了 76 岁。\n穆罕默德二世活了 89 岁。\n因此，穆罕默德二世比爱因斯坦活得更长。"},
    {"question": "目前电影票房第一名是谁？",
     "answer": "《阿凡达》票房 27.9 亿美元。\n《复仇者联盟 4》票房 27.8 亿美元。\n因此，《阿凡达》票房更高。"},
    {"question": "深圳第一高楼是哪个？",
     "answer": "深圳平安国际金融中心楼高 593 米。\n深圳京基100 楼高 441.8 米。\n所以深圳第一高楼是平安国际金融中心。"},
]

# 按语义相似度，从示例集里挑出与当前问题最相关的 k 个示例
example_selector = SemanticSimilarityExampleSelector.from_examples(
    examples=examples,
    embeddings=ollama_emb,
    vectorstore_cls=Chroma(),   # 内存向量库，用于相似度计算
    k=1,
)

question = "穆罕默德二世？"
selected_examples = example_selector.select_examples({"question": question})

example_prompt = PromptTemplate(
    input_variables=["question", "answer"],
    template="问题：{question}\n答案：{answer}"
)

prompt = FewShotPromptTemplate(
    examples=selected_examples,      # 用"挑过的"示例
    example_prompt=example_prompt,
    suffix="问题：{input}",
    input_variables=["input"],
)

print(prompt.format(input=question))
```

## 四、自测题答案

**① 五要素分别解决什么问题？**

| 要素 | 解决的问题 |
|------|-----------|
| 角色 | 决定 AI"用什么知识领域、什么口吻"回答，让输出更专业、更有针对性 |
| 上下文 | 提供背景信息，让 AI 理解任务的关联性和具体要求，避免瞎猜 |
| 指令 | 明确"具体做什么"，是行动命令，直接决定输出方向和形式 |
| 范例 | 给参照样板，降低沟通歧义、锁定预期质量与风格 |
| 输出格式 | 规定"结果长什么样"，决定信息组织方式和最终呈现形态 |

**② 给一段模糊 Prompt 并当场优化（示例）。**

- 模糊版：`写一篇关于人工智能的文章`
- 优化版：
  `你是一位科技专栏作者，面向有编程背景但不懂 AI 的读者，写一篇 800 字左右的科普文章介绍大语言模型（LLM）。先一句话概括 LLM 是什么，再分三个小节展开：① 它为什么"大"；② 它能做什么；③ 普通人怎么入门。每小节不超过 200 字，用通俗比喻解释，避免堆砌专业黑话。用 Markdown 标题分层，关键术语加粗。`

优化要点：加了角色（科技专栏作者）、上下文（读者画像）、指令（具体任务+三小节）、输出格式（字数、分层、加粗），若再补一个范例效果更好。

**③ 下指令四要素是什么？**

- **做什么**：AI 要完成的具体任务（整理邮件、查天气、生成报告）。
- **用什么材料**：AI 需要处理的内容或来源（哪个文件、哪封邮件、哪个网址）。
- **输出什么格式**：你希望结果长什么样（列表、表格、一段话、Word 文档）。
- **发到哪里**：结果送到哪里（发给我、存到桌面、写入飞书文档）。
- 公式：**好指令 = 做什么 + 用什么材料 + 输出什么格式 + 发到哪里**，用对可把成功率从 30% 提升到 90%+。

## 五、常见坑位提醒

1. **五要素别当"八股"硬套**：简单任务只用"指令"即可，五要素是工具箱不是公式。讲师要反复强调"按需取用"，避免学员把简单问题写成三段论。
2. **角色与任务错位**：别让诗人写代码、让程序员写情诗。提醒学员"角色为目标服务"，角色选错反而降低质量。
3. **范例别踩版权**：用范例传"风格/结构"，不传"内容"，别直接复制受保护作品，商业场景尤其注意。
4. **上下文过载**：信息不是越多越好，只留强相关背景。学员常犯"把整段文档全塞进去"，反而让 AI 迷失重点。
5. **SQL 生成器别当生产工具**：演示用的 SQL 生成器缺真实表结构、安全校验、执行确认。要明确告诉学员这是"五要素落地范本"，生产要加固，否则有人真拿去做批量删除会出事。
6. **现场演示依赖网络/模型**：P9 的 SQL 演示务必课前跑通；网络不稳就放回放/截图。SQL 生成器 Prompt 较长，建议课前复制到剪贴板，避免现场手打出错。
7. **四要素与五要素别讲成两套对立的东西**：它们是同一思想的两种表述（一个细、一个精炼），讲清楚"相通"关系，否则学员会纠结"到底学哪个"。
8. **时间把控**：本讲 50 分钟、内容最满，P5（指令）和 P9（SQL 实战）是重头戏要保足时间；P7（输出格式）相对简单可适当加快，P11 收尾要留足时间让学员"带走一句话 + 一个骨架"。
