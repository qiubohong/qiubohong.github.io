- **页面关键元素指引**：强调副标题「我们正站在哪一步」——这不是一个答案，是一套坐标系的入口。
- **现场动作/Demo**：无

### P2 历史回看：OpenAI DevDay 2023

- **本页是什么**：回看 2023 年 11 月 6 日 OpenAI 首届开发者大会，用「三年后视角」看当年的范式如何被 Agent 演进。
- **开场/衔接话术**：「先回到 2023 年 11 月 6 日，OpenAI 在旧金山办的第一届开发者大会。那是 AI 行业的一个转折点，今天很多我们习以为常的东西，都能在那一天找到源头。」
- **核心讲解**：那场 45 分钟的发布会，几个重磅发布：**GPT-4 Turbo**（上下文从 8K 拉到 128K，堪比一本 300 页的书；支持 JSON 输出；知识更新到 2023 年 4 月）；**GPTs + GPT Store + GPT Builder**（让用户通过自然语言定制自己的 AI 助手，还能对外发布）；**Assistants API**（专门构建的 AI 助手，带线程、消息、工具、函数调用）。当天还亮了一组数据：200 万开发者用 OpenAI API、92% 的 500 强公司在用、1 亿周活用户。**三年后回头看**，这一讲最有意思的地方在于：当年这些「革命性」的范式——GPTs、Assistants API——如今都已经被 Agent 全面演进和取代了。这告诉我们一个判断趋势的方法：**技术演进不是推翻，而是吸收**，旧范式的能力被新范式「吞并」进更大的框架里。
- **页面关键元素指引**：发布亮点时间轴，指 GPT-4 Turbo → GPTs → Assistants API 三个节点，最后停在「三年后：范式被 Agent 演进」这个注脚上。
- **现场动作/Demo**：无
- **可能的学员提问 & 回答**：
  - Q：「GPT Store 后来怎么样了？」A：「没有成为『AI 版 App Store』的爆款，因为通用 Agent 能力起来了，用户不再需要一个一个装『专用 GPT』。这恰恰是「范式被吸收」的例证——单一功能被通用能力覆盖了。」
- **时长**：约 3 分钟

### P3 模型技术深水区：DeepSeek 演进

- **本页是什么**：讲 DeepSeek 的演进路线 R1 → V3 → V4-Flash，重点在 V4-Flash 正式版的技术突破和数据。
- **开场/衔接话术**：「从 OpenAI 切到国产阵营，讲 DeepSeek。这条线特别值得讲，因为它代表了一种完全不同的技术路线——用『小参数 + 高效率』追平闭源，还开源。它一路走来，本身就回答了『开源能不能打』这个问题。」
- **核心讲解**：路线三步：**R1**（2025.01，靠「思维链」推理引爆全球，改写对话范式）→ **V3**（MoE 架构基座，671B 总参 / 37B 激活）→ **V4-Flash 正式版**（2026.07，**284B 总参 / 13B 激活**，1M 上下文，MIT 开源，FP4+FP8 量化）。这里要解释几个关键概念：**MoE（混合专家）**——总参数大但每次只激活一小部分，所以 284B 总参却只激活 13B，推理又快又省；**FP4+FP8**——用更低的数值精度存权重，显存和带宽需求大减；**CSA/HCA 稀疏注意力**——不是每个 token 都看所有 token，而是有选择地聚焦，长上下文下更省算力；**DSpark 推测解码**——用一个小模型「猜」大模型要说什么，猜对就跳过，加速生成。效果数据是惊人的：**DeepSWE（软件工程能力基准）从预览版 7.3 干到 54.4，提升 640%**。一句话总结：V4-Flash 证明了「脱离 CUDA 生态 + 小参数高效架构」这条路走得通。
- **页面关键元素指引**：演进时间轴三个节点，重点停在 V4-Flash 上；数据 284B/13B、1M、DeepSWE 54.4（+640%）逐个点。
- **现场动作/Demo**：无
- **可能的学员提问 & 回答**：
  - Q：「MoE 的『激活参数』是什么意思？为什么它更省？」A：「传统稠密模型每次推理所有参数都干活；MoE 把模型分成很多『专家』，每次只叫醒和当前任务相关的几个。所以总参数量大（懂的多），但计算量小（干的少），这就是小参数反超大参数的原因。」
- **时长**：约 4 分钟

### P4 2026 模型格局三足鼎立

- **本页是什么**：本讲第一个 Hero 页，对比 2026 年三大旗舰模型 GPT-5 / Claude Opus 5 / DeepSeek V4-Flash 的卡位。
- **开场/衔接话术**：「看清楚了个体的演进，再看整体格局。2026 年的旗舰模型，形成了三足鼎立的局面——闭源双雄 GPT-5 和 Claude Opus 5，加上开源旗舰 DeepSeek V4-Flash。它们没有直接『内卷』同一条路，而是在三个不同维度各自卡位。」
- **核心讲解**：**GPT-5**（2026.08）：400K 上下文、内置思考、text+vision 多模态，走「全能 + 多模态」路线；**Claude Opus 5**（2026.07）：1M 上下文、thinking 默认开启，走「超长上下文 + 深度推理」路线；**DeepSeek V4-Flash**：开源、$0.14/百万 input token、脱离 CUDA 生态、适配昇腾，走「开源 + 极致成本」路线。这张表的关键不是记住参数，而是看懂卡位逻辑：三巨头在「**上下文 × 成本 × 开源**」三个维度各自占一个生态位。GPT-5 赢在多模态全能，Opus 5 赢在上下文和推理深度，V4-Flash 赢在开源生态和成本。对我们开发者意味着什么？**选模型不再只看「谁最强」，而是看「谁最匹配我的场景和预算」**——这就是第 1 讲「模型格局」的升级版认知。
- **页面关键元素指引**：三卡对比表，先横向比「上下文/成本/开源」三个维度，再纵向点每个模型的独门优势。
- **现场动作/Demo**：无
- **可能的学员提问 & 回答**：
  - Q：「三足鼎立会持续多久？」A：「不好说，但判断趋势的方式是看『卡位有没有被填满』。目前三者在不同维度，短期内会共存；一旦某家开始侵入别家的生态位（比如闭源大幅降价），格局才会重排。」
- **时长**：约 4 分钟

### P5 推理模型时代

- **本页是什么**：讲推理模型（「先想再说」）的兴起，以及思考强度可调（reasoning_effort / effort）和推理 token 成本管理。
- **开场/衔接话术**：「这三巨头有个共同点——都是『推理模型』时代的产品。什么是推理模型？一句话：普通模型是『直接作答』，推理模型是『先想再说』。」
- **核心讲解**：普通模型（如 GPT-4o、V3）拿到问题直接生成；推理模型在给答案前会先经历内部推理——多步拆解、自我验证、不同路径比较，再把思考过程压缩成最终答案。所以差别不是「更聪明一点」，而是**普通模型调输出风格，推理模型调思考强度**。这带来一个新参数体系：`reasoning_effort`（OpenAI）或 `effort`（Claude），控制模型愿意花多少算力去想——`low` 适合简单查询，`high` 适合复杂数学和规划。关键提醒：**推理是有成本的**，思考 token 是要算钱的，很多时候贵的不是最后那几句答案，而是前面一大段内部推理。所以工程上的智慧是「别什么任务都上推理模型」：加一个路由层，简单问题走普通模型，复杂问题才走推理模型，能把不必要的成本直接砍掉。
- **页面关键元素指引**：两阶段生成图「思考 → 输出」，强调「思考强度可调」这个新旋钮和「推理 token 要钱」这个新成本项。
- **现场动作/Demo**：无
- **可能的学员提问 & 回答**：
  - Q：「我怎么知道什么时候该用推理模型？」A：「看任务要不要多步推理。数学题、逻辑题、长链路代码审查、多条件业务判断——值得上；普通闲聊、客服问答、简单翻译、轻量摘要——别上，上了大概率更慢更贵还不更好。」
- **时长**：约 4 分钟

### P6 Ontology：Agent 的语义地基

- **本页是什么**：讲 Ontology（本体）为什么是 Agent 跨系统的语义地基——三元组、本体绑定=权限边界、选型判断。
- **开场/衔接话术**：「接下来讲一个听起来很『哲学』、其实非常工程的东西——Ontology，本体。别被名字吓到，它解决的是一个特别具体的问题：为什么 Agent 一接进公司系统，就开始乱说话。」
- **核心讲解**：问题根源：同一个「客户」，CRM 里叫 `customer`，ERP 里叫 `client`，财务里叫 `account`，Agent 不知道这仨是同一个东西，于是查了三份互相矛盾的数据，自信地给错答案。这是语义问题，不是模型问题。Ontology 就是把业务里的概念、属性、关系用机器能懂的方式写清楚。核心结构是**三元组：主语-谓语-宾语**，比如「患者 - 服用 - 药物」「疾病 - 禁用 - 药物」。有了它，AI 能做确定性多跳推理，而不是靠统计直觉猜。最关键的洞察来自 Palantir：**本体是决策的表示，不仅仅是数据**；而且**本体绑定 = 权限边界**——你不是给 Agent 一把万能钥匙，而是给它「本体绑定」，它只能访问本体里明确授权的对象和关系，越界直接拦截。那什么时候上本体？一句话判断：**Demo 用 RAG 就够了，规模化（跨多系统、多 Agent 协同、要合规）才上本体**——Ontology is optional, until your AI has to scale。
- **页面关键元素指引**：本体结构图（三元组），强调「主语-谓语-宾语」这个最小单元；再点「本体绑定=权限边界」的深层含义。
- **现场动作/Demo**：无
- **可能的学员提问 & 回答**：
  - Q：「本体和知识图谱什么区别？」A：「本体是『概念层』（定义类、属性、关系，像数据库 Schema），知识图谱是『实例层』（存具体事实，像数据库里的数据）。本体定义规则，图谱存储事实。」
- **时长**：约 4 分钟

### P7 多模态与结构化输出

- **本页是什么**：讲多模态打通输入端、json_schema 打通输出端，两者串起来才是完整产品链路。
- **开场/衔接话术**：「模型格局和推理能力讲完了，讲两个把模型从『会聊天』推到『可落地生产工具』的能力——多模态和结构化输出。它们一个打通输入端，一个打通输出端。」
- **核心讲解**：**多模态**让模型接收真实输入——图片、音频、视频，不再只吃文本。典型场景是发票识别：用户传一张发票图片，模型要先看懂内容。**结构化输出**让结果能直接被系统消费——不是一段解释，而是字段齐全、类型稳定的 JSON。这里有个分层认知：`json_object` 只是「尽量像 JSON」，真正严肃的业务要用 `json_schema` 严格卡死结构（`strict: true` + `additionalProperties: false`）。两者串起来才是完整链路：**多模态进、结构化出**。以发票识别为例：图片进 → 多模态理解 → json_schema 严格输出「发票号/日期/金额/销售方」→ 直接写库。判断系统可用性的，已经不只是模型多聪明，而是**输入格式和输出约束有没有设计好**。
- **页面关键元素指引**：产品链路图「图片进 → 结构化出」，指发票识别场景，强调「多模态进、结构化出」的闭环。
- **现场动作/Demo**：无
- **可能的学员提问 & 回答**：
  - Q：「json_object 和 json_schema 我该用哪个？」A：「下游要求不高、只是内部脚本，json_object 够了；要直接入库、驱动自动化、驱动严肃业务，必须 json_schema。前者是『请你认真输出 JSON』，后者是『必须按这个结构，不能多不能少』。」
- **时长**：约 3 分钟

### P8 国产算力与生态

- **本页是什么**：讲国产算力的突围——昇腾 NPU、DeepSeek 用 Triton 自研算子脱离 CUDA、国产生态。
- **开场/衔接话术**：「聊一个容易被忽略但决定性的变量——算力。前几页讲 DeepSeek『脱离 CUDA 生态』，这不是一句口号，是真实的工程突破。算力自主，决定了模型能不能不受制于人。」
- **核心讲解**：长期以来，大模型训练推理高度依赖英伟达 CUDA 生态，高端卡还受出口管制。国产的突围路径有两条线：**硬件**——华为昇腾 NPU，DeepSeek 深度适配，甚至有「昇腾 Atlas 集群」跑通旗舰模型的案例，一体机已落地客户；**软件**——DeepSeek 用 **Triton** 自研算子，绕开 CUDA 的底层绑定，让模型能在不同硬件上跑。加上原生 FP8/FP4 支持，理论性能翻倍、带宽减半。配合国产模型生态（DeepSeek、智谱、千问、豆包），一条「国产芯片 + 国产模型 + 国产框架」的自主链路正在成形。对开发者的启示：**别只盯着英伟达，算力选型要多看一个维度——你的部署目标是什么硬件**。判断趋势时，「算力自主」是一个关键变量。
- **页面关键元素指引**：生态地图，指「昇腾 NPU」和「Triton 脱离 CUDA」两个关键点。
- **现场动作/Demo**：无
- **可能的学员提问 & 回答**：
  - Q：「国产卡的性能追上了吗？」A：「纯算力上仍有差距，但靠 FP8/FP4 低精度、稀疏注意力、推测解码这些『软件优化』在追。DeepSeek V4-Flash 能跑到这个水平，本身就是『软硬件协同』证明差距在快速缩小。」
- **时长**：约 3 分钟

### P9 AI 安全与伦理

- **本页是什么**：讲 AI 安全伦理的三大风险（注入攻击 / 隐私 / 偏见）和应对（Moderation API、数据不出门）。
- **开场/衔接话术**：「能力讲完了，讲底线。AI 越强，安全风险越大。第 8 讲我们讲的是 Agent 工程里的『操作安全』，这一页讲更宏观的『模型安全与伦理』。」
- **核心讲解**：三大风险：**注入攻击**（攻击者把恶意指令藏在文档、网页里，诱导模型执行或泄露）；**隐私**（数据上传到第三方服务，敏感信息出域）；**偏见**（训练数据的偏见被模型放大，影响决策公平）。应对手段：**Moderation API**——在输入输出层做内容安全过滤，拦截有害内容；**数据不出门**——这正是第 2 讲强调「本地部署」的价值，隐私敏感场景用本地模型，数据不离开自己的机器；再加一层**Human-in-the-loop**——关键决策永远有人把关。这里有一个更深的洞察：模型越强，「伦理暗物质」风险越大（预训练阶段嵌入的有害知识在特定诱导下浮现），所以安全不是一次性的「上线前检查」，而是贯穿整个生命周期的持续工作。
- **页面关键元素指引**：安全风险矩阵三卡，逐一讲注入/隐私/偏见，再点「数据不出门」和 Moderation 的应对。
- **现场动作/Demo**：无
- **可能的学员提问 & 回答**：
  - Q：「我是开发者，安全伦理跟我有什么关系？」A：「关系很大。你写的每一个 Agent，如果被注入攻击带偏、泄露了用户数据，责任在你。安全不是安全团队的事，是每个开发者的默认配置——这也是第 8 讲三道防线的意义。」
- **时长**：约 3 分钟

### P10 未来展望

- **本页是什么**：预测 AI 发展的三大趋势——Harness 上移、工程师角色转型、多智能体成主流。
- **开场/衔接话术**：「历史、当下、技术趋势都看完了，最后看『往哪去』。我给出三个判断，每个都附上理由，你可以拿回去验证。」

## 四、自测题答案

1. **MoE 架构的核心思想？V4-Flash 相比前代的核心突破是什么？**
   MoE（混合专家）：总参数量大但每次只激活一小部分专家，做到「知识容量大、计算开销小」，实现小激活参数追平甚至反超稠密大模型。V4-Flash 核心突破：284B 总参 / 13B 激活（MoE）、1M 上下文、MIT 开源、FP4+FP8 量化、CSA/HCA 稀疏注意力、DSpark 推测解码，DeepSWE 从 7.3 提升到 54.4（+640%），并脱离 CUDA 生态适配昇腾。

2. **「本体绑定 = 权限边界」怎么理解？**
   传统做法是给 Agent 一把「万能 API Key」，权限要靠代码里一堆 if 判断；本体绑定的做法是——Agent 的访问范围直接绑定在本体上，它只能访问本体中明确授权的对象和关系，越界在架构层就被拦截，不需要在业务代码里写权限判断。权限和安全因此从「事后补救」前置成了「结构内置」。

3. **你判断趋势时看哪四个视角？**
   模型（能力与成本、开源 vs 闭源、算力自主）、Agent（单 Agent 天花板与多智能体、Harness 工程化）、本体（跨系统的语义地基与权限边界）、安全（注入/隐私/偏见与合规）。四个视角构成判断 AI 新事物的坐标系。

## 五、常见坑位提醒

1. **把具体工具当趋势**：某个框架火了就追，过半年就凉。趋势要看「底层范式」——比如从「补全」到「Agent」再到「规范驱动」，范式不因工具更迭而变。

2. **只记参数不记逻辑**：记住 284B/13B 没用，要理解「为什么 MoE 小激活能追平大模型」。理解了逻辑，参数怎么变都能自己判断。

3. **把推理模型当万能**：什么任务都上推理模型，成本飙升还不一定更好。简单任务走普通模型，加路由层分流。

4. **忽略推理 token 成本**：推理模型的「思考过程」是要算钱的，且往往贵过最终答案。`max_completion_tokens`/`budget_tokens` 是防超支阀门，不是装饰品。

5. **过早引入本体**：单数据源、单场景的 Demo 硬上本体，建模成本拖死项目。记住「until your AI has to scale」——不跨系统就别上。

6. **只盯英伟达、忽略算力自主**：部署选型只考虑 CUDA，忽略了昇腾等国产硬件和 Triton 路线，未来可能在供应链上被动。

7. **安全后置**：等 Agent 上线出事了才补安全。安全要前置——注入防护、数据不出门、Human-in-the-loop 从第一天就设计进去。

8. **迷信「模型变强 Harness 就不需要了」**：模型变强，Harness 的某些组件会简化，但整体空间不缩反移——因为要处理的问题更高阶。会「移除组件」和会「加组件」同样重要。
