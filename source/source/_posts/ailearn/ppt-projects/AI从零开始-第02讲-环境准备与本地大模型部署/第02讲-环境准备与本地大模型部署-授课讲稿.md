### P2 为什么需要本地模型

- **本页是什么**：本地部署的三大理由——免费、可控调用次数、数据不出门；并点明"本地不是替代云，而是多一种选择"。

- **开场/衔接话术**：
  "动手之前，先想清楚『为什么』——我都有免费的网页版了，为啥还要费劲本地部署？"

- **核心讲解**：
  "三个理由，个个都是刚需。第一，**免费**：在线 API 是按 Token 收费的，你反复调用、做测试，账单会一直涨；本地部署一次性投入，之后随便调用，零边际成本。第二，**可控调用次数**：线上 API 有速率限制、有配额，你做个批量任务或者高频 Agent，分分钟被限流；本地模型你自己说了算，想调多少调多少。第三，也是最重要的，**数据不出门**：公司内部的代码、合同、用户数据，你敢传到第三方 API 吗？本地部署意味着数据始终留在你自己的机器上。当然我要说句公道话——本地模型不是要『干掉』云 API，而是给你**多一种选择**：敏感数据走本地，追求最新最强走云端。两者配合，才是成熟的做法。"

- **页面关键元素指引**：左标题右内容，依次点三大理由；右下角补充"本地 vs 云的成本对比"，落到"双轨"这个结论。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："本地模型能力比得上云端 GPT-5 吗？"
  - A："看跟谁比。开源旗舰 DeepSeek V4-Flash 已经能对标闭源旗舰了，但像 GPT-5、Claude Opus 5 这种最新闭源模型，本地通常跑不动、也跑不到同等效果。所以正确的姿势是分工：本地跑开源模型处理敏感数据，云端跑闭源模型处理复杂任务。"

- **时长**：约 3 分钟。

### P4 安装 Python（Anaconda）

- **本页是什么**：Python 的两种装法——官网直装 vs Anaconda，推荐 Anaconda 统一管理环境。

- **开场/衔接话术**：
  "第一件套：Python。这步有个选择——你是裸装 Python，还是装 Anaconda？我强烈建议后者。"

- **核心讲解**：
  "裸装 Python 很简单，去官网下载安装包一路下一步，装完命令行敲 `python --version` 能出版本号就成功了。但它有个痛点：**环境管理麻烦**。你以后做不同项目，A 项目要 Python 3.10 + PyTorch 2.1，B 项目要 Python 3.12 + 别的依赖，裸装 Python 很容易把环境搞成一锅粥。所以推荐 **Anaconda**——它自带 conda 环境管理器，能给你建多个互相隔离的虚拟环境，切环境一条命令搞定。国内下载记得用**清华源**，速度快：`https://mirrors.tuna.tsinghua.edu.cn/anaconda/archive/`。装完验证一下 `conda --version` 能出号，就成功了。具体命令我在讲义第二部分都贴好了，大家课后照抄即可。"

- **页面关键元素指引**：左栏"官网直装 vs Anaconda"对比，重点指 Anaconda 的"环境隔离"优势；右栏强调清华源镜像地址。

- **现场动作/Demo**：Live Demo——展示一个已装好的终端，敲 `conda --version` 和 `conda env list`，让学员看到环境隔离长什么样。

- **可能的学员提问 & 回答**：
  - Q："Anaconda 太大、太占空间，能不能用 Miniconda？"
  - A："完全可以。Miniconda 是 Anaconda 的精简版，只带 conda 和 Python，没有预装那几百个科学计算包。空间紧张就用 Miniconda，命令完全一样。重点是 conda 这个环境管理器，不是 Anaconda 那一堆预装包。"

- **时长**：约 5 分钟。

### P5 安装深度学习库

- **本页是什么**：三条命令装 PyTorch / Transformers / LangChain + 各自的验证方式。

- **开场/衔接话术**：
  "Python 装好了，接下来三件套——PyTorch、Transformers、LangChain，三条命令的事。"

- **核心讲解**：
  "**PyTorch** 建议用 conda 装，因为 conda 会自动帮你匹配 CUDA 版本（GPU 驱动），省去一堆麻烦：`conda install pytorch torchvision torchaudio cudatoolkit=11.3 -c pytorch`。注意 cudatoolkit 版本要跟你的显卡驱动匹配，没 NVIDIA 显卡就直接装 CPU 版。装完验证：`python -c "import torch; print(torch.__version__)"`。**Transformers** 用 pip 装：`pip install transformers`，验证 `python -c "import transformers; print(transformers.__version__)"`。**LangChain** 也是 pip：`pip install langchain`，验证 `python -c "import langchain; print(langchain.__version__)"`。三条命令都不复杂，关键是要**装一条、验证一条**，别一口气全装完才发现某个 import 报错。国内 pip 慢的话，加清华源：`pip install -i https://pypi.tuna.tsinghua.edu.cn/simple 包名`。"

- **页面关键元素指引**：重点指上方大图里的三条命令；强调"装一条验证一条"的节奏；顺带提醒国内 pip 加速用清华源。

- **现场动作/Demo**：Live Demo——在已装好的环境里逐个跑三条验证命令，展示正常输出版本号。

- **可能的学员提问 & 回答**：
  - Q："pip 和 conda 装同一个包，会不会冲突？"
  - A："会。所以一个原则：**同一个环境里，尽量统一用 conda 或统一用 pip**，别混着装同一个包。PyTorch 这种涉及底层编译的用 conda，纯 Python 包（transformers、langchain）用 pip，是比较稳妥的组合。"

- **时长**：约 5 分钟。

### P6 认识 DeepSeek V4-Flash（2026 开源旗舰）

- **本页是什么**：本讲要部署的主角——DeepSeek V4-Flash 的规格数据页。

- **开场/衔接话术**：
  "环境备齐了，现在正式认识我们今天要部署的主角——DeepSeek V4-Flash。它是 2026 年的开源旗舰。"

- **核心讲解**：
  "看这几个数字。**284B 总参数 / 13B 激活参数**——这是 MoE（混合专家）架构，意思是模型总规模很大，但每次推理只激活 13B 的专家参数，所以又快又省显存，实现了『大模型的能力、小模型的开销』。**1M 上下文**——一次能处理 100 万 token 的输入，相当于几十本小说，超长文档、大代码库都能一口吃下。**MIT 开源协议**——完全免费商用，你能随便下载、修改、部署。**FP4 + FP8 量化**——支持低精度量化，进一步降低显存门槛。**$0.14 / 百万 input token**——这是它云端 API 的价格，便宜到可以当水电用。一句话总结：V4-Flash 用更小的激活参数反超了万亿级大模型，2026 年的竞争已经从『比谁大』转向『比谁聪明』。选型不必再追最大模型了。"

- **页面关键元素指引**：这是数据 Hero 页，重点指巨型数字 284B/13B、1M、$0.14/M；每个数字讲一个"意味着什么"。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："284B 总参的模型，我电脑真的跑得动吗？"
  - A："看量化。原版 284B 确实要很大的显存，但 4bit 量化后门槛会降到 24GB 显存左右，且 Ollama 还能用内存换显存。如果你的机器不够，下一页会讲怎么降级。别被总参数吓到——MoE 的好处就是『看着大、跑着轻』。"

- **时长**：约 4 分钟。

### P7 模型演进与知识蒸馏

- **本页是什么**：DeepSeek 的演进路线 R1 → V3 → V4-Flash + 知识蒸馏原理（老师教学生）。

- **开场/衔接话术**：
  "V4-Flash 不是凭空蹦出来的，它前面还有两位老大哥。这一页看演进路线，顺便学一个重要的概念——知识蒸馏。"

- **核心讲解**：
  "DeepSeek 的路线是这样的：**V3**（2024.12）是 MoE 架构的基座模型，671B 总参/37B 激活；**R1**（2025.01）是在 V3 基础上用强化学习训出来的**推理模型**，也就是带『思维链』、会『先想再说』的版本，当年就是它引爆了全球；**V4-Flash**（2026.07 正式版）是新一代开源旗舰，参数更少、能力更强。这条线背后有个关键技术叫**知识蒸馏**——说白了就是『老师教学生』：用一个庞大又聪明的模型当老师，让它去教一个小巧的模型，把老师的能力『浓缩』进学生。所以你才能看到 R1 那些 1.5B 到 70B 的『蒸馏小模型』——它们体型小、跑得快，却继承了老师的不少本事。记住这个类比：**蒸馏不是压缩文件，而是把名师的经验讲给徒弟听**。"

- **页面关键元素指引**：沿时间轴从左到右点 R1 → V3 → V4-Flash；右边重点讲"蒸馏=老师教学生"的示意图。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："蒸馏版和完整版，能力差多少？"
  - A："蒸馏版是小模型，能力肯定不如完整版，但在特定任务上能逼近老师的大部分水平，且资源消耗小一个数量级。对个人开发者来说，蒸馏小模型是性价比很高的入门选择——硬件不够时，先跑 7B/32B 的蒸馏版完全够用。"

- **时长**：约 4 分钟。

### P8 硬件要求

- **本页是什么**：跑 V4-Flash 需要什么硬件，跑不动怎么办（降级），以及入门最低配置。

- **开场/衔接话术**：
  "模型知道了，那问题来了：我的电脑配不配？这一页给你一个诚实的答案。"

- **核心讲解**：
  "先说结论：**V4-Flash 的 4bit 量化版，大概需要 24GB 以上显存，或者用 Ollama 的话约 70GB 内存也能跑**。这对很多同学来说是门槛。但别灰心，有两条退路。第一条**降级跑小模型**：显存不够就换 Qwen3 这类 7B~32B 的小模型，8GB 显存、甚至 16GB 内存都能跑，先跑起来再说。第二条**入门最低配置**：官方给的底线其实很低——Windows 一块 GTX 1650 4GB、16GB 内存、50GB 硬盘；Linux 一块 GTX 1660 6GB；Mac 一台 M2 的 MacBook Air 8GB 都行。也就是说，**你手里任何一台近几年的电脑，基本都能跑起一个小模型**。所以策略是『双轨』：本地跑 4bit 小模型练手、做隐私任务，云端 API 跑完整版旗舰模型。记住，本地部署从来不是『要么旗舰要么别玩』，而是按你的硬件量力而行。"

- **页面关键元素指引**：左大图（显存/内存对照）是重点，先讲 24GB/70GB 的门槛，再指向右边"降级小模型 + 入门最低配置"两条退路。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："我只有 8GB 显存，到底能跑多大的模型？"
  - A："一个粗略经验值：4bit 量化下，7B 模型约需 4~6GB 显存，13B 约需 8~10GB，32B 约需 18~20GB。8GB 显存跑 7B 甚至部分 13B 都没问题。所以先跑 7B 起步，绝对跑得起来。"

- **时长**：约 4 分钟。

### P9 安装 Ollama

- **本页是什么**：Ollama 是什么（类 Docker）+ 安装 + 拉取 deepseek-v4-flash。

- **开场/衔接话术**：
  "硬件心里有数了，接下来是今天的灵魂工具——Ollama。它就是让本地部署『人人可做』的那个关键。"

- **核心讲解**：
  "Ollama 是一个本地大模型运行框架，用 Go 写的。你可以把它**类比成 Docker**：Docker 用 `pull`、`run`、`list` 来管理容器，Ollama 用几乎一模一样的命令来管理模型。这个类比非常重要——如果你会 Docker，那 Ollama 就是零学习成本。安装也极其简单，Linux 一行命令：`curl -fsSL https://ollama.com/install.sh | sh`，装完敲 `ollama -h` 看帮助就是成功了。然后拉模型，一条命令：`ollama pull deepseek-v4-flash`。如果你显存不够，就拉量化版或小模型：`ollama pull deepseek-v4-flash:4bit`，或者 `ollama pull qwen3:7b`。模型拉下来之后，你就拥有了一个『属于自己的 AI』——本地文件、本地运行、数据不出门。"

- **页面关键元素指引**：重点讲"类 Docker"的类比，指终端示意图里的 `pull` 命令；强调"模型名从 R1 升级为 deepseek-v4-flash"。

- **现场动作/Demo**：Live Demo——展示 `ollama pull deepseek-v4-flash` 的下载进度（若模型已在课前下好，则展示 `ollama list` 列出已下载模型）。

- **可能的学员提问 & 回答**：
  - Q："`ollama pull deepseek-v4-flash` 和 `:4bit` 有什么区别？"
  - A："不带后缀的是默认精度（通常较大），`:4bit` 是 4bit 量化版，显存占用小很多。硬件紧张就加 `:4bit`，硬件充足就用默认版。查有哪些可用版本可以用 `ollama show deepseek-v4-flash`。"

- **时长**：约 5 分钟。

### P10 部署与启动（serve / run / curl 验证）

- **本页是什么**：三步跑通——`ollama serve` 起服务 → `ollama run` 对话 → `curl` 验证 API。

- **开场/衔接话术**：
  "模型拉下来了，怎么让它真正跑起来？三步：起服务、开对话、验 API。"

- **核心讲解**：
  "第一步，启动 API 服务：`ollama serve`，它会默认监听本地 11434 端口。第二步，直接对话：`ollama run deepseek-v4-flash`，你就进入了一个命令行聊天界面，可以直接打字聊了。第三步，验证 API——因为后面写程序是通过 HTTP 接口调用它的，所以用 curl 测一下：往 `http://localhost:11434/api/generate` 发一个 POST 请求，带上 `model` 和 `prompt`，模型就会返回生成结果。能拿到 JSON 返回，说明你的本地 AI 服务已经正式上线了，可以像调用云 API 一样调用它——只是这个 API 的服务器，是你自己的电脑。"

  - A："`serve` 是启动后台服务（守护进程），`run` 是拉起一个交互式对话。日常你直接 `ollama run` 它会自动确保服务在跑。但如果你要开放 API 给别人调，就得让 `serve` 稳定在后台，并把监听地址改成 0.0.0.0（下一页讲）。"

## 四、自测题答案

**① DeepSeek V4-Flash 的参数量特点（总参/激活参数）和 1M 上下文意味着什么？**

- 参数量特点：**284B 总参 / 13B 激活**，采用 MoE（混合专家）架构。总参大意味着模型"知识储备"丰富，但每次推理只激活 13B 的专家参数，意味着"大模型的能力、小模型的开销"——推理快、省显存，能用消费级硬件跑起来，实现了小参数反超大参数。
- 1M 上下文意味着：一次能处理约 100 万 token 的输入，超长文档、大代码库、长会议记录等场景都能一次性喂给模型，不用切块。

**② Ollama 和 Docker 的类比关系？**

- 二者都提供类 Docker 的命令行体验（`pull` / `run` / `list` / `serve`），核心思想都是"封装与标准化"：
  - Docker 封装的是**应用及其依赖**，一条命令拉镜像、一条命令跑容器。
  - Ollama 封装的是**模型及其运行环境**，一条 `ollama pull` 拉模型、一条 `ollama run` 跑模型，底层 CUDA、权重格式等细节都被屏蔽。
- 一句话：**Ollama 之于模型，就像 Docker 之于应用**。

**③ 本地部署和云 API 各自的适用场景？**

- 本地部署：免费、无调用次数限制、数据不出门。适合**隐私敏感数据、高频调用、长期自用**的场景；缺点是吃硬件、需自己维护、模型能力受限于本地配置。
- 云 API：省心、模型最新最强、按量付费（V4-Flash 才 $0.14/百万 input）。适合**快速开发、短期验证、追求最强效果、硬件不足**的场景；缺点是有速率限制、数据要出网、长期调用有成本。
- 推荐策略：**"本地 4bit + 云 API 双轨"**——敏感/高频走本地，复杂/最新走云端。

## 五、常见坑位提醒

1. **模型名千万别写错**：素材早期用的是 `deepseek-r1:32b`，本讲已统一升级为 `deepseek-v4-flash`（量化版 `deepseek-v4-flash:4bit`）。命令照抄时注意模型名，否则会报"model not found"。
2. **下载模型慢 / 卡住**：模型文件动辄几个 GB 到几十 GB，现场下载极易超时。**务必课前把模型下载好**，或现场用内网/已缓存机器演示；提醒学员课后在自己网络好的环境下载。
3. **conda 与 pip 混用冲突**：PyTorch 这类底层包用 conda 装、纯 Python 包用 pip 装，别在同一个环境里对同一个包两种方式都装，容易污染环境。
4. **cudatoolkit 版本对不上**：PyTorch 的 cudatoolkit 版本必须与显卡驱动匹配，否则 GPU 用不上、报 CUDA 错误。让学员先去 `nvidia-smi` 看驱动支持的 CUDA 版本。
5. **11434 端口被占用 / 服务没起**：`curl` 连不上时，先确认 `ollama serve` 是否在跑、端口是否被占用。常见原因是忘了起服务，或 serve 跑在前台被关闭。
6. **OLLAMA_HOST 安全风险**：开放 `0.0.0.0` 等于局域网任何人可调你的模型，演示可以，生产必须配合防火墙/鉴权，务必口头提醒。
7. **Dify 启动慢 / 拉镜像失败**：Dify 首次 `docker-compose up -d` 要拉一堆镜像，很慢，且国内拉 Docker Hub 可能失败。课前备好运行中的实例或配好镜像加速；也可把 Dify 作为"可选进阶"讲解，避免卡住主线。
8. **别被硬件门槛劝退**：反复强调"跑不动旗舰就降级 7B 小模型，任何近几年的电脑都能跑"，降低学员心理门槛，别让 P8 变成"劝退页"。
