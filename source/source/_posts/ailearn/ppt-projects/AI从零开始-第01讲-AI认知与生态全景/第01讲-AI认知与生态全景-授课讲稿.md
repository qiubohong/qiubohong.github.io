### P2 什么是 LLM 大模型（参数量视角）

- **本页是什么**：用"参数量"这条线索讲清什么是 LLM，并引出 2026 年的新趋势——MoE 让小参数反超大参数。

- **开场/衔接话术**：
  "先解决最基础的一个词——LLM。这四个字母我们天天见，它到底是什么意思？"

- **核心讲解**：
  "LLM 是 Large Language Model，大语言模型。什么叫『大』？关键看一个指标——**参数量**。你可以把参数理解成模型大脑里的『神经元连接数』，参数越多，理论上能记住的东西、能表达的能力就越强。历史上这条线是这么涨的：GPT-3 是 1750 亿参数，GPT-4 据说到了 1.8 万亿，一路在变大。但到了 2026 年，出现了一个新变量——DeepSeek V4-Flash，它总参数 284B、但真正干活时只激活 13B 参数，靠的是 MoE 架构（混合专家）。结果呢？它小参数反而追平甚至反超了很多万亿级的大模型。这说明一个重要的趋势：2026 年的竞争，已经从『谁更大』转向了『谁更聪明』。所以你现在选模型，不用再迷信『参数最大』了。"

- **页面关键元素指引**：先指左半边"参数量增长条"（1750 亿 → 1.8 万亿），再落到右边的"MoE 小参数反超大参数"案例，强调 DeepSeek V4-Flash 的 284B/13B 两个数字。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："总参数 284B 和激活参数 13B 是什么意思？"
  - A："MoE 架构把模型分成很多个『专家』子模块，284B 是全部专家加起来的规模，但每次回答只调用其中一小部分专家，所以实际算力只花 13B 的量。就像一家医院有 100 个医生，你看病时只挂 1 个科——总规模大，但单次成本低、速度快。"

- **时长**：约 4 分钟。

### P4 Transformer 是什么（比喻层）

- **本页是什么**：用"答题时圈重点"的比喻讲 Transformer 的核心——注意力机制；Q/K/V 数学原理降级到选学页。

- **开场/衔接话术**：
  "刚才那十个词里，有个词值得单独拉出来讲讲——Transformer，因为它是今天所有大模型的地基。"

- **核心讲解**：
  "Transformer 最关键的思想就一个：**注意力机制**。怎么理解呢？想象你考试做阅读理解，拿到一段长文章，你肯定不是逐字背诵，而是会『圈重点』——找出跟问题最相关的几个关键词。Transformer 干的就是这件事：模型看到一句话，它会自动判断这句话里哪些词跟『当前要预测的下一个词』最相关，然后给这些词分配更高的『注意力权重』。那它为什么比之前的 RNN 强？两个原因：一是**并行**，RNN 是一个词一个词顺序处理，像排队过独木桥；Transformer 是全体词同时处理，像高速公路多车道并行，所以能训练更大的模型；二是**长距离依赖**，句子隔得再远，它也能通过注意力直接『看到』，不会因为隔太久就忘了。至于它内部具体怎么算（Q/K/V 那套矩阵），我们放到最后一页选学，有兴趣的同学自己看，没兴趣直接跳过，不影响理解。"

- **页面关键元素指引**：重点讲左栏"圈重点"比喻；右栏的 Q/K/V 只做一句话带过"这是选学内容，详见 P11"。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："我不懂注意力机制，会影响后面学吗？"
  - A："完全不影响。你只需要记住『Transformer = 会圈重点的架构』这一个直觉就够了。后面做应用开发，你调的是 API 和框架，不需要手写注意力。数学原理是给学有余力的同学准备的。"

- **时长**：约 4 分钟。

### P5 Token 是什么（中文 Token 税）

- **本页是什么**：Token 的概念 + 计费关系 + 冷知识"中文 Token 税"（同样语义，中文比英文多耗 40%~100%）。

- **开场/衔接话术**：
  "讲完架构，我们讲一个跟你的钱包直接相关的词——Token。这是今天最『值钱』的一个冷知识。"

- **核心讲解**：
  "Token 是什么？简单说，就是模型处理文本的最小单位。模型不认『字』，它只认『Token』——英文里大概一个单词拆成 1~2 个 Token，中文里大概一个字对应 1~2 个 Token。为什么它跟钱有关？因为所有大模型 API 都是**按 Token 计费**的，你输入多少 Token、输出多少 Token，加起来乘以单价，就是你的账单。所以『Token 就是 AI 世界的计费货币』。那冷知识来了：**中文比英文更贵**。同样的意思，用英文说可能花 100 个 Token，用中文说可能要花 140 到 200 个 Token——多出来的这部分，行话叫『中文 Token 税』。为什么？因为中文信息密度高，一个字往往要拆成多个 Token 才能被模型处理。所以同样是问一个问题，你用中文问，账单就是比英文贵一截。这个知识点看似小，但它能帮你理解后面很多『成本优化』的设计——比如为什么有些应用会先把中文翻译成英文再调用模型。"

- **页面关键元素指引**：这是深色冷知识页，重点指右上角"40%~100%"这个巨数；讲"Token≈金钱"时放慢语速，强调"计费货币"这个比喻。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："那是不是应该都用英文提问来省钱？"
  - A："不一定。省钱的前提是模型对英文和中文的输出质量一样好。对很多国内模型来说，中文任务用中文问反而更准。这个知识的价值不在于『教你绕路』，而在于『看懂账单』——当你做成本优化时，知道中文的 Token 开销天然比英文高，就能做出更合理的判断。"

- **时长**：约 3 分钟。

### P6 Embedding 与向量

- **本页是什么**：Embedding 把文字变成向量，让机器能判断"意思相近"，这是语义检索的基石。

- **开场/衔接话术**：
  "Token 是模型『怎么读』文本，接下来这个词是模型『怎么理解』文本——Embedding，嵌入。"

- **核心讲解**：
  "Embedding 就干一件事：**把文字变成一串数字（向量）**。为什么要变数字？因为机器不懂中文、不懂英文，它只懂数字。而且这个转换不是随机的——它有个神奇的性质：**意思相近的两句话，转出来的向量在数学空间里也挨得近**。比如『苹果手机多少钱』和『iPhone 价格』，虽然字面完全不同，但它们的向量会很接近。有了这个性质，就能做很多事：语义搜索（搜『意思相近』而不只是『字面相同』）、数据分类、推荐系统、异常检测。常见的开源 Embedding 模型有 bge-m3、text2vec 这些。你现在只需要记住一句话：**Embedding 是给文字拍一张『语义坐标照』，让机器能算出两句话有多像**。这个能力，是第 5 讲 RAG 的地基。"

- **页面关键元素指引**：先讲上方"文本→向量"的转换示意，再指向下方三个应用卡（语义搜索/分类/推荐）；强调"意思相近→向量相近"这个核心性质。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："Embedding 和刚才的 Token 是什么关系？"
  - A："Token 是『切分单位』，把文本切成一块块；Embedding 是『表示方式』，把每块（或整句）变成向量。一个管『怎么读』，一个管『怎么理解』。它们常在同一条流水线上出现：先分词，再嵌入。"

- **时长**：约 4 分钟。

  "分国内、国外两条线看。**国外三巨头**：OpenAI 的 GPT-5——2026 年 8 月发布，400K 上下文、内置思考能力、支持文本+视觉；Anthropic 的 Claude Opus 5——2026 年 7 月发布，1M 上下文、thinking 默认开启，编程和长文处理很强；还有 Google 的 Gemini、Meta 的 Llama。**国内阵营**：领头的是 DeepSeek V4-Flash——2026 开源旗舰，284B 总参/13B 激活的 MoE 架构、1M 上下文、MIT 开源协议，价格便宜到 $0.14/百万 input token，还适配国产昇腾芯片，对标的是 GPT-5 和 Claude Opus 5。此外还有智谱 GLM、阿里的千问、百度的文心、腾讯的混元、字节的豆包。这么多模型，你记住一个选型原则就够了：**开源旗舰认 DeepSeek V4-Flash，闭源看 GPT-5 和 Claude Opus 5，其余按生态和价格挑**。"

### P8 主流开发框架

- **本页是什么**：AI 应用开发的几大框架，重点是"从 LangChain 开始，按场景选型"。

- **开场/衔接话术**：
  "模型选好了，怎么用它们开发应用？裸调 API 很痛苦，于是有了开发框架。这一页给你认框架。"

- **核心讲解**：
  "框架很多，但你只需要重点记住四个。**PyTorch**——深度学习的底层框架，你要自己训练或加载模型权重时才直接碰它，是地基。**Hugging Face Transformers**——模型仓库 + 库，几千个预训练模型一键下载调用，是『模型超市』。**LangChain**——LLM 应用开发框架，把提示词模板、链式调用、记忆、工具这些繁琐的事打包好，是我们第 4 讲的主角，也是入门首选。**Ollama**——本地模型运行框架，一条命令拉模型、一条命令跑模型，第 2 讲主角。其余的像 TensorFlow、JAX、PaddlePaddle 都是深度学习底层框架，知道名字即可。选型口诀：**底层训练用 PyTorch，找模型去 Hugging Face，做应用上 LangChain，本地部署用 Ollama**。"

- **页面关键元素指引**：6 框架卡里，重点停在 LangChain 和 Ollama 两张卡（它们是后续两讲的绝对主角），其余四张快速带过。

- **现场动作/Demo**：无。

- **可能的学员提问 & 回答**：
  - Q："LangChain 最近老被说『太重』，还值得学吗？"
  - A："值得。它是目前生态最全、教程最多的 LLM 框架，也是理解『编排』这个概念最好的入口。先学会它，再去看更轻量的方案（甚至裸调 API），你能看清本质。第 4 讲我们还会讲它的核心 LCEL，学会了这套思想，换框架很容易。"

- **时长**：约 4 分钟。

- **核心讲解**：
  "接入模型，本质上就是去一个平台注册、拿一个 API Key，然后一行代码调用。几个主流平台：**OpenAI API**——GPT-5 的官方入口，能力强，但国内访问不便、要绑卡。**腾讯混元 API**、**百度文心 API**——国内大厂，接入方便、文档中文友好。**硅基流动**——聚合平台，一个 Key 能调多个开源模型，对国内开发者很友好。**DeepSeek API**——今天的价格锚点：$0.14 每百万 input token，便宜到几乎可以当『水电』用。这里你要建立一个认知：2026 年调用大模型的成本已经低到，你完全可以『本地跑 + 云 API』双轨并行——本地跑省钱可控，云 API 跑省心省力。拿 Key、填进代码、开始调用，就这么简单。"

- **页面关键元素指引**：左边平台清单逐个点，右边强调 DeepSeek 的 $0.14 价格锚点，说明"接入成本极低，一行 Key 即可开始"。

- **可能的学员提问 & 回答**：

- **时长**：约 3 分钟。

### P10 行动清单（本周作业）

- **本页是什么**：本周行动——跑通一次在线模型对话，附自测 3 题。

- **开场/衔接话术**：
  "听了一堆概念，是时候动动手了。今天这一讲不写代码，但有一件必须亲自做的事。"

- **核心讲解**：

### P11 选学页：Transformer 进阶（Q/K/V）

- **本页是什么**：选学收官页——自注意力 Q/K/V 到底在算什么，明确标注"可跳过"。

- **开场/衔接话术**：
  "最后这页，是给学有余力的同学准备的『加餐』。看不懂、不想看，直接关掉，一点都不影响后面的学习。"

- **核心讲解**：
  "P4 我们只讲了注意力的比喻，现在把它拆成三个向量：**Q（Query，查询）、K（Key，键）、V（Value，值）**。你可以用『图书馆找书』来理解：你想找一本书，你脑子里有个『需求描述』，这就是 Q；每本书封底都贴着『关键词标签』，这就是 K；书本身的内容，就是 V。注意力的计算就是三步：第一步，拿你的 Q 去和所有书的 K 算『匹配度』（点积，数值越大越相关）；第二步，把这些匹配度归一化成权重（softmax，让它们加起来等于 1）；第三步，用权重去加权平均所有书的 V，得到最终输出——相当于你重点读了跟你需求最相关的几本。所以『注意力』的本质就是：**用 Q 和 K 的相似度来决定该重点看哪些 V**。这就是自注意力 Q/K/V 的全部直觉。想看完整公式的，去翻 daily#10，这里就不展开了。"

- **页面关键元素指引**：这是深色收官页，重点指"Q/K/V 三步"示意图；反复强调"选学、可跳过"，降低学员心理负担。

## 三、动手练习与参考答案

**练习**：打开任一大模型对话（DeepSeek/豆包/混元），体验「角色 + 格式」两条 Prompt 技巧，记录输出差异。

**完成步骤**：
1. 打开一个在线大模型（推荐 DeepSeek 网页版）。
2. 第一问（无技巧）：输入一个模糊需求，例如 `帮我写个周末活动方案`，记录输出。
3. 第二问（加角色）：新建对话，输入 `请你扮演一位有 10 年经验的活动策划，帮我设计一个适合一家三口（孩子 5 岁）的周末活动方案`，记录输出。
4. 第三问（加角色 + 格式）：再新建对话，输入 `请你扮演一位有 10 年经验的活动策划，帮我设计一个适合一家三口（孩子 5 岁）的周末活动方案。请用列表形式，分"活动安排、交通建议、预算估算"三部分，每部分不超过 3 条`，记录输出。
5. 对比三次输出，写下"哪一次最可用、为什么"。

**参考答案要点**（观察结论，非固定文本）：
- 第一次：输出泛泛、笼统，缺乏针对性，需要二次加工。
- 第二次：因为有了"活动策划"角色和"一家三口/孩子 5 岁"背景，输出明显更贴合情境。
- 第三次：在第二次基础上叠加了"列表格式 + 分三部分 + 条数限制"，输出结构清晰、可直接复用。
- 核心结论：**角色决定"用什么知识"，背景决定"贴合谁"，格式决定"长什么样"**——三者叠加，输出质量逐级提升。

## 四、自测题答案

**① Token 为什么"贵"？中文为什么更费？**

- "贵"是因为：大模型 API 按 Token 计费，输入和输出的 Token 都算钱；长对话、长文本会迅速消耗大量 Token，账单自然涨上去。Token 是 AI 世界的"计费货币"。
- 中文更费是因为：同样语义，中文通常要拆成比英文更多的 Token（信息密度高、分词粒度细），导致中文任务比英文多消耗约 40%~100% 的 Token。这就是"中文 Token 税"——同样的意思，用中文问，账单更贵。

**② RAG、Embedding、向量数据库三者的关系？**

- **Embedding（嵌入）**：负责"转换"——把文本变成向量，使语义相近的文本在向量空间里也相近。
- **向量数据库**：负责"存 + 找"——存储这些向量，并提供高效的相似性检索。
- **RAG（检索增强生成）**：负责"组合"——先检索（调用 Embedding 把问题转成向量、到向量库找相关资料），再把资料连同问题一起交给大模型生成答案。
- 一句话：**Embedding 是转换器，向量库是仓库+检索器，RAG 用它们两个实现"查资料再回答"。**

**③ 说出国内 3 个开源大模型和 3 个闭源大模型。**

- 开源（示例）：DeepSeek V4-Flash、阿里通义千问 Qwen、智谱 GLM（ChatGLM 系列）。
- 闭源（示例）：百度文心一言、腾讯混元、字节豆包。
- 补充说明：部分厂商（如智谱、阿里）同时有开源和闭源版本，答题时说出主流通用认知即可，重点是能区分"源码权重是否公开"这一判断标准。

## 五、常见坑位提醒

1. **别在 P2 纠结参数量精确值**：GPT-3/GPT-4 的参数量不同资料口径不一（早期文章甚至把 175B 写成 175 亿）。讲课以"数量级趋势"为主——"从千亿到万亿再到 MoE 小参数反超"，不要陷入具体数字的争议。
2. **10 词卡别逐词展开**：P3 有 10 个术语，每个展开会严重超时。每个词一句话带过，只在 RAG、Agent、Function Calling 三个"后续主角"上多停。
3. **Transformer 一定别上公式**：P4 是比喻层，P11 才是选学。若学员在 P4 追问 Q/K/V，礼貌地"请到 P11 再看"，不要当场陷入数学推导，否则会吓跑一批人。
4. **中文 Token 税是冷知识，别讲成"劝退中文"**：讲完要补一句"国内模型对中文任务通常中文更准，别为了省钱硬切英文"，避免学员误读。
5. **模型格局要加"时点"**：讲 P7 时反复强调"2026 年 8 月这个时点"，因为模型换代快，不加时点的话几个月后就过时了。这也顺便给学员植入"持续关注前沿"的意识。
6. **P10 演示依赖网络**：提前测好 DeepSeek 网页版；网络不稳就切换截图，别在现场等加载。
7. **P11 选学页要主动"劝退"**：明确告诉学员"跳过不影响后续"，降低心理负担；学有余力者才看。若时间紧张，这页可整体压缩为 2~3 分钟。
