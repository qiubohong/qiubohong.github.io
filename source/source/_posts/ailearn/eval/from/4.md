> 原文：[Assessing and Verifying Task Utility in LLM-Powered Applications](https://arxiv.org/html/2405.02178v1)

## 摘要

大型语言模型（LLM）的快速发展催生了大量促进多智能体协作、协助人类日常任务的应用。然而，在评估 LLM 驱动应用是否真正提升用户体验和任务执行效率方面，仍存在显著差距。

这凸显了验证 LLM 驱动应用实用性的必要性，特别是确保应用功能与最终用户需求之间的一致性。

本文介绍 **AgentEval**——一个新颖的框架，旨在通过自动提出一套针对任何给定应用独特目的的标准来简化实用性验证过程。这使得能够进行全面评估，根据建议的标准量化应用的实用性。

我们对两个开源数据集（数学问题求解和 ALFWorld 家务任务）进行了 AgentEval 有效性和鲁棒性的全面分析。为了可复现性，我们公开了数据、代码和所有日志：https://bit.ly/3w3yKcS

---

## 1. 引言

智能体的长期目标之一是与人类进行自然语言交互，并帮助最终用户完成任务，例如完成家务、数学辅导等。开源库的快速发展简化了针对各种以用户为中心任务的 LLM 驱动智能体应用的开发。

为确保应用行为满足应用开发者的要求，评估其对最终用户的潜在实用性也至关重要，因为这会显著影响其改进历程。

### 现有方法的局限性

考虑到各种应用，假设每个领域都有基准测试是不现实的。此外，直接评估智能体应用面临挑战，因为当前方法主要依赖端到端成功指标（即应用是否完成任务）。然而，理解用户与应用的交互远不止于成功与否。

以数学问题求解为例，虽然应用正确解决问题很重要，但其根据各种标准（如完整性、简洁性和清晰度）呈现和解释解决方案的能力同样关键。

### AgentEval 的目标

AgentEval 旨在弥合这一差距，为 LLM 驱动应用的实用性提供评估框架。其目标是通过为应用开发者提供关于当前流程如何被表征的见解来评估实用性。

## 2. 任务实用性分类

下图展示了 LLM 驱动应用目标任务的分类，按成功指标划分：

### 成功未明确定义的任务

用户以辅助方式使用系统，寻求建议而非期望系统解决任务。例如，用户可以请求系统生成电子邮件，通常将系统的响应用作模板，之后可以编辑。直接评估这类辅助任务很困难，特别是对于在线评估或处理定义不明确的任务时。

### 成功明确定义的任务

系统是否解决了任务是清楚的，例如协助完成家务任务。这一类别可进一步分为：

- **存在最优解**：只有一种成功结果是可能的。例如，当要求助手打开灯时，成功是明确定义的，因为只有一种方法可以做到。
- **存在多种解决方案**：越来越多地，我们观察到多种智能体行为轨迹可以导致成功的情况。例如，当要求智能体建议食谱时，成功可能是多种美食都好吃，但也许食谱不应该太贵。

**AgentEval 目前专注于成功明确定义且可能存在多种成功解决方案的任务。**

## 3. AgentEval 框架

AgentEval 由以下三个智能体组成：

### 3.1 CriticAgent（批评智能体）

**目标**：建议一套可用于评估任务实用性的标准。

CriticAgent 接收任务描述，以及可选的几对解决方案（其中一些优于另一些，例如成功和失败的示例）。CriticAgent 返回一套标准 C = {c₁, ..., cₙ}，其中每个标准 cᵢ 附带一组接受值 ω。

**示例**（数学问题求解）：

| 标准 | 接受值 |
|------|--------|
| 准确性（Accuracy） | 正确、轻微错误、重大错误、不正确 |
| 简洁性（Conciseness） | 非常简洁、简洁、有些冗长、冗长 |
| 清晰度（Clarity） | 非常清晰、清晰、有些不清晰、不清晰 |
| 效率（Efficiency） | 高效、适中、低效 |
| 完整性（Completeness） | 完整、部分完整、不完整 |

### 3.2 QuantifierAgent（量化智能体）

**目标**：量化每个建议标准，以评估系统对最终用户的任务实用性。

我们将任务 t 的实用性定义为：
```
Uₜ(s) = {Qᵢ(s|cᵢ)}ᵢ₌₁ⁿ
```
其中 s 表示任务样本，Q(s|cᵢ) 是基于标准 cᵢ 对样本 s 的量化器输出。

### 3.3 VerifierAgent（验证智能体）

**目标**：验证标准的质量，确保其鲁棒性和可区分性。

可能存在 CriticAgent 建议的标准并不都有助于评估实用性的情况。一些标准可能是冗余的，而另一些可能无助于区分性能。VerifierAgent 通过以下方式验证标准质量：

1. **检查标准是否可以在重复样本上鲁棒地量化**
2. **检查 QuantifierAgent 是否能从原始样本中识别出对抗性攻击的目标样本**

如果健全性检查未通过，VerifierAgent 将更新标准列表，最终得到一套鲁棒、稳定、信息丰富且可区分的评估标准。

## 4. 数据集与解决方案

### 4.1 数学问题求解（MATH Problem Solving）

**数据集**：MATH 数据集包含来自高中竞赛的 12,500 道具有挑战性的数学题，每道题附有逐步解答，并按难度级别标注。实验在 120 道 5 级难题上进行。

**评估的解决方案**：
- **AutoGen**：多智能体协作框架
- **LangChain ReAct**：基于推理-行动循环的方法
- **Vanilla GPT-4**：直接使用 GPT-4 求解

### 4.2 ALFWorld 家务任务

**数据集**：ALFWorld 提供了一套在模拟家庭环境中基于语言的交互式决策任务。它是第一个将文本描述和命令与物理具身机器人模拟对齐的交互式并行环境。

**评估的解决方案**：
- ReAct
- AutoGen（两个智能体）
- AutoGen（三个智能体）

## 5. 实验结果

### 5.1 实现细节

所有实验使用 GPT-4 版本 0613（通过 Azure OpenAI 服务访问），温度设置为 0。AgentEval 使用 AutoGen 实现，因为它提供了一个多功能环境，可以根据特定应用需求对智能体进行精细调整和定制。

### 5.2 数学问题的 AgentEval 评估

执行 CriticAgent 后，获得了一套评估标准。然后 QuantifierAgent 根据接受值量化每个标准。

**关键发现**：

1. **AgentEval 能区分不同解决方案的性能**：虽然三种解决方案都使用 GPT-4 作为底层语言模型，但 AutoGen 在准确性方面优于 ReAct 和 Vanilla GPT-4。

2. **成功案例和失败案例的区分**：在大多数情况下，成功案例和失败案例在 95% 置信区间内都能被区分开来。

3. **超越简单成功/失败指标**：即使两个解决方案都成功，一个在某些标准（如清晰度或效率）上可能表现更好或更差。这为解决方案开发者提供了有价值的额外见解。

### 5.3 VerifierAgent 的鲁棒性验证

VerifierAgent 通过以下方式验证标准的鲁棒性：

- **标准稳定性测试**：多次运行相同样本，检查量化结果的一致性
- **对抗性测试**：引入噪声样本，检查系统是否能正确识别

实验结果表明，经过 VerifierAgent 筛选后的标准具有更高的稳定性和判别力。

## 6. 主要贡献总结

**C1**：引入 AgentEval，一个利用 LLM 驱动智能体作为可扩展且经济高效的人工评估替代方案的新颖框架，通过三个智能体（CriticAgent、QuantifierAgent 和 VerifierAgent）的协作产生任务实用性评估。

**C2**：对 AgentEval 在两个应用中跨不同解决方案的鲁棒性进行深入分析，可在未见领域上复现。

---

## 7. 结论

AgentEval 代表了 LLM 驱动应用评估领域的重大进步。通过自动化标准生成、量化和验证过程，AgentEval 为开发者提供了：

- **深入的性能洞察**：超越简单的成功/失败指标
- **多维度评估**：从多个角度全面评估应用实用性
- **可扩展的评估方案**：无需为每个领域单独设计基准测试
- **人在回路支持**：允许领域专家参与评估过程

随着 LLM 驱动应用的持续发展，AgentEval 这样的框架将在确保这些应用真正满足用户需求方面发挥越来越重要的作用。
