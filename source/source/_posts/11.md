# mock-llm-server v1 接口与 MySQL 持久化改造 实施计划

  

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

  

**Goal:** 在 mock-llm-server 中新增 `POST /v1/chat/completions` 接口，从请求体的 user 消息 content 提取 `REQUEST_ID` / `CONVERSATION_ID` / `INDEX`，从 MySQL 表 `mock_responses` 取出对应响应；老接口 `POST /chat/completions` 与 `data/` fixture 完全保留，零改动。

  

**Architecture:**

- 双接口共存：老接口走文件 fixture，新接口走 MySQL；两接口共用 `StreamHandler`、`types.ts`、错误格式。

- 启动时强制建立 MySQL 连接池并执行健康检查，失败则 fail-fast (`process.exit(1)`)，符合 PRD §6 与本轮决策 C1。

- 服务端管顺序推进：基于请求体 `messages` 中 `role==='assistant'` 的数量决定 `message_index`；`INDEX=N` 显式覆盖。

- 未命中（不存在对应 `request_id` + `message_index`）**不返回 4xx**，按 OpenAI Chat Completion 协议返回 200 兜底响应（覆盖 PRD §3.1/§3.2 中 400/404 的写法，与本轮用户决策一致）。

  

**Tech Stack:**

- TypeScript + express（已有）

- mysql2/promise（新增依赖，硬依赖）

- mocha + supertest（项目惯用，新增 supertest 与 @types/supertest）

- dotenv（仅本地开发使用）

**提取规则：**

1. 找到第一条 `role==='user'` 的消息 content

2. 优先匹配 `/REQUEST_ID=(\S+)/` → `source='request-id'`

3. 否则匹配 `/CONVERSATION_ID=(\S+)/` → `source='conversation-id'`

4. 都没有 → `requestId = deps.defaultRequestId`, `source='default'`

5. 同 content 中匹配 `/INDEX=(\d+)/` → `index = Number(...)`

6. 完全没有 user 消息 → 用 `defaultRequestId`，`index` undefined

```typescript
// src/node/v1/extract-request-context.ts

export interface ExtractedContext {

requestId: string;

source: 'request-id' | 'conversation-id' | 'default';

index?: number;

}

  

export interface ExtractDeps {

defaultRequestId: string;

}

  

export function extractRequestContext(

messages: Array<{role: string; content: string}>,

deps: ExtractDeps

): ExtractedContext {

const firstUser = messages.find(m => m.role === 'user');

const content = firstUser?.content ?? '';

  

const reqMatch = /REQUEST_ID=(\S+)/.exec(content);

const convMatch = /CONVERSATION_ID=(\S+)/.exec(content);

const idxMatch = /INDEX=(\d+)/.exec(content);

  

let requestId: string;

let source: ExtractedContext['source'];

if (reqMatch) {

requestId = reqMatch[1];

source = 'request-id';

} else if (convMatch) {

requestId = convMatch[1];

source = 'conversation-id';

} else {

requestId = deps.defaultRequestId;

source = 'default';

}

  

const result: ExtractedContext = { requestId, source };

if (idxMatch) {

result.index = Number(idxMatch[1]);

}

return result;

}

```

```typescript
export class MockResponseRepository {

constructor(private pool: Pool) {}

  

async findByRequestIdAndIndex(requestId: string, index: number): Promise<StoredResponse | null> {

const [rows] = await this.pool.query(

'SELECT response_body, finish_reason FROM mock_responses WHERE request_id = ? AND message_index = ? LIMIT 1',

[requestId, index]

);

const arr = rows as Array<{ response_body: any; finish_reason: string | null }>;

if (arr.length === 0) return null;

const raw = arr[0].response_body;

const responseBody = typeof raw === 'string' ? JSON.parse(raw) : raw;

return { responseBody, finishReason: arr[0].finish_reason };

}

}
```

**说明：**

- `content` 模板：`[mock-llm-server] No mock response found for request_id=${ctx.requestId} message_index=${ctx.index}. Please check db.mock_responses.`

- 非流式：`finish_reason: 'stop'`

- 流式：role chunk → content chunk（一次性发送，无需切块）→ finish chunk → `data: [DONE]\n\n`

**处理流程（基于 PRD §3 + 用户兜底决策）：**

```

1. 读取 req.body.messages，调用 extractRequestContext(messages, {defaultRequestId})

2. 计算目标 index：

- 若 ctx.index 存在 → index = ctx.index (精确返回模式)

- 否则 → index = messages.filter(m => m.role==='assistant').length (顺序推进)

3. repo.findByRequestIdAndIndex(ctx.requestId, index)

- 命中：根据 req.body.stream 返回流式或非流式

- 未命中：返回 200 + buildFallbackChatCompletion / buildFallbackStreamChunks

4. 流式响应复用 StreamHandler.setupSSEHeaders；

非流式直接 res.json(storedResponse.responseBody)

5. 流式命中：把 storedResponse.responseBody 转成 ResponseData 喂入 StreamHandler；

- 已有 storedResponse 是完整 chat.completion，需要从 choices[0].message 提取 ResponseMessage

- 新增内部函数 chatCompletionToResponseData() 完成转换

```
